Claude Code ne fournit pas de parseur d'options : il découpe les arguments selon les règles de guillemets du shell, puis les remplace dans le texte du prompt. Pour des flags, des listes de fichiers ou des regex, c'est Claude qui fait le parsing. Il s'en sort très bien si vous lui donnez une grammaire précise et des exemples. Cet article part de ce que fait réellement Claude Code, puis montre comment écrire des commandes à arguments riches.

## Ce que Claude Code fait (et ne fait pas)

| Élément | Comportement |
| --- | --- |
| `$ARGUMENTS` | La chaîne complète, exactement telle que tapée |
| `$0`, `$1`, `$ARGUMENTS[N]` | Positions découpées avec les guillemets du shell : `"hello world"` compte pour un |
| `$nom` (champ `arguments`) | Nom donné à une position ; vide si absent |
| Position absente (`$2`) | Reste écrite telle quelle dans le prompt |
| Aucun emplacement dans le texte | Claude Code ajoute `ARGUMENTS: <votre texte>` à la fin |
| `\$1` | Dollar littéral, pas de substitution |
| Validation, valeurs par défaut, flags | Rien : c'est à Claude de le faire |

Exemple : avec `/remplacer "use client" "use server" --dry-run`, on obtient `$0` = `use client`, `$1` = `use server`, `$2` = `--dry-run`, et `$ARGUMENTS` contient la ligne entière.

Les bases (positions, arguments nommés, namespacing) sont détaillées dans [Arguments et namespacing](/wiki/slash-commands/arguments-namespacing).

## Règle d'or : une grammaire explicite avec exemples

Ne laissez rien d'implicite. Décrivez chaque argument, ses valeurs possibles, ses valeurs par défaut, et donnez des exemples valides et invalides.

`.claude/skills/remplacer/SKILL.md` :

```md
---
description: Cherche et remplace un motif dans des fichiers du projet
argument-hint: <motif> <remplacement> [--dry-run] [--regex] [glob...]
disable-model-invocation: true
allowed-tools: Read Grep Glob
---

Arguments reçus : $ARGUMENTS

## Grammaire
- `<motif>` : premier argument, entre guillemets s'il contient des espaces.
- `<remplacement>` : deuxième argument.
- `--dry-run` : n'écrit rien, liste seulement les occurrences.
- `--regex` : traite le motif comme une expression régulière.
- `[glob...]` : zéro ou plusieurs motifs de fichiers. Défaut : `**/*.{ts,tsx}`.
- Les flags peuvent apparaître n'importe où après les deux premiers arguments.

## Exemples valides
- `"oldName" "newName"`
- `"oldName" "newName" --dry-run`
- `"foo.*bar" "baz" --regex "src/**/*.ts"`

## Exemple invalide
- `"oldName"` seul : remplacement manquant.

## Déroulé
1. Affichez la lecture que vous faites des arguments (motif, remplacement, flags, fichiers).
2. Listez les occurrences trouvées avec Grep.
3. Sans `--dry-run`, demandez confirmation puis appliquez les modifications avec Edit.
```

Afficher l'interprétation à l'étape 1 coûte trois lignes et évite la plupart des mauvaises surprises.

`allowed-tools` ne liste volontairement pas `Edit` : les modifications passent par la demande de confirmation habituelle. C'est un second filet de sécurité.

## Flags de style Unix

Fixez la convention une fois pour toutes dans le prompt :

```md
---
description: Génère un composant React
argument-hint: <Nom> [--type=server|client] [--with-test]
arguments: [nom]
allowed-tools: Read Edit(app/components/**)
---

Nom du composant : $nom
Arguments complets : $ARGUMENTS

## Options
- `--type=server|client` : défaut `server`. Avec `client`, ajoutez "use client".
- `--with-test` : crée aussi `app/components/$nom.test.tsx`.
- Toute autre option : arrêtez-vous et listez les options valides.

Créez `app/components/$nom.tsx` en suivant les conventions du CLAUDE.md.
```

```text
> /composant Header --type=client --with-test
```

Combiner un argument nommé (`$nom`, toujours en première position) et `$ARGUMENTS` (pour les flags) donne un prompt lisible sans perdre d'information.

Pour les fichiers, pré-autorisez `Edit(...)` et non `Write(...)` : seuls les motifs `Edit` et `Read` sont vérifiés pour les chemins.

## Expressions régulières

Les guillemets sont votre meilleur allié : `$0` reçoit la regex entière, backslashes compris, tant qu'elle est entre guillemets.

```md
---
description: Liste les TODO correspondant à une regex
argument-hint: "\"<regex>\""
arguments: [regex]
allowed-tools: Grep
---

Cherchez dans tout le dépôt les lignes correspondant à l'expression régulière suivante : `$regex`

Utilisez l'outil Grep (syntaxe ripgrep), pas le shell.
Si l'expression est invalide, dites-le et proposez une correction.
```

```text
> /todos "TODO\(@\w+\):"
```

Passer par l'outil Grep plutôt que par `grep` dans le shell évite tout problème d'échappement et toute injection.

## Listes de fichiers

```md
---
description: Lit plusieurs fichiers et résume chacun
argument-hint: <fichier ou glob> [...]
allowed-tools: Read Glob
---

Fichiers demandés : $ARGUMENTS

- Chaque argument est un chemin ou un motif glob.
- Résolvez les motifs avec l'outil Glob.
- Ignorez les chemins hors du projet et signalez-les.
- Pour chaque fichier, résumez son rôle en trois lignes.
```

```text
> /resumer app/page.tsx lib/curriculum.ts
> /resumer "app/**/*.tsx"
```

Mettez le glob entre guillemets pour qu'il reste un seul argument.

## Arguments JSON pour les cas touffus

Quand les options s'accumulent, un objet JSON supprime toute ambiguïté :

```md
---
description: Prépare un déploiement paramétré
argument-hint: '{"env": "staging|prod", "skipTests": false, "tags": []}'
disable-model-invocation: true
---

Configuration reçue : $ARGUMENTS

Validez l'objet :
- `env` : obligatoire, `staging` ou `prod`.
- `skipTests` : booléen, défaut `false`. Refusez `true` si `env` vaut `prod`.
- `tags` : liste de chaînes, défaut `[]`.

Si l'objet est invalide, n'exécutez rien et affichez un exemple correct.
```

```text
> /deployer {"env": "staging", "tags": ["v1.3.0"]}
```

## Erreurs et confirmation

Terminez le prompt par une consigne d'erreur claire :

```md
Si les arguments ne respectent pas la grammaire :
- n'exécutez aucune action ;
- affichez le format attendu et un exemple ;
- rappelez ce que vous avez reçu.
```

Pour une commande destructrice, demandez un récapitulatif puis une confirmation avant d'écrire. Claude peut poser la question avec son outil de questions à choix (AskUserQuestion), plus fiable qu'un « tapez y ».

## Anti-patterns

- **Grammaire implicite** : « vous comprendrez ». Claude invente alors une convention différente à chaque appel.
- **Flags ambigus** : `-r` qui veut dire tantôt « récursif », tantôt « regex ».
- **Argument dans un bloc `` !`…` ``** : cela peut l'exécuter dans un shell. Voir [Bash injection](/wiki/slash-commands/bash-injection-securisee).
- **Compter sur `$2` absent** : il reste écrit `$2` dans le prompt. Utilisez un argument nommé si vous voulez une valeur vide.
- **Trop d'options** : au-delà de cinq ou six, découpez en plusieurs commandes.
