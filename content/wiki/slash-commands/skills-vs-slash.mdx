La question « skill ou slash command ? » ne se pose plus comme avant : Claude Code a fusionné les commandes personnalisées dans les skills. Un fichier `.claude/commands/deploy.md` et un skill `.claude/skills/deploy/SKILL.md` créent tous les deux `/deploy` et fonctionnent de la même façon. La vraie question est désormais : **qui déclenche** (vous, Claude, ou les deux) et **où placer l'instruction** (skill, CLAUDE.md ou hook).

## Ce qui se cache derrière un `/`

Quand vous tapez `/`, le menu mélange plusieurs familles :

| Famille | Exemples | Ce que c'est |
| --- | --- | --- |
| Commandes intégrées | `/clear`, `/compact`, `/model`, `/usage` | Logique codée dans le CLI, exécutée directement |
| Skills intégrés (bundled) | `/code-review`, `/simplify`, `/batch`, `/loop`, `/doctor` | Prompts fournis par Anthropic, que Claude exécute avec ses outils |
| Vos skills | `.claude/skills/<nom>/SKILL.md` | Format recommandé pour vos commandes |
| Ancien format | `.claude/commands/<nom>.md` | Toujours pris en charge, mêmes champs sauf `name` et `paths` |
| Skills de plugin | `/mon-plugin:revue` | Toujours préfixés par le nom du plugin |
| Prompts MCP | `/serveur:prompt` (aussi `/mcp__serveur__prompt`) | Exposés par un serveur MCP, marqués « (MCP) » dans le menu |

Un skill du projet ou personnel qui porte le nom d'une commande intégrée ou d'un skill intégré la remplace (mais pas ses alias). Un skill `code-review` dans votre projet remplace `/code-review`, alors que `/review` lance toujours la version intégrée.

## Le vrai choix : qui déclenche ?

Par défaut, un skill peut être lancé par vous (`/nom`) **et** chargé par Claude quand sa description correspond à la demande. Deux champs changent ce comportement :

| Frontmatter | Vous | Claude | Coût en contexte |
| --- | --- | --- | --- |
| (par défaut) | Oui | Oui | Description chargée en permanence |
| `disable-model-invocation: true` | Oui | Non | Rien tant que vous ne l'invoquez pas |
| `user-invocable: false` | Non | Oui | Description chargée en permanence |

### Déclenchement manuel uniquement

Pour toute action avec effets de bord ou dont vous voulez choisir le moment : déployer, commiter, publier une release, envoyer un message.

```md
---
description: Déploie sur Vercel (preview par défaut)
argument-hint: "[--prod]"
disable-model-invocation: true
allowed-tools: Bash(git status *) Bash(vercel *)
---

1. Vérifiez `git status` et arrêtez-vous si le dépôt n'est pas propre.
2. Si les arguments contiennent `--prod`, lancez `vercel --prod`, sinon `vercel`.
3. Affichez l'URL obtenue.

Arguments : $ARGUMENTS
```

Vous ne voulez pas que Claude décide de déployer parce que le code « a l'air prêt ». Si Claude essaie quand même, Claude Code bloque l'appel.

### Déclenchement par Claude (et par vous)

Pour une procédure que Claude doit appliquer dès que la situation se présente : conventions d'API, règles Supabase, style de tests. La `description` fait tout le travail : écrivez-la avec les mots que vous utiliseriez.

```md
---
description: Conventions Supabase du projet (migrations, RLS, clients). À utiliser dès qu'on crée une table, une migration ou une route qui lit la base.
---

- Toute nouvelle table a RLS activé et au moins une policy.
- Les routes API utilisent le client service role, jamais côté navigateur.
- Une migration par changement, nommée en snake_case.
```

### Claude seulement

`user-invocable: false` pour du savoir de fond qui n'a pas de sens comme commande (« comment fonctionne l'ancien système de facturation »). La commande disparaît du menu `/`, mais Claude peut toujours la charger.

## Skill, CLAUDE.md ou hook ?

| Besoin | Où le mettre | Pourquoi |
| --- | --- | --- |
| Un fait court valable tout le temps (« on utilise pnpm ») | `CLAUDE.md` | Chargé à chaque session |
| Une procédure en plusieurs étapes | Skill | Chargé seulement quand il sert |
| Une longue référence (API, conventions détaillées) | Skill + fichiers annexes | `SKILL.md` court, détails lus à la demande |
| Une règle qui doit s'appliquer **à chaque fois** | Hook | Exécuté par Claude Code, pas laissé au jugement de Claude |
| Une tâche longue et isolée | Skill avec `context: fork` ou sous-agent | Ne pollue pas votre contexte |

La documentation officielle le résume ainsi : créez un skill quand vous collez sans cesse les mêmes instructions, ou quand une section de `CLAUDE.md` est devenue une procédure plutôt qu'un fait. Pour une règle impérative (« jamais de `--no-verify` »), un skill ne suffit pas : Claude peut l'oublier en cours de route. Utilisez un hook ou une règle `deny`.

Pour la comparaison avec les sous-agents et MCP, voir [Skill, agent ou MCP](/wiki/skills/skill-vs-agent-vs-mcp).

## Exécuter dans un sous-agent : `context: fork`

Avec `context: fork`, le contenu du skill devient le prompt d'un sous-agent isolé, qui ne voit pas votre conversation. Il tourne en arrière-plan par défaut et rapporte son résultat à la fin (`background: false` pour l'attendre).

```md
---
description: Recherche approfondie dans le code
context: fork
agent: Explore
disable-model-invocation: true
---

Recherchez $ARGUMENTS dans le code :
1. Trouvez les fichiers concernés avec Glob et Grep.
2. Lisez et analysez le code.
3. Résumez avec les chemins de fichiers.
```

Ne l'utilisez que pour un skill qui contient une tâche complète. Un skill de conventions (« suivez ces règles d'API ») en `fork` ne produit rien d'utile : le sous-agent reçoit des règles mais aucune tâche. Attention aussi : les modifications faites par un fork en arrière-plan échappent aux checkpoints, `/rewind` ne les annule pas.

## Coût en contexte

- Chaque skill invocable par Claude ajoute sa description à la liste chargée à chaque tour. Ce budget est d'environ 1 % de la fenêtre de contexte ; au-delà, les descriptions des skills les moins utilisés sont supprimées.
- Une fois invoqué, le contenu d'un skill reste dans la conversation. Après une compaction, Claude Code n'en garde que le début (5 000 tokens par skill, 25 000 au total) : placez l'essentiel en haut.
- `/skills` affiche le coût de chaque skill (touche `t` pour trier) ; `/skill-doctor` repère ceux qui coûtent sans servir.

## Migrer un ancien fichier `.claude/commands/`

Rien ne presse : l'ancien format fonctionne. Migrez quand vous avez besoin d'une fonction propre aux skills (fichiers annexes, rechargement à chaud, champ `paths`).

```bash
mkdir -p .claude/skills/deploy
git mv .claude/commands/deploy.md .claude/skills/deploy/SKILL.md
```

Si les deux existent avec le même nom, c'est le skill qui gagne. Attention aux sous-dossiers : `.claude/commands/db/migrate.md` donne `/db:migrate`, alors qu'un skill `db-migrate` donne `/db-migrate`. Prévenez l'équipe si le nom change.

## Anti-patterns

- **Description trop large** : le skill se charge pour tout et pollue le contexte.
- **Action sensible sans `disable-model-invocation: true`** : Claude peut la lancer de lui-même.
- **Doublon skill + commande** au même nom : seul le skill est utilisé, l'autre fichier devient du code mort.
- **Règle impérative confiée à un skill** : passez par un hook.
