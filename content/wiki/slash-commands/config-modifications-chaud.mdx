Claude Code surveille ses fichiers de réglages et applique la plupart des modifications à la session en cours, sans redémarrage. Vous pouvez passer par le menu `/config`, par la forme rapide `/config clé=valeur`, ou éditer directement un `settings.json`. Quelques clés font exception : elles ne sont lues qu'au démarrage et ont leur propre commande pour changer en cours de route.

## Le menu `/config`

`/config` (alias `/settings`) ouvre l'interface des réglages. L'onglet **Config** propose une courte liste d'options personnelles : thème, mode d'éditeur, sortie verbeuse, etc. Ce n'est pas une vue complète de votre `settings.json`.

Claude Code enregistre le choix à votre place :

- la plupart des options vont dans `~/.claude/settings.json` ;
- quelques-unes (par exemple l'affichage des astuces) vont dans `.claude/settings.local.json` ;
- les options de configuration globale vont dans `~/.claude.json`.

Le même dialogue a un onglet **Status** (`/status`) qui affiche la version, le modèle, le compte et la ligne `Setting sources` : la liste des fichiers de réglages chargés.

`/config` fait partie de l'interface du terminal. Dans le panneau VS Code et l'application de bureau, passez par les fichiers ou par les réglages propres à ces applications.

## La forme rapide `/config clé=valeur`

Pour changer une option sans ouvrir le menu :

```text
> /config theme=dark
> /config verbose=true
> /config model=sonnet
> /config thinking=false
```

Vous pouvez passer plusieurs paires à la fois. `/config --help` liste les clés acceptées. Cette forme fonctionne aussi en mode non interactif (`claude -p`) et depuis l'application mobile via Remote Control. Elle peut désactiver un réglage qui demande une confirmation dans le menu, mais pas l'activer.

## Les commandes dédiées

Pour les réglages les plus fréquents, une commande spécialisée est plus rapide et plus claire :

| Besoin | Commande |
| --- | --- |
| Changer de modèle (enregistré comme défaut) | `/model opus` |
| Changer de modèle pour cette session seulement | `/model`, puis touche `s` sur la ligne choisie |
| Niveau de raisonnement | `/effort high` (ou `low`, `medium`, `xhigh`, `max`, `auto` ; `max` vaut pour la session) |
| Seuil de compaction automatique | `/autocompact 500k` ou `/autocompact auto` |
| Style de sortie | `/output-style concise` |
| Règles de permission | `/permissions` |
| Sandbox | `/sandbox` |
| Ligne de statut | `/statusline` |
| Mode rapide | `/fast on` ou `/fast off` |

Changer de modèle en cours de session a un coût : chaque modèle a son propre cache de prompt, donc la requête suivante relit toute la conversation sans cache. Claude Code peut vous demander de confirmer.

## Éditer un `settings.json` à la main

Les modifications des fichiers de réglages sont rechargées automatiquement, y compris `permissions`, `hooks` et les assistants d'identifiants comme `apiKeyHelper`. Un fichier créé en cours de session est pris en compte si son dossier existait déjà au démarrage (le dossier `.claude/` du projet fait exception : il est pris en compte même s'il est créé pendant la session).

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": ["Bash(npm run lint)", "Bash(npm run test *)"],
    "deny": ["Read(./.env)", "Read(./.env.*)"]
  }
}
```

La ligne `$schema` active l'autocomplétion et la validation dans VS Code ou Cursor. Les fichiers sont du JSON strict : un commentaire `//` ou une virgule finale est une erreur.

Chaque modification détectée déclenche le hook `ConfigChange`, utile pour journaliser ou bloquer des changements de configuration.

## Ce qui n'est pas rechargé à chaud

Certaines clés ne sont lues qu'au démarrage de la session :

- **`model`** : utilisez `/model` pour changer en cours de route ;
- **`effortLevel`** et **`modelSettings`** : utilisez `/effort`.

Autres cas à connaître :

- **Serveurs MCP** : ils se gèrent avec `claude mcp add` ou `.mcp.json`, pas dans `settings.json`. Après un changement, `/mcp reconnect <serveur>` (ou `/mcp reconnect all`) relance la connexion.
- **Plugins** : `/reload-plugins` applique les changements sans redémarrer.
- **Skills** : les modifications de `.claude/skills/` sont prises en compte automatiquement ; `/reload-skills` sert pour un dossier créé en cours de session ou pour `.claude/commands/`.
- **Variables d'environnement du shell** (`ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`…) : lues au lancement.
- **Réglages gérés par l'organisation** arrivant par MDM ou la console claude.ai : ils arrivent selon un calendrier, pas à l'enregistrement.

## Précédence des fichiers

Quand une même clé est définie à plusieurs endroits, du plus fort au plus faible :

1. **Réglages gérés** (organisation) : rien ne les surcharge ;
2. **Ligne de commande** : `--settings`, `--model`, etc., pour la session seulement ;
3. **`.claude/settings.local.json`** : vos réglages personnels pour ce projet ;
4. **`.claude/settings.json`** : réglages d'équipe versionnés ;
5. **`~/.claude/settings.json`** : vos réglages pour tous les projets.

Les listes (comme `permissions.allow`) se cumulent au lieu de se remplacer. Les variables d'environnement ne sont pas un niveau de cette pile : leur priorité se décide clé par clé (par exemple `ANTHROPIC_MODEL` l'emporte sur la clé `model` de n'importe quel fichier).

Conséquence pratique : une valeur modifiée avec `/config` va dans vos réglages utilisateur. Si le projet définit la même clé dans `.claude/settings.json`, c'est la valeur du projet qui s'applique. Pour un changement d'équipe, éditez `.claude/settings.json` et commitez.

## Tester un réglage sans l'enregistrer

Pour une seule session, passez la valeur au lancement :

```bash
claude --settings '{"model": "claude-opus-5-5"}'
claude --model sonnet --effort high
```

Pour basculer souvent entre profils, préparez des fichiers JSON et des alias shell plutôt qu'une commande personnalisée qui réécrirait `settings.json` :

```bash
# ~/.zshrc
alias claude-revue='claude --settings ~/.claude/profils/revue.json'
alias claude-rapide='claude --model haiku --effort low'
```

Une commande personnalisée ne peut pas exécuter `/model` ou `/config`. Elle peut seulement fixer `model` et `effort` pour son propre tour via son frontmatter (voir [Le frontmatter des commandes](/wiki/slash-commands/markdown-frontmatter)).

## En cas de fichier invalide

- **Settings Error** : le fichier entier est invalide (JSON cassé ou valeur refusée). Au démarrage d'une session interactive, une fenêtre propose de le corriger avec l'aide de Claude, de quitter ou de continuer sans ce fichier.
- **Settings Warning** : seules certaines entrées sont refusées (règle mal formée, événement de hook inconnu). Elles sont ignorées, le reste s'applique.
- **`~/.claude.json` illisible** : Claude Code en garde une copie dans `~/.claude/backups/` et propose de réinitialiser.

En `claude -p`, aucune fenêtre n'apparaît : les valeurs invalides sont ignorées en silence. Lancez `claude doctor` pour voir ce qui a été écarté, et `/status` pour vérifier les fichiers chargés.

Pour décrire un changement en langage naturel (« autorise npm test », « ajoute un hook après chaque édition »), le skill intégré `/update-config` modifie le bon fichier pour vous.
