Deux commandes vous évitent les mauvaises surprises : `/usage` pour savoir ce que coûte la session et où en sont vos limites, `/compact` pour résumer une conversation trop longue et continuer la même tâche. `/cost` existe toujours, mais c'est désormais un simple alias de `/usage`.

## `/usage` : coût, limites et statistiques

`/usage` réunit trois informations : le coût de la session, les limites de votre offre et des statistiques d'activité. `/cost` et `/stats` ouvrent le même écran (`/stats` directement sur l'onglet Stats). La commande s'exécute même pendant que Claude répond.

Le bloc Session ressemble à ceci :

```text
Total cost:            $0.55
Total duration (API):  6m 20s
Total duration (wall): 6h 33m 10s
Total code changes:    0 lines added, 0 lines removed
Usage by model:
   claude-opus-5-5:  1.2k input, 5.3k output, 940.0k cache read, 50.0k cache write ($0.55)
Prompt cache (main):   14 requests · 91% of input tokens from cache · 2 misses ...
```

Comment le lire :

- **Le montant est une estimation** calculée localement au prix catalogue. La facture fait foi dans la console Claude.
- **Abonnés Pro, Max, Team, Enterprise** : le montant en dollars ne vous est pas facturé. Regardez plutôt les barres de limites et la répartition (skills, sous-agents, plugins, serveurs MCP) sur 24 h ou 7 jours (touches `d` et `w`).
- **Le cache** : une lecture en cache coûte environ 10 % du prix d'entrée normal. Sur Opus 5.5 (4 $ / 20 $ par million de tokens en entrée / sortie), relire 1 million de tokens en cache coûte donc environ 0,40 $. Une ligne `Prompt cache` avec un fort pourcentage et peu de « misses » signale une session saine.
- **Remise à zéro** : les totaux repartent à 0 après un `/clear`.

Pour suivre le coût en continu, ajoutez-le à votre [ligne de statut](/wiki/cli/status-line-custom). En mode non interactif, `--output-format json` renvoie `total_cost_usd`.

## Pourquoi la consommation grimpe

Chaque requête renvoie toute la conversation au modèle. Les causes classiques d'une session qui coûte cher :

- un contexte long jamais nettoyé ;
- une pause plus longue que la durée du cache (une heure sur abonnement, cinq minutes par défaut avec une clé API), qui oblige à tout retraiter ;
- des tâches planifiées (`/loop`), des sous-agents ou des workflows qui envoient leurs propres requêtes ;
- la compaction elle-même, qui relit toute la conversation pour la résumer.

`/context` affiche ce qui remplit la fenêtre : fichiers, outils MCP, mémoire, skills. C'est le premier réflexe avant de compacter.

## `/compact` : résumer pour continuer

`/compact` remplace l'historique par un résumé et libère de la place, tout en restant sur la même tâche. Vous pouvez orienter le résumé :

```text
> /compact
> /compact Garder les décisions sur le schéma SQL et la liste des fichiers modifiés
```

Pour des consignes permanentes, ajoutez une section à votre `CLAUDE.md` :

```markdown
# Compact instructions

Lors d'une compaction, conserver la sortie des tests et les changements de code.
```

Bons moments pour compacter :

- vous êtes au milieu d'une tâche longue et `/context` montre une fenêtre bien remplie ;
- l'avertissement de compaction automatique apparaît ;
- vous allez faire une pause longue sur une grosse session (le cache aura expiré au retour).

Mauvais moments :

- vous changez de sujet : `/clear` est gratuit et plus propre ;
- vous aurez besoin d'un détail précis vu plus tôt : il risque de disparaître du résumé ;
- la conversation est courte : le résumé n'apporte rien.

Ce qui survit à la compaction (règles, `CLAUDE.md`, skills invoqués) est détaillé dans la documentation sur la fenêtre de contexte. Retenez que les skills invoqués sont réattachés dans une limite de taille : un très gros skill peut être tronqué.

## La compaction automatique

Claude Code compacte tout seul quand la conversation approche de la limite. `/autocompact` règle ce seuil :

```text
> /autocompact          # affiche la fenêtre actuelle
> /autocompact 500k     # compacter vers 500 000 tokens
> /autocompact auto     # revenir au réglage adapté au modèle
```

La valeur est enregistrée dans vos réglages utilisateur (v2.1.221 et plus).

Pour garder une trace de chaque compaction, un hook `PreCompact` peut écrire dans un journal. Le matcher distingue `manual` et `auto` :

```json
{
  "hooks": {
    "PreCompact": [
      {
        "matcher": "auto",
        "hooks": [
          {
            "type": "command",
            "command": "echo \"compaction auto $(date -Iseconds)\" >> \"$CLAUDE_PROJECT_DIR/.claude/compact.log\""
          }
        ]
      }
    ]
  }
}
```

## Réduire la facture sans compacter

- `/clear` entre deux tâches sans rapport.
- `/model` : réservez Opus aux tâches difficiles, Sonnet 5.5 (2 $ / 10 $) suffit pour beaucoup de travail courant.
- `/effort` : un niveau plus bas réduit les tokens de réflexion sur les tâches simples.
- Déplacez les instructions spécialisées de `CLAUDE.md` vers des skills, chargés seulement quand ils servent.
- Désactivez dans `/mcp` les serveurs inutilisés.
- Confiez les sorties volumineuses (tests, logs) à un sous-agent : seul le résumé revient.

## Erreurs classiques

- **Lire le montant de `/usage` comme une facture** quand on est abonné : ce sont les barres de limites qui comptent.
- **Compacter pour changer de sujet** : le résumé devient du bruit.
- **Compacter trop souvent une petite session** : chaque compaction est elle-même une grosse requête.
