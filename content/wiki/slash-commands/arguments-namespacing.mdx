Une commande sans argument ne sait faire qu'une chose. Dès que vous voulez la paramétrer (un numéro de PR, un fichier, un mode), il faut savoir où les valeurs arrivent dans le prompt. Et dès que le catalogue grossit, les préfixes de namespacing gardent le menu `/` lisible. Tout ce qui suit vaut pour les skills comme pour l'ancien format `.claude/commands/`.

## `$ARGUMENTS` : tout le texte d'un bloc

Tout ce que vous tapez après le nom de la commande remplace `$ARGUMENTS`. Exemple, `.claude/skills/expliquer/SKILL.md` :

```md
---
description: Explique un concept ou le rôle d'un fichier
argument-hint: <concept ou chemin>
---

Expliquez simplement : $ARGUMENTS

S'il s'agit d'un chemin de fichier, lisez-le et résumez son rôle.
Sinon, expliquez le concept en trois paragraphes au plus.
```

```text
> /expliquer RLS Supabase
> /expliquer lib/curriculum.ts
```

La substitution se fait dans le texte envoyé à Claude, pas dans un shell. Si vous passez des arguments alors qu'aucun emplacement ne les reçoit, Claude Code ajoute `ARGUMENTS: <votre texte>` à la fin du prompt : Claude voit quand même ce que vous avez tapé.

## Arguments par position : `$0`, `$1`, `$ARGUMENTS[N]`

Pour distinguer plusieurs paramètres, utilisez les positions (comptées à partir de 0) :

```md
---
description: Crée une route API Next.js
argument-hint: <GET|POST|PUT|DELETE> <chemin>
---

Créez un handler $0 dans app/api/$1/route.ts.
Respectez les conventions d'authentification du CLAUDE.md.
```

```text
> /route-api POST wiki/comments
```

`$0` vaut `POST`, `$1` vaut `wiki/comments`. `$ARGUMENTS[1]` est la forme longue de `$1`.

Les positions suivent les règles de guillemets du shell : `/ma-commande "hello world" second` donne `$0` = `hello world` et `$1` = `second`. `$ARGUMENTS`, lui, contient toujours la chaîne complète telle que tapée.

## Arguments nommés

Le champ `arguments` du frontmatter donne un nom à chaque position :

```md
---
description: Migre un composant d'un langage vers un autre
arguments: [composant, depuis, vers]
argument-hint: <composant> <depuis> <vers>
---

Migrez le composant $composant de $depuis vers $vers.
Conservez le comportement et les tests existants.
```

```text
> /migrer SearchBar JavaScript TypeScript
```

Différence de comportement à connaître : un argument nommé absent devient une chaîne vide, alors qu'un `$2` sans valeur reste écrit tel quel (`$2`) dans le prompt.

## Échappement et cas particuliers

- **Dollar littéral** : écrivez `\$1.00` pour afficher « $1.00 » sans substitution.
- **Valeurs contenant `$`** : si vous tapez `/resumer "$ARGUMENTS d'hier"`, la valeur est insérée telle quelle, sans nouvelle substitution.
- **Variables toujours remplacées** : `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_SESSION_ID}` et `${CLAUDE_EFFORT}` sont remplacées après les arguments. `${CLAUDE_SKILL_DIR}` sert à appeler un script rangé dans le dossier du skill.

## Enchaîner plusieurs skills

Depuis la v2.1.199, vous pouvez empiler jusqu'à six skills en début de message. Le texte qui suit est passé à chacun :

```text
> /ecrire-tests /corriger-issue 123
```

L'enchaînement s'arrête au premier élément qui n'est pas un skill simple : `/code-review`, qui tourne dans un sous-agent, ou `/loop` terminent la chaîne et tout ce qui suit devient du texte d'argument.

## Namespacing

### Ancien format : les sous-dossiers deviennent des préfixes

Dans `.claude/commands/`, chaque sous-dossier devient un préfixe séparé par `:` :

```text
.claude/commands/
  db/
    migrate.md        → /db:migrate
    seed.md           → /db:seed
  pr/
    resume.md         → /pr:resume
  release.md          → /release
```

Le chemin complet est converti, donc `db/migrations/new.md` donne `/db:migrations:new`. Tapez `/db` pour filtrer tout le domaine dans le menu.

### Skills : un dossier par skill

Un skill vit dans son propre dossier (`.claude/skills/db-migrate/SKILL.md` donne `/db-migrate`). Pour regrouper, deux options :

- **un préfixe dans le nom** : `db-migrate`, `db-seed`, `pr-resume`. Le menu ignore les séparateurs `-` et `:` dans sa recherche, taper `/db` les retrouve ;
- **un plugin** : ses skills sont toujours préfixés par le nom du plugin, par exemple `/outils-db:migrate`. C'est la bonne solution pour un catalogue partagé entre dépôts.

Dans un monorepo, si un skill `deploy` existe à la racine et dans `apps/web/.claude/skills/`, `/deploy` lance celui de la racine et `/apps/web:deploy` celui du sous-dossier.

## Mélanger arguments et namespacing

`.claude/commands/db/migrate.md` :

```md
---
description: Crée une migration Supabase
argument-hint: <nom_de_migration> "<description>"
allowed-tools: Bash(supabase migration new *)
---

Créez une migration nommée `$0` avec `supabase migration new $0`,
puis écrivez le SQL correspondant à cette demande : $1
Activez RLS sur toute nouvelle table.
```

```text
> /db:migrate ajout_votes "table des votes du wiki, un vote par utilisateur"
```

## Limites à connaître

- Aucune validation : une valeur absurde arrive telle quelle. Décrivez dans le prompt ce que Claude doit refuser.
- `$ARGUMENTS` est inséré dans un prompt, pas exécuté. En revanche, ne le placez jamais dans un bloc `` !`…` `` qui, lui, s'exécute dans un shell (voir [Bash injection](/wiki/slash-commands/bash-injection-securisee)).
- Pour des flags et des grammaires plus riches, voir [Arguments complexes](/wiki/slash-commands/arguments-complexes).
