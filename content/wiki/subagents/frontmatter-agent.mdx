Le frontmatter YAML en tête d'un fichier `.claude/agents/<nom>.md` configure le subagent : identité, outils, modèle, permissions, mémoire, isolation. Cette page liste les champs officiels et leurs valeurs. Les noms en plusieurs mots s'écrivent en camelCase et doivent correspondre exactement : un champ inconnu est ignoré sans message d'erreur.

## Squelette minimal

```markdown
---
name: doc-writer
description: Met à jour la documentation Markdown à partir du code. À utiliser après un changement d'API.
---

Vous êtes rédacteur technique...
```

Seuls `name` et `description` sont obligatoires. Le nom de fichier n'a pas besoin de correspondre au `name`.

## Tableau de référence

| Champ | Valeurs | Rôle |
| --- | --- | --- |
| `name` | texte, sans `:` ni `-` initial | Identifiant unique ; reçu par les hooks comme `agent_type` |
| `description` | texte | Quand Claude doit déléguer à cet agent |
| `tools` | liste ou chaîne séparée par des virgules | Liste blanche d'outils ; tous hérités si absent |
| `disallowedTools` | même format | Outils retirés |
| `model` | `sonnet`, `opus`, `haiku`, `fable`, ID complet, `inherit` | Modèle de l'agent |
| `permissionMode` | `default` (alias `manual`), `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions`, `plan` | Mode de permission |
| `maxTurns` | entier | Nombre maximal de tours ; la sortie est alors marquée partielle |
| `skills` | liste | Skills préchargées en entier au démarrage |
| `mcpServers` | liste | Serveurs MCP propres à l'agent |
| `hooks` | objet | Hooks actifs seulement pendant l'exécution de l'agent |
| `memory` | `user`, `project`, `local` | Mémoire persistante entre sessions |
| `background` | `true` | Toujours en arrière-plan |
| `omitClaudeMd` | `true` | Ne charge pas les CLAUDE.md utilisateur, projet et local |
| `effort` | `low`, `medium`, `high`, `xhigh`, `max` | Niveau d'effort, prioritaire sur celui de la session |
| `isolation` | `worktree` | Exécution dans un worktree Git temporaire |
| `color` | `red`, `blue`, `green`, `yellow`, `purple`, `orange`, `pink`, `cyan` | Couleur dans la liste des tâches et le transcript |
| `initialPrompt` | texte | Premier message envoyé quand l'agent est l'agent de session (`--agent`) |
| `experimental` | objet (`cacheTtl: 5m` ou `1h`) | Durée du cache de prompt pour cet agent |

## `tools` et `disallowedTools`

```yaml
tools: Read, Grep, Glob, Bash
```

- Sans `tools`, l'agent hérite de tous les outils disponibles aux subagents, outils MCP compris.
- Si les deux champs sont présents, `disallowedTools` s'applique d'abord.
- Motifs MCP acceptés : `mcp__github` ou `mcp__github__*` (tout un serveur) ; dans `disallowedTools`, `mcp__*` retire tous les outils MCP.
- Une entrée avec spécificateur comme `Bash(git push *)` dans `disallowedTools` retire **tout** l'outil `Bash`. Pour bloquer une seule commande, utilisez une règle `permissions.deny` dans vos réglages.
- Si aucune entrée ne correspond à un outil réel (faute de frappe), l'agent refuse de démarrer avec une erreur qui nomme les entrées fautives.
- Certains outils ne sont jamais donnés à un subagent (`AskUserQuestion`, `EnterPlanMode`, `Workflow`…), et un subagent en arrière-plan ne garde qu'une liste réduite d'outils intégrés (`Read`, `Grep`, `Glob`, `Bash`, `Edit`, `Write`, `WebFetch`, `WebSearch`, `Skill`, `SendMessage`…).
- Ajouter `Agent` permet au subagent de lancer ses propres subagents, dans la limite de profondeur. La syntaxe `Agent(worker, researcher)` ne filtre les types que pour un agent lancé en session principale avec `claude --agent`.

## `model`

Ordre de résolution : paramètre `model` passé par Claude à l'appel, puis frontmatter, puis `CLAUDE_CODE_SUBAGENT_MODEL`, puis modèle de la conversation. Si le modèle principal appartient à la même famille que l'alias (par exemple `opus` alors que vous êtes sur Opus 5.5), l'agent reprend le modèle exact de la conversation. `/tasks` affiche le modèle réellement utilisé.

## `permissionMode`

La valeur n'est respectée que si la conversation principale est en `default`, `dontAsk` ou `plan`. Si la session est en `auto`, `acceptEdits` ou `bypassPermissions`, le subagent suit ce mode et votre valeur est ignorée. Un agent ne peut jamais s'accorder `bypassPermissions` si la session ne l'a pas.

## `skills`

```yaml
skills:
  - api-conventions
  - error-handling-patterns
```

Le contenu complet de chaque skill est injecté au démarrage. Sans ce champ, l'agent peut quand même invoquer les skills via l'outil `Skill`. Les skills avec `disable-model-invocation: true` ne peuvent pas être préchargées.

## `mcpServers`

```yaml
mcpServers:
  - playwright:
      type: stdio
      command: npx
      args: ["-y", "@playwright/mcp@latest"]
  - github
```

Une définition en ligne n'est connectée que pendant l'exécution de l'agent : ses descriptions d'outils n'encombrent pas la conversation principale. Un nom seul réutilise un serveur déjà configuré.

## `hooks`

```yaml
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/validate-readonly-query.sh"
```

Tous les événements sont acceptés. Un hook `Stop` déclaré ici devient `SubagentStop` à l'exécution. Pour un agent de projet, ces hooks ne tournent qu'après acceptation de la confiance du dossier.

## `memory`

| Portée | Dossier |
| --- | --- |
| `user` | `~/.claude/agent-memory/<nom>/` |
| `project` | `.claude/agent-memory/<nom>/` (versionnable, portée recommandée) |
| `local` | `.claude/agent-memory-local/<nom>/` |

L'agent reçoit les 200 premières lignes (ou 25 Ko) de `MEMORY.md`, et les outils `Read`, `Write` et `Edit` sont activés pour gérer ce dossier. Sans mémoire automatique activée, le champ n'a aucun effet.

## `isolation: worktree`

L'agent travaille dans un worktree Git temporaire, créé par défaut depuis votre branche par défaut (pas depuis le `HEAD` de la session). Le worktree est supprimé si l'agent ne modifie rien. Claude Code bloque les commandes qui tenteraient d'agir sur votre copie principale.

## `background`

`background: true` force l'exécution en arrière-plan. En session interactive, le fork mode lance déjà les subagents en arrière-plan par défaut ; le champ sert surtout en mode `-p` et avec l'Agent SDK.

## Champs à ne pas utiliser

Des articles plus anciens citaient `isolation: strict | inherit`, `disallowed_tools` ou `permission_mode`. Ces valeurs et graphies n'existent pas : elles sont ignorées sans erreur.

## Vérifier un agent

- `claude --debug` affiche pourquoi un fichier a été ignoré.
- `claude plugin validate .claude/agents` signale le YAML invalide (v2.1.233 ou plus).
- `/tasks` montre le modèle et l'effort d'un agent en cours.
