Un subagent peut lui-même déléguer une partie de sa tâche à d'autres subagents. C'est utile quand une tâche déléguée se découpe à son tour en sous-tâches parallèles, par exemple un relecteur qui lance un vérificateur par problème trouvé. Sans garde-fous, l'arbre grossit vite et les tokens avec lui.

## Ce que permet Claude Code

Par défaut, un subagent peut lancer des subagents jusqu'à **trois niveaux sous la conversation principale**. Au niveau limite, Claude Code retire l'outil `Agent` au subagent : il fait lui-même le travail et renvoie un seul résumé.

| Version de Claude Code | Comportement par défaut |
| --- | --- |
| v2.1.172 à v2.1.216 | Imbrication jusqu'à 5 niveaux, non réglable |
| v2.1.217 et v2.1.218 | 1 niveau (pas d'imbrication sans réglage) |
| v2.1.219 et suivantes | 3 niveaux, réglable |

Vérifiez votre version avec `claude --version` : un ancien tutoriel peut décrire un autre comportement.

## Régler la profondeur

```json
{
  "env": {
    "CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH": "2"
  }
}
```

Avec `2`, vos subagents peuvent déléguer à un second niveau, qui ne peut pas aller plus loin. Avec `1`, l'imbrication est désactivée.

Pour empêcher un seul agent de déléguer (un relecteur qui doit rester en lecture seule, par exemple), retirez `Agent` de sa liste `tools` ou ajoutez-le à `disallowedTools`. La syntaxe `Agent(worker, researcher)`, qui restreint les types lançables, ne fonctionne que pour un agent lancé en session principale avec `claude --agent` ; dans une définition de subagent, la liste entre parenthèses est ignorée.

## Comment remontent les résultats

- **Session interactive** : seul le résumé du subagent de premier niveau vous parvient. Un subagent qui lance des subagents en arrière-plan attend leurs résultats avant de terminer.
- **Mode `-p` et Agent SDK** : le subagent lanceur n'attend pas. Un sous-subagent qui termine après lui envoie son rapport directement à la conversation principale.
- **Forks** : un fork ne peut pas lancer d'autres forks.

Dans le terminal, le panneau sous la zone de saisie affiche les subagents en arbre ; un compteur `(+N)` indique le nombre de descendants encore actifs.

## Concevoir l'arbre

Dessinez l'arbre avant de lancer :

```text
conversation principale
  └── reviewer (lit le diff, liste les problèmes)
        ├── verifier n°1 (confirme ou infirme le problème 1)
        ├── verifier n°2
        └── verifier n°3
```

Règles utiles :

- **Une responsabilité par nœud**, une entrée claire (le brief) et une sortie claire (le rapport).
- **Aplatir plutôt qu'allonger** : si vous avez besoin d'un troisième niveau, un nœud fait souvent trop de choses.
- **Pas de communication implicite entre frères** : c'est le parent qui transmet. Des subagents nommés peuvent s'écrire avec `SendMessage`, mais gardez ce cas pour des besoins précis.
- **Dépendances en losange** : si B et C ont besoin du même résultat D, faites calculer D une fois par le parent et transmettez-le.

## Éviter les boucles et la dérive

La limite de profondeur empêche une récursion infinie, mais pas une cascade coûteuse. Dans vos prompts d'agents :

1. **Critère d'arrêt vérifiable** : test qui passe, fichier qui existe, liste non vide.
2. **Pas d'auto-délégation** : un agent ne doit pas relancer un agent du même type pour « réessayer ».
3. **Budget de tours** : `maxTurns` dans le frontmatter arrête un agent qui tourne en rond ; sa sortie revient marquée partielle.
4. **Rapport partiel plutôt que relance** : en cas d'échec, l'agent remonte ce qu'il a trouvé au parent.

Rappel : 20 subagents simultanés au maximum par session par défaut (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`), tous niveaux confondus.

## Observer l'arbre avec des hooks

Les hooks `SubagentStart` et `SubagentStop` reçoivent `agent_id` et `agent_type`. `SubagentStop` reçoit aussi `agent_transcript_path` et `last_assistant_message`. Un journal minimal :

```json
{
  "hooks": {
    "SubagentStop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "jq -c '{t: now, id: .agent_id, type: .agent_type}' >> .claude/subagents.log"
          }
        ]
      }
    ]
  }
}
```

Les transcripts de chaque subagent sont aussi conservés dans `~/.claude/projects/<projet>/<session>/subagents/agent-<id>.jsonl`.

## Quand passer à un workflow

Si votre arbre devient un vrai pipeline (des dizaines d'agents, étapes répétables, recoupement des résultats), un [dynamic workflow](/wiki/cli/dynamic-workflows-agents-arriere-plan) est plus adapté : le plan vit dans un script, les résultats intermédiaires restent dans des variables et la conversation ne reçoit que la réponse finale.
