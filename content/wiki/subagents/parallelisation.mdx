Lancer plusieurs subagents en parallèle réduit fortement l'attente sur les tâches d'exploration ou d'audit. Mal découpé, le parallélisme multiplie les tokens et produit des résultats qui se recoupent. Voici comment Claude Code gère la concurrence en 2026 et comment en tirer parti.

## Comment les subagents partent en parallèle

En session interactive, le fork mode est actif par défaut (v2.1.232 ou plus) : Claude Code lance **tous** les subagents en arrière-plan. Vous continuez à travailler pendant qu'ils tournent, et leurs résultats arrivent sous forme de notification de fin dans un tour suivant. Claude attend ces notifications avant de vous présenter une synthèse.

En mode `-p` et dans l'Agent SDK, le fork mode est inactif : Claude lance les subagents en arrière-plan par défaut, mais au premier plan quand il a besoin du résultat pour continuer. Plusieurs appels de l'outil `Agent` dans un même tour partent alors en même temps.

Dans les deux cas, il suffit de le demander clairement :

```text
Étudiez en parallèle, avec un subagent chacun :
1. app/api/ : quelles routes vérifient le jeton Supabase ?
2. lib/ : où le client Supabase est-il créé ?
3. content/ : quels articles n'ont pas de champ updatedAt ?
Chaque subagent répond en 10 lignes maximum.
```

## Les limites officielles

| Limite | Valeur par défaut | Réglage |
| --- | --- | --- |
| Subagents simultanés dans une session | 20 | `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` |
| Profondeur d'imbrication | 3 niveaux sous la conversation principale | `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` |
| Nombre total de subagents sur une session | aucune limite | |

Au-delà de 20 subagents actifs, un nouvel appel échoue avec `Concurrent subagent limit reached` et Claude ne réessaie pas ; l'appel redevient possible dès qu'un emplacement se libère. Les sessions avec ultracode actif ne sont pas soumises à cette limite. Les agents des dynamic workflows et des équipes d'agents ont leurs propres limites.

## Suivre et piloter les subagents

- Le panneau sous la zone de saisie liste les subagents en cours, en arbre s'ils sont imbriqués.
- `/tasks` liste tout ce qui tourne en arrière-plan, avec le modèle de chaque subagent ; `x` arrête l'élément sélectionné.
- **Ctrl+B** envoie une tâche en cours en arrière-plan.
- Les demandes de permission d'un subagent en arrière-plan apparaissent dans votre session principale, avec le nom de l'agent. Échap refuse l'appel d'outil sans arrêter l'agent.

## Quand paralléliser

- Recherches indépendantes : frontend et backend, trois bibliothèques candidates.
- Vérifications croisées : un agent lit le code, un autre les tests, un troisième la documentation.
- Audit en éventail : vulnérabilités, `TODO`, types `any`, chacun par un agent.

## Quand ne pas paralléliser

- Si B a besoin du résultat de A : enchaînez les deux (« utilisez l'agent X pour trouver, puis l'agent Y pour corriger »).
- Si les agents écrivent dans les mêmes fichiers : risque de conflit. Donnez à chacun `isolation: worktree` (copie Git isolée) ou un périmètre de fichiers distinct.

## Découper pour éviter le travail en double

Les subagents ne se voient pas entre eux. Sans périmètre explicite, trois agents liront les mêmes fichiers et vous paierez trois fois. Précisez dans chaque brief :

- le dossier ou le motif de fichiers (« uniquement `app/api/**/*.ts` ») ;
- ce qu'il ne faut pas regarder ;
- un format de sortie commun (même tableau, mêmes colonnes) pour fusionner facilement.

## Surveiller le coût

Chaque subagent consomme ses propres tokens, sur les mêmes limites d'usage que votre session. Et tous les rapports reviennent dans la conversation principale : dix rapports de 2 000 tokens, c'est 20 000 tokens injectés d'un coup. Demandez des réponses courtes et structurées. Voir [Coût et budget de tokens](/wiki/subagents/cout-token-budgeting).

## Au-delà d'une poignée d'agents

- **`/batch`** : skill qui découpe un gros changement en 5 à 30 subagents isolés chacun dans un worktree.
- **Dynamic workflows** : un script JavaScript orchestre des dizaines ou centaines d'agents (16 simultanés par défaut, 1 000 au maximum par exécution), avec recoupement des résultats. Suivi via `/workflows`. Voir [Dynamic workflows](/wiki/cli/dynamic-workflows-agents-arriere-plan).
- **Agent view** : `claude agents` pour lancer et suivre plusieurs sessions indépendantes.
