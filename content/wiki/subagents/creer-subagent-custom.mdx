Un subagent personnalisé est un simple fichier Markdown : le frontmatter YAML sert de configuration, le corps devient le prompt système. Créez-en un dès que vous relancez souvent le même type de tâche avec les mêmes consignes (revue, tests, migration, rédaction de documentation).

## Où placer le fichier

Quand deux agents portent le même `name`, Claude Code garde celui de l'emplacement prioritaire :

| Emplacement | Portée | Priorité |
| --- | --- | --- |
| Paramètres gérés (managed settings) | Toute l'organisation | 1 (la plus haute) |
| Flag `--agents` | Session en cours | 2 |
| `.claude/agents/` | Projet courant, versionnable | 3 |
| `~/.claude/agents/` | Tous vos projets | 4 |
| Dossier `agents/` d'un plugin | Là où le plugin est activé | 5 |

Points pratiques :

- Les dossiers sont lus récursivement : vous pouvez ranger vos agents dans `agents/review/` ou `agents/research/`. L'identité vient uniquement du champ `name`.
- Les `.claude/agents/` sont cherchés en remontant depuis le dossier courant jusqu'à la racine du dépôt ; le plus proche gagne.
- Claude Code surveille ces dossiers : une modification est prise en compte en quelques secondes, sans redémarrage. Redémarrez seulement si le dossier `agents` n'existait pas au lancement de la session.

## Trois façons de créer un agent

1. **Demander à Claude** : c'est la méthode recommandée. Depuis la v2.1.198, `/agents` n'ouvre plus d'assistant interactif ; il rappelle simplement de demander à Claude ou d'éditer les fichiers.

   ```text
   Créez un subagent personnel code-improver dans ~/.claude/agents/
   qui analyse les fichiers et propose des améliorations de lisibilité
   et de performance. Il doit être en lecture seule et utiliser Sonnet.
   ```

2. **Écrire le fichier vous-même** dans `.claude/agents/` (partagé avec l'équipe via Git) ou `~/.claude/agents/`.
3. **Le passer en JSON** avec `--agents` pour une session ou un script (voir plus bas).

## Exemple complet

```markdown
---
name: api-auth-reviewer
description: Vérifie l'authentification des routes API. À utiliser après toute modification dans app/api/.
tools: Read, Grep, Glob, Bash
model: sonnet
color: orange
---

Vous êtes un relecteur sécurité spécialisé dans les routes API Next.js.

Quand vous êtes invoqué :
1. Lancez `git diff --name-only` et ne gardez que les fichiers sous app/api/.
2. Pour chaque route, vérifiez que le jeton est contrôlé avant tout accès aux données.
3. Signalez les secrets en clair et les entrées non validées.

Format de sortie :
- Un tableau Fichier | Ligne | Gravité (critique, majeur, mineur) | Problème
- « RAS » si vous ne trouvez rien.

Ne modifiez aucun fichier.
```

Seuls `name` et `description` sont obligatoires. Le subagent reçoit ce prompt plus quelques détails d'environnement (dossier de travail), pas le prompt système complet de Claude Code. Il charge en revanche vos fichiers CLAUDE.md et un instantané `git status`, sauf si vous ajoutez `omitClaudeMd: true`.

## Écrire une bonne `description`

Claude choisit l'agent à partir de sa description. Elle doit dire **quand** l'utiliser et, si possible, ce qu'il livre.

- Bon : « Lance les tests et rapporte uniquement les échecs. À utiliser après une modification de code. »
- Trop vague : « Aide sur le code. »
- Pour encourager la délégation automatique, ajoutez une formule comme « Use proactively » ou « À utiliser de façon proactive ».

Restez bref : au-delà de 15 000 tokens cumulés pour les descriptions de vos agents (hors agents intégrés), Claude Code affiche un avertissement au démarrage. Mettez le détail dans le corps du fichier, qui ne se charge qu'à l'exécution.

## Outils et modèle

- `tools` est une liste blanche. Sans ce champ, l'agent hérite de tous les outils disponibles aux subagents, MCP compris.
- `disallowedTools` retire des outils de cette liste héritée.
- `model` accepte `sonnet`, `opus`, `haiku`, `fable`, un identifiant complet comme `claude-opus-5-5`, ou `inherit`.

Ordre de résolution du modèle (depuis la v2.1.251) :

1. le paramètre `model` passé par Claude lors de l'appel ;
2. le champ `model` du frontmatter ;
3. la variable `CLAUDE_CODE_SUBAGENT_MODEL` ;
4. le modèle de la conversation principale.

Pour imposer un modèle à tous les subagents, ajoutez `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`. Le détail de chaque champ est dans la [référence du frontmatter](/wiki/subagents/frontmatter-agent).

## Définir des agents en ligne de commande

```bash
claude --agents '{
  "debugger": {
    "description": "Spécialiste du débogage pour les erreurs et tests en échec.",
    "prompt": "Vous analysez les erreurs, trouvez la cause racine et proposez un correctif.",
    "tools": ["Read", "Edit", "Bash", "Grep", "Glob"],
    "model": "sonnet"
  }
}'
```

Ces agents n'existent que pour la session. En mode `-p`, `--agents` accepte aussi le chemin d'un fichier JSON (v2.1.281 ou plus). Les champs `color` et `experimental` y sont ignorés.

## Invoquer votre agent

- **Langage naturel** : « Utilisez l'agent api-auth-reviewer sur mes derniers changements ». Claude décide.
- **@-mention** : tapez `@` et choisissez l'agent, ou écrivez `@agent-api-auth-reviewer`. L'agent est alors garanti.
- **Toute la session** : `claude --agent api-auth-reviewer`, ou `"agent": "api-auth-reviewer"` dans `.claude/settings.json`. Le prompt de l'agent remplace alors le prompt système de Claude Code.

## Pièges fréquents

- Un champ mal orthographié (`disallowed_tools` au lieu de `disallowedTools`) est ignoré sans erreur.
- Un fichier sans `name`, sans `description`, avec un `name` contenant `:` ou un YAML invalide est ignoré. Lancez `claude --debug` ou `claude plugin validate .claude/agents` pour comprendre.
- Les agents fournis par un plugin ignorent `hooks`, `mcpServers` et `permissionMode` pour des raisons de sécurité. Copiez le fichier dans `.claude/agents/` si vous en avez besoin.
- Les hooks et serveurs MCP en ligne d'un agent de projet ne s'exécutent qu'après acceptation de la confiance du dossier.
