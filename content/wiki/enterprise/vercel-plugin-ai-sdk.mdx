Si vous déployez sur Vercel, quatre briques relient votre travail avec Claude à la plateforme : le plugin Vercel pour Claude Code, l'AI SDK pour appeler Claude depuis votre application, l'abstraction expérimentale `HarnessAgent` pour faire tourner Claude Code dans une sandbox, et AI Gateway pour centraliser clés, coûts et journaux. Cette page fait le point sur chacune, avec des exemples à jour (AI SDK 7, `@ai-sdk/anthropic` 4.x).

## Le flux de base : Git, previews, variables

Rien de spécifique à Claude ici, mais c'est le socle : un dépôt GitHub (ou GitLab, Bitbucket) importé dans Vercel produit un **déploiement de prévisualisation** à chaque push sur une branche, et un déploiement de production à chaque merge sur la branche principale. Claude Code s'insère naturellement dans ce flux :

- il crée la branche, commite et ouvre la PR (`gh pr create`) ; vous testez l'URL de preview avant de fusionner ;
- il peut dresser la liste des variables d'environnement d'un projet et indiquer celles qui doivent rester côté serveur ; seules les variables préfixées `NEXT_PUBLIC_` sont exposées au navigateur dans Next.js ;
- il ne doit jamais lire ni recopier vos secrets : protégez `.env*` par une règle `deny` dans `.claude/settings.json`.

## Le plugin Vercel pour Claude Code

Vercel maintient un plugin open source (`vercel/vercel-plugin`), disponible dans la marketplace officielle d'Anthropic sous le nom `vercel` :

```bash
/plugin install vercel@claude-plugins-official
```

Il apporte (version 0.54 au moment de la rédaction) :

| Composant | Contenu |
|---|---|
| Graphe de l'écosystème | Un fichier `vercel.md` décrivant les produits Vercel, leurs relations et les produits abandonnés |
| 32 skills | `ai-sdk`, `ai-gateway`, `vercel-functions`, `vercel-sandbox`, `env-vars`, `deployments-cicd`, `workflow`, `vercel-storage`, `vercel-firewall`, etc. |
| 3 sous-agents | `deployment-expert`, `performance-optimizer`, `ai-architect` |
| 4 commandes | `bootstrap`, `deploy`, `env`, `status`, appelées avec l'espace de noms du plugin, par exemple `/vercel:deploy` |
| Hooks | Au `SessionStart`, injection d'un contexte Vercel et profilage du dépôt, uniquement dans un dossier vide ou un projet Vercel, Next.js ou eve détecté |

Deux précisions utiles :

- Les versions récentes ont **allégé** le comportement automatique : les skills ne sont plus injectées à chaque appel d'outil ou à chaque prompt, et le hook après outil se contente d'observer. Vous invoquez les skills à la demande.
- La télémétrie est active par défaut (noms des skills du plugin utilisées, sans contenu de prompt). Désactivez-la avec `VERCEL_PLUGIN_TELEMETRY=off`.

Pour Next.js, le plugin renvoie vers la documentation versionnée fournie par Next.js lui-même (dans `node_modules/next/dist/docs/`) plutôt que vers ses propres skills.

## Appeler Claude depuis votre app avec l'AI SDK

L'AI SDK (`ai`, version 7) exige Node.js 22 ou plus. Deux façons d'appeler Claude :

**Via le fournisseur Anthropic**, avec votre propre clé `ANTHROPIC_API_KEY` :

```bash
npm i ai @ai-sdk/anthropic
```

```ts
import { anthropic, type AnthropicLanguageModelOptions } from '@ai-sdk/anthropic';
import { streamText } from 'ai';

export async function POST(req: Request) {
  const { prompt } = await req.json();

  const result = streamText({
    model: anthropic('claude-sonnet-5-5'),
    system: 'Vous êtes un formateur Claude Code. Répondez en français, clairement.',
    prompt,
    maxOutputTokens: 4000,
    providerOptions: {
      anthropic: {
        effort: 'medium',
      } satisfies AnthropicLanguageModelOptions,
    },
  });

  return result.toTextStreamResponse();
}
```

**Via AI Gateway**, avec une simple chaîne `fournisseur/modèle` (par exemple `anthropic/claude-sonnet-5-5`) passée à `model` : l'authentification passe alors par `AI_GATEWAY_API_KEY` ou par le jeton OIDC de Vercel en déploiement. Vérifiez l'identifiant exact dans la liste renvoyée par `https://ai-gateway.vercel.sh/v1/models`.

Points spécifiques aux modèles Claude actuels, gérés par `@ai-sdk/anthropic` :

| Modèle | Réflexion | Effort par défaut (API) |
|---|---|---|
| `claude-opus-5-5` | Toujours adaptative, impossible à désactiver | `medium` |
| `claude-sonnet-5-5` | Toujours adaptative (niveau minimal `between_tools`) | `high` |

- `effort` accepte `low`, `medium`, `high`, `xhigh` et `max` (selon le modèle). C'est le levier principal de coût et de latence.
- Sur les modèles à réflexion adaptative uniquement, le fournisseur retire `thinking: { type: 'disabled' }` et convertit un budget `budgetTokens` en mode adaptatif, avec un avertissement.
- La réflexion compte dans `maxOutputTokens` : laissez de la marge.
- Une réponse peut commencer par un bloc de réflexion : lisez les parties par type (`text`, `reasoning`, `tool-call`).
- Le cache de prompt se pose avec `providerOptions: { anthropic: { cacheControl: { type: 'ephemeral' } } }` sur un message ou une partie ; les jetons lus et écrits en cache sont dans `usage.inputTokenDetails`.

## Piloter Claude Code en sandbox : `HarnessAgent` (expérimental)

Le paquet `@ai-sdk/harness` (marqué **expérimental**) fournit `HarnessAgent`, une interface commune pour piloter des agents de code existants. L'adaptateur `@ai-sdk/harness-claude-code` s'appuie sur le Claude Agent SDK et fait tourner le CLI `claude` **dans une Vercel Sandbox** (microVM), ce qui isole votre serveur du code généré.

```bash
npm i ai zod @ai-sdk/harness @ai-sdk/harness-claude-code @ai-sdk/sandbox-vercel
```

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { claudeCode } from '@ai-sdk/harness-claude-code';
import { createVercelNetworkSandboxSession } from '@ai-sdk/sandbox-vercel';

const agent = new HarnessAgent({
  harness: claudeCode,
  id: 'refactor-agent',
  model: 'claude-sonnet-5-5',
  instructions: 'Vous êtes un assistant de refactoring prudent. Diffs minimaux.',
});

const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  ports: [4000],
  template: await agent.getSandboxTemplate(),
});
const session = await agent.createSession({ sandboxSession });

try {
  const result = await agent.generate({
    session,
    prompt: 'Corrige le test qui échoue dans src/auth.ts',
  });
  console.log(result.text);
} finally {
  await session.destroy();
  await sandboxSession.destroy();
}
```

L'adaptateur installe `@anthropic-ai/claude-agent-sdk` et `@anthropic-ai/claude-code` dans la sandbox au premier démarrage. C'est vous qui gérez le cycle de vie de la sandbox : fermer la session de l'agent ne l'arrête pas, d'où le bloc `finally`. L'API étant expérimentale, épinglez les versions et relisez le changelog avant chaque mise à jour. Pour un agent qui n'a pas besoin de Claude Code lui-même, `ToolLoopAgent` du paquet `ai` reste la voie standard.

## Faire passer Claude Code par AI Gateway

AI Gateway expose un point d'accès compatible Anthropic. Y router Claude Code donne des journaux par requête, des budgets par clé et une facturation centralisée. La méthode recommandée est l'assistant du CLI Vercel, qui crée ou réutilise une clé, détecte les agents installés et montre le diff avant d'écrire :

```bash
vercel ai-gateway setup --dry-run   # aperçu des changements
vercel ai-gateway setup             # application, après confirmation
```

Configuration manuelle équivalente :

```bash
export ANTHROPIC_BASE_URL="https://ai-gateway.vercel.sh/claude-code"
export ANTHROPIC_API_KEY=""                      # doit rester vide
export ANTHROPIC_AUTH_TOKEN="<votre clé AI Gateway>"
export CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1
```

- `ANTHROPIC_API_KEY` doit être **vide** : une valeur non vide serait utilisée à la place du jeton de la passerelle.
- `ANTHROPIC_AUTH_TOKEN` est envoyé dans l'en-tête `Authorization: Bearer`.
- `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` remplit le sélecteur `/model` à partir des modèles de la passerelle.
- Les sessions d'agent consomment beaucoup de tokens : fixez un budget ou une expiration sur la clé (`--budget`, `--expiration`).
- En cas d'échec, consultez les journaux AI Gateway : `401` = authentification, `402` = crédits ou budget, `429` = limite de débit.

Vérifiez `vercel ai-gateway setup --help` : `--agent <nom>` limite la configuration à un agent, et c'est l'aide du CLI qui fait foi pour la liste des agents pris en charge.
