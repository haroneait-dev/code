Amazon Bedrock sert les modèles Claude sur l'infrastructure AWS, avec l'authentification, la facturation et le périmètre de sécurité d'AWS. Depuis Opus 4.7, Bedrock expose Claude via un endpoint qui reprend exactement le format de l'API Messages d'Anthropic. Voici comment l'utiliser proprement.

## Deux intégrations Bedrock, plus une alternative

| Option | Modèles | Endpoint | Exploité par |
|---|---|---|---|
| **Claude in Amazon Bedrock** (recommandé) | Opus 4.7 et suivants, Sonnet 5, Sonnet 5.5, Fable, Haiku 4.5 | `https://bedrock-mantle.{region}.api.aws/anthropic/v1/messages` | AWS |
| Intégration historique `InvokeModel` / `Converse` | Opus 4.6 et modèles plus anciens (Haiku 4.5 aussi) | `bedrock-runtime.{region}.amazonaws.com` | AWS |
| **Claude Platform on AWS** | Tous les modèles de l'API Claude | `aws-external-anthropic.{region}.api.aws` | Anthropic, facturé via AWS Marketplace |

Choisissez Bedrock si vous voulez que l'inférence reste chez AWS (Anthropic n'a aucun accès opérateur à cette infrastructure). Choisissez Claude Platform on AWS si vous voulez toutes les fonctionnalités de l'API Claude (Batch, Files, Skills, exécution de code) le jour de leur sortie, avec une facturation AWS.

## ID de modèles

Sur l'endpoint Messages, les ID portent le préfixe `anthropic.` et n'ont plus de date ni de suffixe `-v1:0` :

| Modèle | ID Bedrock |
|---|---|
| Opus 5.5 | `anthropic.claude-opus-5-5` |
| Sonnet 5.5 | `anthropic.claude-sonnet-5-5` |
| Fable 5.1 | `anthropic.claude-fable-5-1` |
| Sonnet 5 | `anthropic.claude-sonnet-5` |
| Haiku 4.5 | `anthropic.claude-haiku-4-5` |

Fable 5.1, Sonnet 5, Opus 4.8, Opus 4.7 et Haiku 4.5 sont ouverts à tous les clients Bedrock. Pour Opus 5.5 et Sonnet 5.5, vérifiez les conditions d'accès dans la page **Model access** de la console Bedrock.

## Authentification

Trois chemins, du plus sûr au moins conseillé :

1. **Rôle de service Bedrock** : un administrateur crée le rôle et accorde `iam:PassRole` aux développeurs.
2. **Rôles IAM assumés** via votre fournisseur d'identité (SAML, OIDC, IAM Identity Center), sessions de 12 heures maximum. La politique accorde l'action `bedrock-mantle:CreateInference` sur les seuls modèles autorisés.
3. **Jetons bearer** de courte durée (12 heures maximum), générés avec `aws-bedrock-token-generator`. Bloquez les jetons longue durée avec une condition sur `bedrock:BearerTokenType`.

Exemple de politique minimale (remplacez la ressource par les ARN des modèles autorisés, au format indiqué dans la documentation Bedrock) :

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "bedrock-mantle:CreateInference",
      "Resource": "<ARN des modèles autorisés>"
    }
  ]
}
```

Attachez-la à un rôle (IRSA sur EKS, rôle de tâche ECS, rôle EC2), jamais à un utilisateur IAM avec des clés statiques.

## Premier appel

```bash
pip install -U "anthropic[bedrock]"
```

```python
from anthropic import AnthropicBedrockMantle

client = AnthropicBedrockMantle(aws_region="eu-west-3")  # Paris

message = client.messages.create(
    model="anthropic.claude-sonnet-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Résume ce rapport en trois points."}],
)

print(next(b.text for b in message.content if b.type == "text"))
```

Le SDK lit les identifiants AWS dans l'ordre standard (arguments, variables `AWS_*`, profil, rôle). En TypeScript, le paquet est `@anthropic-ai/bedrock-sdk` et la classe `AnthropicBedrockMantle`. Le streaming utilise le SSE standard, comme l'API Claude.

## Régions et résidence des données

- **Endpoint global** : routage dynamique entre toutes les régions, sans surcoût.
- **Endpoint régional** : l'inférence reste dans la région choisie, avec un **surcoût de 10 %**. Pour router dans une zone (US, EU, JP, AU), utilisez un profil d'inférence.

Régions européennes disponibles : `eu-west-3` (Paris), `eu-central-1` (Francfort), `eu-central-2` (Zurich), `eu-west-1` (Irlande), `eu-west-2` (Londres), `eu-north-1` (Stockholm), `eu-south-1` (Milan), `eu-south-2` (Espagne). Pour Fable 5.1, les endpoints régionaux ne sont disponibles qu'en `us-east-1` pour l'instant.

## Ce qui n'existe pas sur Bedrock

D'après la documentation d'Anthropic, l'endpoint Bedrock ne propose pas :

- les sorties structurées (et donc les outils `strict`) ;
- les sources par URL (images, documents) et la Files API ;
- les outils côté serveur : exécution de code, recherche web, web fetch, advisor ;
- Agent Skills, connecteur MCP, appel d'outils programmatique ;
- les endpoints Batch, Models, Admin, Usage ;
- le repli automatique côté serveur (`fallbacks`) : gérez le repli côté client.

Le prompt caching, la réflexion, le tool use (bash, éditeur de texte, mémoire, computer use en version bêta) et les citations sont disponibles. Si une fonctionnalité absente vous est indispensable, regardez Claude Platform on AWS.

## Quotas

Quota par défaut : 2 millions de tokens d'entrée par minute. Vous pouvez demander jusqu'à 5 millions de tokens d'entrée et 500 000 tokens de sortie par minute sans approbation d'Anthropic. Les limites de requêtes par minute se règlent avec le support AWS.

## Observabilité et garde-fous

- **CloudTrail et CloudWatch** reçoivent les journaux. Anthropic recommande de conserver au moins 30 jours d'historique d'activité.
- **Bedrock Guardrails** permet d'ajouter des filtres de contenu et de données personnelles. Vérifiez dans la documentation AWS leur compatibilité avec l'endpoint Messages avant de vous en servir comme seule protection.
- Ajoutez vos propres contrôles applicatifs : voir [Filtres de modération](/wiki/enterprise/content-safety).

## Claude Code sur Bedrock

```bash
export CLAUDE_CODE_USE_BEDROCK=1
export AWS_REGION=eu-west-3
claude
```

Utilisez Claude Code 2.1.280 ou plus récent pour Opus 5.5 sur Bedrock (2.1.255 pour Fable 5.1). Pour une flotte de postes, distribuez ces variables par réglages gérés. Voir [Claude sur Bedrock, Vertex et Foundry](/wiki/enterprise/clouds).
