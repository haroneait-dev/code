Pour une administration, un hôpital ou une entreprise européenne, la question n'est pas seulement « quel modèle ? » mais « où sont traitées et stockées les données ? ». Cet article fait le point, canal par canal, sur ce que vous pouvez réellement garantir avec Claude en octobre 2026, et sur les engagements contractuels à obtenir.

## Le cadre à respecter

- **RGPD** (UE) : base légale, minimisation, durée de conservation, encadrement des transferts hors UE, analyse d'impact (AIPD) pour les traitements à risque.
- **HIPAA** (santé, États-Unis) : les données de santé identifiables (PHI) exigent un BAA (*Business Associate Agreement*) avec chaque sous-traitant.
- **SOC 2 Type 2** : rapport d'audit indépendant sur l'efficacité des contrôles de sécurité pendant une période donnée.
- **FedRAMP** (secteur public américain) : autorisation obligatoire pour les services cloud utilisés par les agences fédérales.

Anthropic publie ses certifications (rapport SOC 2 Type 2, certificat ISO 27001, etc.) sur son **Trust Center** (`trust.anthropic.com`). Le DPA et, selon l'offre, un BAA se négocient avec l'équipe commerciale.

## Où tourne l'inférence, canal par canal

| Canal | Contrôle de la localisation | Résidence UE possible ? |
|---|---|---|
| API Claude (Anthropic) | Paramètre `inference_geo` : `"global"` (défaut) ou `"us"` | Non : seules les valeurs `us` et `global` existent |
| Amazon Bedrock | Région de l'endpoint ou profil d'inférence | Oui, avec des régions et profils UE |
| Google Cloud Agent Platform (ex-Vertex AI) | Région de l'endpoint | Oui, avec des régions UE |
| Microsoft Foundry | Type de déploiement Azure | Selon le déploiement choisi |
| Claude for Government | Environnement autorisé FedRAMP High | Non concerné (secteur public américain) |

Points clés :

- Sur l'API Claude, `inference_geo: "us"` garantit une inférence aux États-Unis, facturée **1,1 fois** le tarif standard (modèles Claude 4.6 et suivants). La **workspace geo** (stockage au repos) n'existe aujourd'hui qu'en `"us"` et ne se change pas après création.
- Sur Bedrock et Google Cloud, `inference_geo` ne s'applique pas : c'est l'URL de l'endpoint ou le profil d'inférence qui fixe la région.
- Vérifiez toujours la **disponibilité du modèle** dans la région visée : tous les modèles n'arrivent pas en même temps dans toutes les régions.

## Exemple : forcer une inférence UE

Avec le SDK Python, la région se fixe à la création du client. Ne laissez jamais la région à une valeur par défaut implicite.

```python
from anthropic import AnthropicBedrock, AnthropicVertex

# Bedrock, région Paris (vérifiez l'ID du modèle ou du profil UE dans la console AWS)
bedrock = AnthropicBedrock(aws_region="eu-west-3")

# Google Cloud, région Belgique
vertex = AnthropicVertex(region="europe-west1", project_id="mon-projet-ue")
```

Pour Claude Code, le même principe passe par des variables d'environnement :

```bash
# Claude Code sur Bedrock, région UE
export CLAUDE_CODE_USE_BEDROCK=1
export AWS_REGION=eu-west-3

# Ou sur Google Cloud, région UE
export CLAUDE_CODE_USE_VERTEX=1
export CLOUD_ML_REGION=europe-west1
export ANTHROPIC_VERTEX_PROJECT_ID=mon-projet-ue
```

Un administrateur peut verrouiller ce choix avec le réglage géré `allowedProviders` (par exemple `["bedrock"]`), disponible depuis Claude Code v2.1.285 : une session pointée ailleurs est alors refusée.

## Ce qui sort encore du périmètre

Fixer la région d'inférence ne suffit pas. Claude Code envoie aussi du trafic annexe (vérifications de version, télémétrie, rapports d'erreurs) vers Anthropic et des services tiers :

- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` coupe ce trafic non essentiel (et désactive les mises à jour automatiques : prévoyez un autre canal de mise à jour).
- `DISABLE_TELEMETRY`, distribué via les **managed settings**, coupe la télémétrie pour toute l'organisation.
- Si vous utilisez des clés de chiffrement gérées par le client (CMEK) et passez par une gateway ou un `ANTHROPIC_BASE_URL` personnalisé, la CMEK ne couvre pas la télémétrie opérationnelle de Claude Code : désactivez-la.
- Les fonctions liées à claude.ai (sessions cloud, Remote Control, Slack) ne passent pas par votre cloud. Désactivez-les si le flux doit rester chez votre fournisseur.

## Claude for Government (secteur public américain)

Claude for Government est l'offre d'Anthropic pour les agences fédérales, étatiques et locales américaines et certaines organisations publiques éligibles. Elle est **généralement disponible depuis le 30 septembre 2026** et fonctionne dans un environnement **autorisé FedRAMP High**. L'application de bureau Claude for Government donne aussi accès à Claude Code et Cowork dans ce même environnement.

Pour une organisation européenne, ce n'est pas une option de résidence UE. C'est en revanche un bon repère : un hébergement « souverain » se juge sur une autorisation formelle (FedRAMP, ou SecNumCloud en France) et un périmètre isolé, pas sur le seul choix d'une région.

## HIPAA et santé

1. Signez le BAA avec le fournisseur qui traite les PHI (AWS, Google Cloud, Microsoft ou Anthropic selon le canal).
2. N'utilisez que des services et régions couverts par ce BAA.
3. Activez la journalisation (CloudTrail, Cloud Audit Logs, Azure Monitor) et le chiffrement avec vos propres clés.
4. Documentez le flux de PHI dans votre registre et votre analyse de risques.

Côté Anthropic, un BAA peut être conclu pour certaines offres commerciales. Vérifiez avec votre interlocuteur quelles fonctionnalités il couvre : certaines fonctions bêta ou outils serveur peuvent en être exclus.

## Architecture défensive recommandée

```yaml
defense_in_depth:
  reseau:
    - vpc_service_controls        # Google Cloud
    - privatelink                 # AWS
    - filtrage_egress
  donnees:
    - cmek_ou_byok
    - pseudonymisation_des_pii_avant_envoi
    - zero_data_retention_si_eligible
  identite:
    - sso_saml_oidc
    - mfa_obligatoire
    - acces_juste_a_temps
  audit:
    - export_siem
    - journaux_immuables
    - aipd_documentee
```

La pseudonymisation avant l'appel reste la mesure la plus efficace : une donnée qui n'est pas envoyée ne pose aucun problème de résidence.

## Checklist de conformité

1. Le canal et la région d'inférence sont choisis et verrouillés (code, variables, `allowedProviders`).
2. Le modèle visé est disponible dans cette région.
3. DPA signé, BAA si PHI, rapport SOC 2 Type 2 récupéré.
4. Trafic non essentiel et télémétrie désactivés si nécessaire.
5. Les durées de conservation sont documentées (voir [Confidentialité des données](/wiki/enterprise/data-privacy)).
