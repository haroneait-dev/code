Pour rester dans votre gouvernance, votre région et votre facturation cloud, vous pouvez utiliser les [modèles](/wiki/modeles) Claude via **Amazon Bedrock**, **Google Cloud** ou **Microsoft Foundry** plutôt que par l'[API Anthropic](/wiki/api) directe. Claude Code fonctionne avec ces trois fournisseurs, ainsi qu'avec **Claude Platform on AWS**. Cet article résume ce qui change d'un fournisseur à l'autre.

> **Changement de nom.** Google a renommé Vertex AI en **Agent Platform** (« Google Cloud's Agent Platform »). Les variables `CLAUDE_CODE_USE_VERTEX`, les ID de modèles et la configuration ne changent pas ; l'écran de connexion de Claude Code affiche encore « Google Vertex AI ».

## Les quatre options en un coup d'œil

| Fournisseur | Opéré par | Variable d'activation | Facturation |
|---|---|---|---|
| Amazon Bedrock | AWS | `CLAUDE_CODE_USE_BEDROCK=1` | Facture AWS |
| Claude Platform on AWS | Anthropic | `CLAUDE_CODE_USE_ANTHROPIC_AWS=1` + `ANTHROPIC_AWS_WORKSPACE_ID` | AWS Marketplace |
| Google Cloud (Agent Platform) | Google | `CLAUDE_CODE_USE_VERTEX=1` + `CLOUD_ML_REGION` + `ANTHROPIC_VERTEX_PROJECT_ID` | Facture Google Cloud |
| Microsoft Foundry | Anthropic (ressource Azure) | `CLAUDE_CODE_USE_FOUNDRY=1` + `ANTHROPIC_FOUNDRY_RESOURCE` | Azure Marketplace |

**Claude Platform on AWS** est l'API d'Anthropic elle-même, avec une authentification AWS (SigV4 ou clé de workspace) et une facturation via AWS Marketplace. Vous y obtenez les mêmes modèles et fonctions API, au même rythme de sortie. À ne pas confondre avec Bedrock, qui est un service AWS.

## Mise en route rapide

Bedrock et Google Cloud ont un **assistant de connexion** : lancez `claude`, choisissez « 3rd-party platform » puis le fournisseur. Il détecte vos identifiants, vérifie les modèles accessibles et enregistre la configuration dans `~/.claude/settings.json`. Pour le relancer : `/setup-bedrock` ou `/setup-vertex`. Foundry n'a pas d'assistant : tout passe par les variables d'environnement.

Pour un déploiement scripté ou en CI, posez les variables vous-même :

```bash
# Amazon Bedrock
export CLAUDE_CODE_USE_BEDROCK=1
export AWS_REGION=eu-west-3          # sinon la région du profil AWS

# Google Cloud (Agent Platform)
export CLAUDE_CODE_USE_VERTEX=1
export CLOUD_ML_REGION=global        # ou eu, us, europe-west1...
export ANTHROPIC_VERTEX_PROJECT_ID=mon-projet

# Microsoft Foundry
export CLAUDE_CODE_USE_FOUNDRY=1
export ANTHROPIC_FOUNDRY_RESOURCE=ma-ressource   # le nom seul, pas l'URL
```

Vérifiez ensuite avec `/status` : la ligne « API provider » doit afficher le bon fournisseur.

## Les prérequis côté cloud

1. **Accès aux modèles.** Bedrock : formulaire de cas d'usage dans le catalogue de modèles (une fois par compte AWS ; accès immédiat). Google Cloud : activer l'API `aiplatform.googleapis.com` puis demander l'accès dans le Model Garden (jusqu'à 24-48 h). Foundry : créer une ressource et un déploiement par modèle.
2. **Identité et droits.**
   - Bedrock : `bedrock:InvokeModel`, `bedrock:InvokeModelWithResponseStream`, `bedrock:ListInferenceProfiles`, `bedrock:GetInferenceProfile`. Authentification par profil AWS, SSO, clés d'accès ou clé API Bedrock (`AWS_BEARER_TOKEN_BEDROCK`).
   - Google Cloud : rôle `roles/aiplatform.user`. Authentification par Application Default Credentials (`gcloud auth application-default login`) ou compte de service.
   - Foundry : rôles `Azure AI User` ou `Cognitive Services User`. Authentification par clé API, Microsoft Entra ID (`az login`) ou jeton.
3. **Chemin réseau.** VPC, proxy d'entreprise, ou passerelle LLM interne via `ANTHROPIC_BASE_URL` (voir [passerelles API](/wiki/enterprise/api-gateways)).
4. **Garde-fous.** Permissions, sandbox, audit : voir [Workflows & Sécurité](/wiki/workflows).

Conseil de la documentation officielle : dédiez un compte AWS ou un projet Google Cloud à Claude Code pour suivre facilement les coûts et les accès.

## Épingler les versions de modèles

Sans épinglage, les alias `opus` et `sonnet` pointent vers le modèle par défaut de Claude Code pour ce fournisseur, qui peut changer à chaque mise à jour. Sur Bedrock et Google Cloud, `opus` vise aujourd'hui **Opus 5.5** ; sur Foundry, **Opus 4.6**. Pour un déploiement d'équipe, épinglez :

```bash
# Bedrock : ID de profil d'inférence, avec préfixe de région
export ANTHROPIC_DEFAULT_OPUS_MODEL='eu.anthropic.claude-opus-5-5'
export ANTHROPIC_DEFAULT_SONNET_MODEL='eu.anthropic.claude-sonnet-4-6'
export ANTHROPIC_DEFAULT_HAIKU_MODEL='eu.anthropic.claude-haiku-4-5-20251001-v1:0'

# Google Cloud et Foundry : ID sans préfixe (sur Foundry, le nom de votre déploiement)
export ANTHROPIC_DEFAULT_OPUS_MODEL='claude-opus-5-5'
export ANTHROPIC_DEFAULT_SONNET_MODEL='claude-sonnet-5'
```

Les formats d'ID diffèrent :

- **Bedrock** : `anthropic.` précédé d'un préfixe de profil d'inférence (`us.`, `eu.`, `apac.`, `global.`, `us-gov.` en GovCloud). `ANTHROPIC_BEDROCK_REGION_PREFIX` change le préfixe sans épingler. Un ARN de profil d'inférence applicatif est aussi accepté.
- **Claude Platform on AWS** : les mêmes ID que l'API Anthropic (`claude-opus-5-5`), sans préfixe.
- **Google Cloud** : ID sans préfixe, parfois avec une date (`claude-haiku-4-5@20251001`).
- **Foundry** : le nom de déploiement que vous avez choisi dans Azure.

Coût : depuis la version 2.1.207, un déploiement Bedrock ou Google Cloud sans épinglage démarre sur Opus, plus cher que Sonnet. Pour rester sur Sonnet, fixez `ANTHROPIC_MODEL`.

Au démarrage, Bedrock et Google Cloud vérifient que les modèles sont accessibles et basculent sur une version antérieure si besoin. Foundry n'a pas cette vérification : un modèle absent provoque directement des erreurs.

## Contexte de 1 million de tokens

Sur Bedrock et Google Cloud, Sonnet 5 tourne toujours avec 1M de tokens. Pour Opus 4.6 et plus récents ou Sonnet 4.6, ajoutez le suffixe `[1m]` à l'ID épinglé (l'assistant de connexion le propose). Sans ce suffixe, ces modèles compactent la conversation à 200 000 tokens. Détails : [Fenêtre de contexte](/wiki/modeles/contexte-200k).

## Ce qui n'est pas disponible

Le cœur de Claude Code fonctionne partout : CLI, extensions VS Code et JetBrains, sous-agents, hooks, skills, plugins, MCP, checkpoints, sandbox, OpenTelemetry, fichier de réglages gérés. En revanche :

| Fonction | Bedrock | Google Cloud | Foundry | Claude Platform on AWS |
|---|---|---|---|---|
| Fonctions liées à un abonnement claude.ai (sessions cloud, Routines `/schedule`, Remote Control, Ultrareview, extension Chrome) | Non | Non | Non | Non |
| Recherche web (`WebSearch`) | Non | Modèles Claude 4 et plus | Déploiements hébergés par Anthropic | Oui |
| Fast mode, advisor | Non | Non | Non | Non |
| Réglages gérés côté serveur | Non | Non | Non | Non |
| Mode `auto` | Sonnet 5+, Opus 4.7+, Fable | Sonnet 5+, Opus 4.7+, Fable | Sonnet 5+, Opus 4.7+, Fable | Comme l'API Anthropic |

Sur Bedrock, remplacez la recherche web par `WebFetch` avec une URL précise, et `/schedule` par `/loop` ou une [CI GitHub Actions](/wiki/cli/cicd-execution). Le mode `auto` est actif par défaut sur ces fournisseurs ; l'ancienne variable `CLAUDE_CODE_ENABLE_AUTO_MODE` n'a plus d'effet (voir [modes de permission](/wiki/cli/permissions-modes)).

> La matrice évolue vite. Avant un choix d'architecture, vérifiez la page officielle de disponibilité des fonctions (lien en fin d'article).

## Gouvernance : réglages gérés

Distribuez la configuration de façon centralisée avec le **fichier de réglages gérés** (déployé par MDM, plist macOS ou registre Windows). Il prime sur les réglages utilisateur et projet ([hiérarchie settings.json](/wiki/cli/settings-json)). Vous y fixez notamment :

- les variables `env` (fournisseur, région, modèles épinglés) ;
- `availableModels` et `enforceAvailableModels` pour limiter les modèles autorisés ;
- les règles `permissions.deny` et, si besoin, `permissions.disableAutoMode` ;
- un `CLAUDE.md` d'organisation (clé `claudeMd`).

## Observabilité et coûts

- Claude Code exporte des métriques **OpenTelemetry** vers votre outil de supervision (voir [observabilité OTel](/wiki/hooks/observabilite-otel)).
- Sur Bedrock, les **profils d'inférence applicatifs** permettent de suivre les coûts par équipe ou projet ; `modelOverrides` associe chaque version de modèle à un ARN.
- Bedrock propose des niveaux de service (`ANTHROPIC_BEDROCK_SERVICE_TIER` : `default`, `flex`, `priority`) et les garde-fous **Bedrock Guardrails**.
- Les points de terminaison régionaux coûtent 10 % de plus que les points globaux sur Bedrock et Google Cloud.
