En octobre 2026, la gamme compte quatre niveaux : **Haiku 4.5** (rapide et économique), **Sonnet 5.5** (usage courant), **Opus 5.5** (haut de gamme, modèle par défaut de Claude Code) et **Fable 5.1** (frontière). Choisir, c'est arbitrer entre qualité, coût et latence. Voici une méthode simple.

## La question à se poser d'abord

Avant de regarder les benchmarks, demandez-vous : **qu'est-ce que coûte une erreur ?**

- Une erreur se voit tout de suite et se corrige vite → prenez le modèle le moins cher qui fait le travail.
- Une erreur passe inaperçue et coûte cher plus tard (sécurité, données, juridique) → montez d'un cran.

## Haiku 4.5 : le volume

1 $ / 5 $ par million de tokens, 200K de contexte, réponses très rapides.

Pour : classification, extraction, routage, modération, résumés courts, sous-agents d'exploration du code dans Claude Code.

À éviter pour : le code non trivial et les raisonnements en plusieurs étapes.

## Sonnet 5.5 : le travail courant

2 $ / 10 $, 1M de contexte, environ 30 % plus rapide que Sonnet 5.

Pour : le développement de tous les jours (features, corrections, tests), un chatbot produit, la recherche web avec synthèse. C'est le meilleur rapport qualité/prix de la gamme.

À éviter pour : les décisions d'architecture lourdes et les bugs subtils qui résistent.

## Opus 5.5 : quand ça compte

4 $ / 20 $, 1M de contexte, fast mode disponible.

Pour : refactor d'architecture, bug qui résiste, agents autonomes de plusieurs heures, analyse de contrats ou de code sensible. Depuis septembre 2026, il atteint le niveau de Fable 5.1 sur la plupart des tâches.

À éviter pour : ce que Sonnet fait aussi bien. Vous payez deux fois plus cher.

## Fable 5.1 : la frontière

10 $ / 50 $. Pour les problèmes où Opus 5.5 bute vraiment : recherche, preuves, chantiers très longs. Dans la plupart des projets, vous n'en aurez pas besoin.

## Combiner plutôt que choisir

Le schéma le plus rentable :

1. **Haiku** trie la demande (valide ? quel type ?) ;
2. **Sonnet** traite la majorité des cas ;
3. **Opus** ne prend la main que sur les cas signalés comme complexes ou à risque.

Dans Claude Code, l'équivalent est **Sonnet 5.5 + [advisor](/wiki/cli/effort-fast-advisor) Opus** : Sonnet fait le travail, Opus intervient aux moments de décision.

## Exemples

| Tâche | Modèle |
|---|---|
| Classer 10 000 tickets par jour | Haiku 4.5 |
| Chatbot produit pour vos utilisateurs | Sonnet 5.5 |
| Développement dans Claude Code | Sonnet 5.5 (+ advisor Opus) ou Opus 5.5 |
| Agent autonome de refactoring | Opus 5.5 en effort `high` |
| Résumé d'e-mails | Haiku 4.5 |
| Analyse juridique d'un contrat | Opus 5.5 |
| Recherche web et synthèse | Sonnet 5.5 |
| Modération de commentaires | Haiku 4.5 |

## Avant de changer de modèle, changez l'effort

Sur Sonnet 5.5 et Opus 5.5, l'effort par défaut est `medium`. Une réponse trop superficielle se corrige souvent en passant en `high`, pour bien moins cher qu'un changement de modèle. Voir [Effort, fast mode et advisor](/wiki/cli/effort-fast-advisor).
