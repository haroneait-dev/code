Avec la réflexion (*thinking*), Claude travaille le problème dans des blocs `thinking` avant d'écrire sa réponse. La qualité augmente sur le code, le débogage, les maths et les tâches agentiques longues, au prix de tokens de sortie supplémentaires. Le mécanisme dépend du modèle : c'est la première chose à vérifier.

## Le mode dépend du modèle

| Modèle | Sans champ `thinking` | `adaptive` | `enabled` + `budget_tokens` | `disabled` |
|---|---|---|---|---|
| Opus 5.5, Fable 5.1, Mythos 5.1 | Adaptatif (toujours actif) | Oui | 400 | 400 |
| Sonnet 5.5 | Adaptatif | Oui | 400 | 400 (utiliser `between_tools`) |
| Opus 5 | Adaptatif | Oui | 400 | Oui jusqu'à `high`, 400 en `xhigh` et `max` |
| Sonnet 5 | Adaptatif | Oui | 400 | Oui |
| Opus 4.8, Opus 4.7 | Pas de réflexion | Oui | 400 | Oui |
| Opus 4.6, Sonnet 4.6 | Pas de réflexion | Oui (recommandé) | Déprécié mais accepté | Oui |
| Haiku 4.5, Sonnet 4.5, Opus 4.5 | Pas de réflexion | 400 | Oui (seul mode) | Oui |

Deux familles :

- **Réflexion adaptative** (`type: "adaptive"`) : Claude décide quand et combien réfléchir. Vous orientez avec `output_config.effort`. Voir [Raisonnement adaptatif et effort](/wiki/modeles/adaptive-thinking-effort).
- **Réflexion manuelle** (`type: "enabled"`) : vous fixez `budget_tokens` (minimum 1 024, inférieur à `max_tokens`). Réservée aux modèles qui n'ont pas le mode adaptatif.

Sur Sonnet 5.5, le réglage le plus bas est `thinking: {"type": "between_tools"}` : pas de réflexion avant la réponse, mais des notes de progression entre les appels d'outils. Il n'est accepté qu'avec un effort `high` ou inférieur.

```javascript
// Opus 4.8 : la réflexion est coupée par défaut, il faut l'activer
const res = await client.messages.create({
  model: "claude-opus-4-8",
  max_tokens: 32000,
  thinking: { type: "adaptive", display: "summarized" },
  output_config: { effort: "xhigh" },
  messages: [{ role: "user", content: "Démontre que..." }],
});

// Opus 5.5 : rien à activer, la réflexion est toujours là
const res2 = await client.messages.create({
  model: "claude-opus-5-5",
  max_tokens: 32000,
  output_config: { effort: "high" },
  messages: [{ role: "user", content: "Démontre que..." }],
});
```

## Afficher ou masquer la réflexion (`display`)

Le texte d'un bloc `thinking` n'est jamais la réflexion brute : c'est un **résumé** produit par un autre modèle. Le champ `display` contrôle ce que vous recevez :

| Valeur | Contenu du bloc | Défaut sur |
|---|---|---|
| `"summarized"` | Résumé lisible | Opus 4.6, Sonnet 4.6 et modèles plus anciens |
| `"omitted"` | Champ `thinking` vide, seule la `signature` est présente | Opus 4.7 et suivants, Sonnet 5, Sonnet 5.5, Fable, Mythos |
| `"updates"` (bêta) | Seules les notes de progression entre outils sont lisibles | Sur demande, en-tête `thinking-display-updates-2026-08-18` |

Si votre interface montre la réflexion à l'utilisateur, passez explicitement `display: "summarized"`. Sinon, le défaut `"omitted"` a un avantage : le texte de la réponse commence à arriver plus tôt en streaming.

Sur Opus 5.5, Sonnet 5.5 et Fable 5.1, demander au modèle de recopier son raisonnement interne dans la réponse peut déclencher un refus de catégorie `reasoning_extraction`. Lisez les blocs `thinking` plutôt.

## Coût : la réflexion est facturée comme de la sortie

- Les tokens de réflexion sont facturés au tarif de sortie, **même en mode `omitted`**. Vous payez la réflexion complète, pas le résumé.
- Le détail est dans `usage.output_tokens_details.thinking_tokens` (en streaming, uniquement dans le dernier événement `message_delta`).
- La réflexion compte dans `max_tokens`. Un `max_tokens` dimensionné pour une réponse sans réflexion est souvent trop petit.

```python
print(response.usage.output_tokens)                         # total facturé
print(response.usage.output_tokens_details.thinking_tokens) # dont réflexion
```

## Limites de sortie

| Modèle | Sortie max (API synchrone) |
|---|---|
| Fable 5.1, Opus 5.5, Sonnet 5.5, Opus 5, Sonnet 5, Opus 4.x récents | 128K tokens |
| Haiku 4.5 | 64K tokens |

Sur l'[API Batch](/wiki/api/batch-api), l'en-tête bêta `output-300k-2026-03-24` porte la limite à 300K pour Opus 5.5, Opus 5, Sonnet 5.5, Sonnet 5, Opus 4.8, 4.7, 4.6 et Sonnet 4.6. Au-delà d'environ 16K tokens de sortie, streamez la réponse pour éviter les timeouts HTTP.

## Réflexion, outils et conversations multi-tours

- **Réflexion entrelacée** : automatique en mode adaptatif, sans en-tête bêta. Haiku 4.5 ne la prend pas en charge.
- **Renvoyez les blocs `thinking` sans les modifier**, surtout pendant une boucle d'outils. Un bloc modifié provoque une erreur 400.
- **Conservation des blocs** : Opus 4.5 et les modèles 4.6 et suivants gardent les blocs des tours précédents dans le contexte (facturés en entrée). Les modèles plus anciens, Haiku 4.5 compris, ne gardent que le dernier tour.
- **Outil forcé** : avec la réflexion manuelle, seul `tool_choice` `auto` ou `none` est accepté. Opus 5.5, Sonnet 5.5, Fable 5.1 et Mythos 5.1 refusent aussi `any` et `tool`.

## Cache de prompt

La configuration de réflexion et l'effort sont inscrits dans le prompt. Changer de mode, de `budget_tokens` ou d'effort entre deux requêtes invalide le cache. Choisissez un réglage par conversation et gardez-le. Voir [Prompt caching](/wiki/api/prompt-caching-implementation).

## Erreurs fréquentes

| Erreur | Cause | Correction |
|---|---|---|
| 400 `"thinking.type.enabled" is not supported` | `budget_tokens` sur Opus 4.7 ou plus récent | Passer à `adaptive` + `effort` |
| 400 sur `thinking: {"type": "disabled"}` | Opus 5.5, Fable, ou Sonnet 5.5 | Baisser l'effort, ou `between_tools` sur Sonnet 5.5 |
| Blocs `thinking` vides | `display: "omitted"` par défaut | Ajouter `display: "summarized"` |
| `stop_reason: "max_tokens"` fréquent | Réflexion longue en `high` et au-dessus | Monter `max_tokens` (64K en `xhigh`) ou baisser l'effort |
| Cache qui ne fonctionne plus | Effort ou mode changé entre deux requêtes | Garder la même configuration |
