Sur les modèles Claude récents, vous ne fixez plus un budget de réflexion en tokens. Le modèle décide lui-même s'il doit réfléchir et combien, et vous orientez ce choix avec un seul paramètre : `effort`. Cette page explique les deux mécanismes et la migration depuis l'ancien `budget_tokens`.

## Le raisonnement adaptatif

Avec le raisonnement adaptatif (`thinking: {"type": "adaptive"}`), Claude évalue chaque requête. Une question factuelle simple peut recevoir une réponse directe, sans bloc de réflexion. Un bug subtil ou une démonstration déclenchent une réflexion plus longue. Ce choix se fait requête par requête : dans une même conversation, certains tours ont un bloc `thinking`, d'autres non.

Le raisonnement adaptatif active aussi automatiquement la **réflexion entrelacée** : Claude peut réfléchir entre deux appels d'outils, après avoir lu un résultat, sans en-tête bêta. C'est ce qui rend les boucles agentiques fiables.

Selon le modèle, le comportement par défaut change :

| Modèle | Sans champ `thinking` | Couper la réflexion |
|---|---|---|
| Opus 5.5, Fable 5.1, Mythos 5.1 | Adaptatif, toujours actif | Impossible (`disabled` renvoie 400) |
| Sonnet 5.5 | Adaptatif | `{"type": "between_tools"}`, jusqu'à l'effort `high` |
| Opus 5 | Adaptatif | `{"type": "disabled"}`, sauf en `xhigh` et `max` |
| Sonnet 5 | Adaptatif | `{"type": "disabled"}` |
| Opus 4.8, 4.7, 4.6, Sonnet 4.6 | Pas de réflexion | Il faut activer `{"type": "adaptive"}` |
| Haiku 4.5 | Pas de réflexion | Réflexion manuelle uniquement (`budget_tokens`) |

## Le paramètre effort

`effort` se place dans `output_config`, pas dans l'objet `thinking`. C'est un **signal de comportement, pas un budget strict**. Il agit sur tous les tokens de sortie : réflexion, texte, appels d'outils. Un effort bas donne moins d'appels d'outils, plus courts, et des réponses plus directes.

| Niveau | Comportement | Usage typique |
|---|---|---|
| `low` | Réfléchit le moins possible, saute la réflexion sur les cas simples | Sous-agents, classification, chat rapide |
| `medium` | Réflexion modérée. **Défaut d'Opus 5.5** | Tâches agentiques bien cadrées |
| `high` | Réfléchit dès que c'est utile. **Défaut des autres modèles** | Raisonnement complexe, code difficile |
| `xhigh` | Plus profond que `high` | Code et agents sur de longues durées (30 min et plus) |
| `max` | Aucune limite de dépense | Problèmes de pointe, après mesure |

Disponibilité : `max` existe sur Fable, Mythos, Opus 4.6 et suivants, Sonnet 4.6 et suivants. `xhigh` existe sur Fable, Mythos, Opus 4.7 et suivants, Sonnet 5 et Sonnet 5.5. Haiku 4.5 ne prend pas en charge `effort`. Sur Sonnet 5.5, les niveaux ont été recalibrés : `high` ne produit pas la même quantité de réflexion que `high` sur Sonnet 5.

```python
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=32000,                     # plafond dur : réflexion + réponse
    output_config={"effort": "high"},     # défaut d'Opus 5.5 : medium
    messages=[{"role": "user", "content": "Trouve la cause de ce deadlock : ..."}],
)

print(response.usage.output_tokens)
print(response.usage.output_tokens_details.thinking_tokens)
```

> Dans Claude Code, l'effort se règle avec `/effort` et l'outil applique ses propres défauts et niveaux supplémentaires (`auto`, `ultracode`). Voir [Effort, fast mode et advisor](/wiki/cli/effort-fast-advisor).

### Changer d'effort en cours de conversation

Changer `effort` au niveau de la requête invalide le cache de prompt, car la valeur est inscrite dans le prompt. Sur Opus 5.5, Opus 5, Sonnet 5.5, Fable 5.1 et Mythos 5.1, une bêta (`mid-conversation-output-config-2026-07-01`) permet de changer l'effort par message, avec un message `role: "system"` vide qui porte `output_config`. Le cache est alors préservé.

## Les task budgets (bêta)

Un task budget donne au modèle une enveloppe de tokens pour **toute une boucle agentique** (réflexion, appels d'outils, résultats, réponse). Claude voit un compte à rebours et s'organise pour finir proprement.

```python
response = client.beta.messages.create(
    model="claude-opus-5-5",
    max_tokens=128000,
    output_config={
        "effort": "high",
        "task_budget": {"type": "tokens", "total": 64000},
    },
    messages=[{"role": "user", "content": "Audite ce dépôt et propose un plan de refactor."}],
    betas=["task-budgets-2026-03-13"],
)
```

Points clés : minimum 20 000 tokens, indicatif et non bloquant (`max_tokens` reste le plafond dur), non pris en charge sur Sonnet 5, Opus 4.6, Sonnet 4.6 et Haiku 4.5, ni dans Claude Code. Un budget trop petit peut pousser Claude à refuser ou à bâcler la tâche.

## Migrer depuis budget_tokens

`thinking: {"type": "enabled", "budget_tokens": N}` est déprécié sur Opus 4.6 et Sonnet 4.6, et renvoie une erreur 400 sur tous les modèles à partir d'Opus 4.7.

```python
# Avant (400 sur Opus 4.7 et suivants)
thinking = {"type": "enabled", "budget_tokens": 32000}

# Après
thinking = {"type": "adaptive"}          # inutile sur les modèles 5.x : c'est le défaut
output_config = {"effort": "high"}
```

Correspondance indicative, à valider sur vos evals :

| Ancien budget | Effort de départ |
|---|---|
| Moins de 4 000 tokens | `low` ou `medium` |
| 8 000 à 32 000 tokens | `high` |
| Plus de 32 000 tokens | `xhigh` (puis `max` si mesuré) |

À vérifier en même temps : retirer `temperature`, `top_p`, `top_k` non par défaut (400 depuis Opus 4.7), retirer l'en-tête `interleaved-thinking-2025-05-14` (inutile), et recompter vos tokens (le tokenizer introduit avec Opus 4.7 produit environ 30 % de tokens en plus).

## Bonnes pratiques

1. **Partez du défaut, puis mesurez.** Lancez un balayage d'effort sur vos propres evals à chaque changement de modèle, plutôt que de reprendre l'ancien réglage.
2. **Baissez l'effort avant de toucher au prompt.** C'est un levier calibré. Les consignes du type « réfléchis longuement » sont moins fiables.
3. **Prévoyez un `max_tokens` large.** La réflexion compte dans `max_tokens`. En `xhigh` ou `max`, partez de 64 000. Si vous voyez `stop_reason: "max_tokens"`, montez le plafond ou baissez l'effort.
4. **Surveillez `usage.output_tokens_details.thinking_tokens`.** Les tokens de réflexion sont facturés comme de la sortie, même quand le texte n'est pas renvoyé.
