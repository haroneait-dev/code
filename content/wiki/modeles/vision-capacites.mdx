Tous les modèles Claude actuels lisent les images : captures d'écran, maquettes, schémas, graphiques, documents scannés. Depuis Opus 4.7, les modèles récents les traitent en **haute résolution**, ce qui change la précision et le coût. Voici l'essentiel pour bien s'en servir.

## Envoyer une image

En API, une image est un bloc de contenu `image` avec trois sources possibles :

1. `base64` : l'image encodée dans la requête ;
2. `url` : une image en ligne ;
3. `file` : un `file_id` obtenu via la [Files API](/wiki/api/files-api), à privilégier quand l'image revient dans plusieurs tours.

Sur Amazon Bedrock et Google Cloud, seule la source `base64` est disponible.

```python
import anthropic

client = anthropic.Anthropic()

message = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=2048,
    messages=[{
        "role": "user",
        "content": [
            {"type": "image", "source": {"type": "url", "url": "https://exemple.fr/maquette.png"}},
            {"type": "text", "text": "Liste les composants de cette maquette et propose une structure React."},
        ],
    }],
)
print(message.content[0].text)
```

Placez de préférence l'image **avant** la question. Pour plusieurs images, précédez chacune d'une étiquette (`Image 1 :`, `Image 2 :`) pour pouvoir les citer.

## Formats et limites

| Élément | Limite |
|---|---|
| Formats | JPEG, PNG, GIF, WebP (pour un GIF animé, seule la première image est lue) |
| Taille par image | 10 Mo en API directe, 5 Mo sur Bedrock et Google Cloud |
| Dimensions max | 8000 x 8000 px |
| Images par requête | 600 (100 pour les modèles à 200K de contexte, comme Haiku 4.5) |
| Images par message sur claude.ai | 20 |
| Taille totale de requête | 32 Mo (moins sur certaines plateformes partenaires) |

Au-delà de 20 images dans une requête, une limite de dimension plus stricte s'applique à chaque image. Le plus simple : redimensionner à 2000 px maximum par côté, ou rester à 20 images.

## Résolution et coût

Claude découpe l'image en carrés de 28 x 28 pixels. Chaque carré est un token visuel : une image coûte `⌈largeur / 28⌉ x ⌈hauteur / 28⌉` tokens, au prix des tokens d'entrée du modèle.

| Niveau | Modèles | Bord long max | Tokens max par image |
|---|---|---|---|
| Haute résolution | Opus 4.7 et suivants (Opus 5.5, Sonnet 5, Sonnet 5.5, Fable...) | 2576 px | 4784 |
| Standard | Haiku 4.5 et modèles plus anciens | 1568 px | 1568 |

Quelques exemples tirés de la documentation :

| Image | Standard | Haute résolution |
|---|---|---|
| 1000 x 1000 px | 1296 tokens | 1296 tokens |
| 1920 x 1080 px | réduite à 1456 x 819, 1560 tokens | non réduite, 2691 tokens |
| 3840 x 2160 px (4K) | 1560 tokens | réduite à 2576 x 1449, 4784 tokens |

Une image trop grande est réduite automatiquement en gardant ses proportions. En haute résolution, une même image peut coûter jusqu'à environ trois fois plus de tokens. Si vous n'avez pas besoin du détail (photo d'ambiance, illustration), réduisez l'image avant l'envoi. Gardez la pleine résolution pour les captures d'écran denses, les documents et le computer use.

## Ce que Claude fait bien

- **Lecture de texte** : texte imprimé, tableaux, documents scannés, avec restitution de la structure (Markdown, JSON).
- **Schémas et diagrammes** : architecture, UML, organigrammes, graphiques. Claude identifie les éléments et la logique, et peut transcrire un schéma en Mermaid.
- **Graphiques** : tendances et ordres de grandeur. Pour des valeurs exactes, joignez les données brutes.
- **Interfaces** : maquette vers composant, audit de hiérarchie visuelle et de contraste, comparaison maquette / rendu réel.

Pour un PDF, envoyez plutôt le document lui-même (bloc `document`) : Claude lit alors le texte et les pages en image.

## Limites connues

D'après la documentation officielle :

- **Identification de personnes** : Claude refuse de nommer des personnes sur une image.
- **Images petites ou de mauvaise qualité** : erreurs possibles sous 200 px, sur une image floue ou tournée.
- **Raisonnement spatial et coordonnées** : approximatifs. Pour des boîtes englobantes, suivez le guide « Coordinates and bounding boxes » et vérifiez les résultats.
- **Comptage** : approximatif sur de nombreux petits objets.
- **Images générées par IA** : Claude ne sait pas les détecter de façon fiable.
- **Imagerie médicale** : pas conçu pour interpréter scanners ou IRM.
- **Pas de génération d'image** : Claude lit, mais ne crée ni ne modifie d'images.
- **Métadonnées** : Claude ne reçoit pas les métadonnées EXIF.

## Bonnes pratiques

1. Recadrez sur la zone utile plutôt que d'envoyer un écran entier.
2. Évitez la compression JPEG forte sur du texte : les artefacts gênent la lecture.
3. Pour un document long, envoyez le PDF ou une page par image, avec une question précise.
4. Dans une conversation longue, utilisez la Files API pour éviter de renvoyer les octets à chaque tour.
5. Vérifiez toujours les extractions sensibles (montants, identifiants) par un contrôle côté code.
