Claude Haiku 4.5 (`claude-haiku-4-5-20251001`) est le plus rapide et le moins cher des modèles Claude actuels. Il reste le petit modèle de la gamme en octobre 2026 : Haiku 5.5 est annoncé, mais pas encore sorti. On l'utilise pour le volume : classification, extraction, routage, sous-agents d'exploration.

## Fiche technique

| | Haiku 4.5 |
|---|---|
| ID API | `claude-haiku-4-5-20251001` (alias `claude-haiku-4-5`) |
| Bedrock / Google Cloud | `anthropic.claude-haiku-4-5` / `claude-haiku-4-5@20251001` |
| Sortie | 15 octobre 2025 |
| Prix (par million de tokens) | 1 $ en entrée, 5 $ en sortie |
| Cache | 1,25 $ en écriture (5 min), 0,10 $ en lecture |
| API Batch | 0,50 $ / 2,50 $ |
| Contexte | 200K tokens |
| Sortie max | 64K tokens |
| Réflexion | Manuelle (`budget_tokens`), pas de raisonnement adaptatif |
| Paramètre `effort` | Non pris en charge |
| Connaissances fiables | jusqu'à février 2025 |
| Entrées | Texte et images |

**Cycle de vie.** La page officielle indique un retrait « pas avant le 15 octobre 2026 ». Aucune dépréciation n'est annoncée à ce jour, mais surveillez la page [Model deprecations](https://platform.claude.com/docs/en/about-claude/model-deprecations) : Anthropic prévient au moins 60 jours avant un retrait.

## Cas d'usage

1. **Classification** : intention d'un message, catégorie de ticket, tri de support.
2. **Extraction structurée** : entités, champs de facture, données d'un e-mail.
3. **Pré-filtre de modération** devant un modèle plus cher.
4. **Résumés courts** : e-mails, transcriptions, notes.
5. **Routage** : décider quel modèle ou quel sous-agent traite la suite.
6. **Sous-agents d'exploration** dans Claude Code (recherche de fichiers, lecture rapide).

## Exemple : extraction JSON

```ts
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();

const res = await client.messages.create({
  model: "claude-haiku-4-5-20251001",
  max_tokens: 300,
  system:
    "Extrais nom, téléphone et e-mail. Réponds uniquement avec un objet JSON " +
    '{"nom": string|null, "telephone": string|null, "email": string|null}.',
  messages: [
    { role: "user", content: "Bonjour, je suis Sophie, +33 6 12 34 56 78, sophie@acme.fr" },
  ],
});

const text = res.content.find((b) => b.type === "text")?.text ?? "{}";
console.log(JSON.parse(text));
```

Pour un JSON garanti conforme au schéma, préférez les sorties structurées (`output_config.format`) quand votre plateforme les propose, plutôt que de compter sur la consigne seule. Sinon, validez le JSON côté code.

## Exemple : routeur d'intention

```python
from anthropic import Anthropic

client = Anthropic()
CATEGORIES = {"facturation", "technique", "commercial"}

def route(message: str) -> str:
    msg = client.messages.create(
        model="claude-haiku-4-5-20251001",
        max_tokens=10,
        system="Réponds par un seul mot parmi : facturation, technique, commercial.",
        messages=[{"role": "user", "content": message}],
    )
    label = msg.content[0].text.strip().lower()
    return label if label in CATEGORIES else "technique"  # repli sûr
```

## Le pattern « Haiku devant, Sonnet derrière »

```text
requête entrante
  -> Haiku 4.5 : classe la demande et vérifie qu'elle est complète
  -> simple    : Haiku répond directement
  -> complexe  : Sonnet 5.5 (ou Opus 5.5) prend le relais
```

Sonnet 5.5 coûte deux fois plus cher par token (2 $ / 10 $) et produit plus de tokens pour le même texte (tokenizer plus récent). Envoyer les cas simples à Haiku réduit donc nettement la facture, à condition de mesurer que la qualité tient sur vos données.

## Réflexion étendue sur Haiku

Haiku 4.5 ne connaît que la réflexion manuelle :

```python
response = client.messages.create(
    model="claude-haiku-4-5-20251001",
    max_tokens=8000,
    thinking={"type": "enabled", "budget_tokens": 4000},  # minimum 1024, inférieur à max_tokens
    messages=[{"role": "user", "content": "Vérifie la cohérence de ce planning : ..."}],
)
```

`thinking: {"type": "adaptive"}` et `output_config.effort` renvoient une erreur sur ce modèle. Haiku 4.5 ne fait pas non plus de réflexion entrelacée entre les appels d'outils.

## Limites

- **Raisonnement multi-étapes** : il peut sauter des étapes. Au-delà d'une logique simple, passez à Sonnet 5.5.
- **Code long ou architecture** : la qualité baisse vite par rapport à Sonnet et Opus.
- **Contexte de 200K** : pour un gros dépôt ou un long corpus, les modèles 5.x offrent 1M.
- **Connaissances arrêtées début 2025** : ne lui demandez pas l'état actuel d'une bibliothèque.

## Bonnes pratiques

- Donnez 2 à 5 exemples (few-shot) : Haiku y est très sensible.
- Imposez un format strict (sorties structurées, balises XML).
- Gardez `max_tokens` bas pour les réponses courtes.
- Mettez en cache vos longs prompts système. Attention : sur Haiku 4.5, le préfixe minimal pour le cache est de **4 096 tokens**. En dessous, `cache_control` n'a aucun effet.

```ts
const res = await client.messages.create({
  model: "claude-haiku-4-5-20251001",
  max_tokens: 100,
  system: [
    { type: "text", text: longSystemPrompt, cache_control: { type: "ephemeral" } },
  ],
  messages: [{ role: "user", content: userQuery }],
});
```
