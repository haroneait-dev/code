Un skill isolé rend service. Plusieurs skills bien découpés font de Claude Code un assistant adapté à votre stack. Encore faut-il savoir lequel s'exécute quand deux portent le même nom, comment les enchaîner et ce que coûte leur accumulation. Cette page s'appuie uniquement sur le comportement documenté.

## Comment Claude choisit un skill

Il n'y a ni score de pertinence publié ni règle « premier trouvé ». À chaque tour, Claude voit la **liste des noms et descriptions** des skills qu'il peut invoquer, et décide lui-même s'il en charge un, comme il choisit un outil. Conséquences :

- deux skills aux descriptions proches se font concurrence : Claude peut hésiter ou choisir le mauvais ;
- le champ `paths` réduit un skill aux fichiers concernés, ce qui limite les chevauchements ;
- `disable-model-invocation: true` retire un skill de la liste vue par Claude.

Vous pouvez aussi forcer le choix en tapant `/nom`.

## Même nom à plusieurs endroits

| Même nom dans | Ce qui s'exécute |
|---|---|
| Entreprise, personnel et projet | Entreprise avant personnel, personnel avant projet |
| Un de ces emplacements et un skill intégré | Votre skill remplace la commande intégrée (mais pas ses alias) |
| Un skill et un fichier `.claude/commands/` | Le skill |
| Racine du dépôt et sous-dossier (skill imbriqué) | Les deux restent disponibles : `/deploy` et `/apps/web:deploy` |
| Un skill de plugin et un skill local | Les deux, car le plugin est préfixé : `/mon-plugin:deploy` |
| Un skill synchronisé depuis claude.ai et un autre | L'autre ; le skill synchronisé reste accessible via `/anthropic-skills:<nom>` |

Attention au sens : un skill **personnel** l'emporte sur un skill **de projet** du même nom. Si un collègue a un `~/.claude/skills/deploy`, il n'exécute pas le `/deploy` de l'équipe. Pour un skill d'équipe critique, choisissez un nom distinctif ou distribuez-le en plugin.

Le format standard de `name` (minuscules, chiffres et tirets) exclut les barres obliques comme `acme/deploy`. Pour un espace de noms, utilisez un plugin (préfixe automatique) ou un préfixe dans le nom (`acme-deploy`).

## Enchaîner des skills

### Empiler à l'invocation

Vous pouvez charger plusieurs skills dans un même message :

```text
/ecrire-tests /corriger-issue 123
```

Les deux skills sont chargés et reçoivent `123` comme `$ARGUMENTS`. Claude Code développe le premier skill et jusqu'à cinq autres. L'empilement s'arrête au premier élément qui n'est pas un skill exécuté en ligne : un skill en `context: fork` comme `/code-review` termine la chaîne.

### Renvoyer d'un skill à l'autre

Dans le corps d'un skill orchestrateur, nommez explicitement les skills suivants :

```markdown
---
name: preparer-release
description: Prépare une release (version, changelog, tag). À utiliser quand l'utilisateur annonce une nouvelle version.
disable-model-invocation: true
---

1. Incrémentez la version dans `package.json` selon SemVer.
2. Invoquez ensuite le skill `rediger-changelog` pour générer les notes.
3. Une fois le changelog validé par l'utilisateur, invoquez `creer-tag`.
```

Claude suit ces instructions avec jugement. Si une étape doit **toujours** avoir lieu (un contrôle avant chaque commit, par exemple), mettez-la dans un hook, éventuellement déclaré dans le `hooks` du skill.

### Précharger des skills dans un subagent

Un subagent peut recevoir le contenu complet de skills dès son démarrage, via son champ `skills` :

```yaml
---
name: dev-api
description: Implémente des endpoints selon les conventions de l'équipe
skills:
  - conventions-api
  - gestion-erreurs
---

Implémentez l'endpoint demandé en suivant les conventions préchargées.
```

Un skill en `disable-model-invocation: true` ne peut pas être préchargé. L'inverse existe aussi : un skill en `context: fork` s'exécute dans un subagent choisi par `agent`.

## Découper : atomique ou orchestrateur

- **Skills de référence** (conventions, glossaire métier) : courts, déclenchés par Claude, idéalement limités par `paths`.
- **Skills de tâche** (déploiement, release) : invoqués par vous, souvent en `disable-model-invocation: true`.
- **Un orchestrateur** léger qui renvoie vers les skills de tâche plutôt que de tout dupliquer.

Le partage de fichiers entre skills se fait par le plugin : `${CLAUDE_PLUGIN_ROOT}` pointe vers sa racine, accessible à tous ses skills.

## Le coût de l'accumulation

Chaque skill que Claude peut invoquer ajoute son nom et sa description au contexte **à chaque tour**. La liste a un budget d'environ 1 % de la fenêtre de contexte. Au-delà, Claude Code supprime d'abord les descriptions des skills les moins utilisés, et Claude ne peut plus les choisir correctement.

Outils pour garder la maîtrise :

- `/skill-doctor` : coût et fréquence d'usage de chaque skill ;
- `/doctor` : estimation du coût total de la liste ;
- `skillOverrides` : `"name-only"` pour les skills secondaires, `"off"` pour ceux à masquer ;
- `skillListingBudgetFraction` pour élever le budget si vraiment nécessaire.

Après une compaction, Claude Code ne réattache que les 5 000 premiers tokens de chaque skill invoqué, dans un budget total de 25 000 tokens, en partant du plus récent. Avec beaucoup de skills invoqués, les plus anciens peuvent disparaître : invoquez-les de nouveau si besoin.
