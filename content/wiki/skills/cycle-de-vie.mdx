Un skill n'est pas un processus : c'est du texte que Claude Code place dans la conversation au bon moment. Comprendre quand il entre dans le contexte, combien de temps il y reste et ce qui le fait disparaître permet d'écrire des skills plus fiables et moins coûteux.

## 1. Découverte au démarrage

Au lancement, Claude Code lit les skills des emplacements entreprise, personnel, projet (et dossiers parents jusqu'à la racine du dépôt), des plugins activés et, si vous êtes connecté avec claude.ai, des skills synchronisés. Les skills de sous-dossiers (`apps/web/.claude/skills/`) se chargent plus tard, la première fois que Claude lit ou modifie un fichier dans ce sous-dossier.

Seuls le **nom** et la **description** de chaque skill entrent alors dans le contexte, et uniquement pour les skills que Claude peut invoquer. Côté plateforme, Anthropic estime ce coût à une centaine de tokens par skill.

## 2. Invocation

Deux chemins mènent au même résultat :

- **vous** tapez `/nom-du-skill` (sauf si `user-invocable: false`) ;
- **Claude** juge que votre demande correspond à la description et appelle l'outil Skill (sauf si `disable-model-invocation: true`, ou si le champ `paths` exclut les fichiers en cours).

À ce moment, Claude Code **rend** le skill :

1. substitution des arguments (`$ARGUMENTS`, `$0`, `$nom`) et des variables (`${CLAUDE_SKILL_DIR}`, `${CLAUDE_SESSION_ID}`…) ;
2. exécution des commandes injectées `` !`commande` `` et des blocs ` ```! ` : leur sortie remplace la ligne ;
3. application des `allowed-tools` (pré-autorisation), `disallowed-tools`, `model` et `effort` pour ce tour ;
4. enregistrement des `hooks` déclarés dans le frontmatter.

Si une commande injectée échoue (code de sortie non nul) ou est refusée par vos règles de permission, **toute l'invocation est annulée** : Claude ne voit pas le skill. Ajoutez `|| true` aux commandes qui peuvent légitimement renvoyer une erreur.

Avec `context: fork`, le contenu rendu devient le prompt d'un subagent séparé, en arrière-plan par défaut. Le reste de cet article concerne les skills exécutés dans la conversation principale.

## 3. Pendant la conversation

Le contenu rendu entre dans la conversation sous forme d'**un seul message** et y reste pour les tours suivants. Points importants :

- Claude Code **ne relit pas** le fichier aux tours suivants. Écrivez donc des consignes valables pour toute la tâche (« Lancez les tests après chaque modification ») plutôt que des étapes ponctuelles.
- Si Claude réinvoque le skill avec un rendu identique, Claude Code ajoute seulement une note indiquant qu'il est déjà chargé. Si le rendu diffère (autres arguments, sortie de commande différente), le contenu complet est ajouté de nouveau.
- Les **permissions** ne persistent pas : la pré-autorisation `allowed-tools` tombe dès votre message suivant. La réinvoquer la réapplique.
- Les **hooks** du skill, eux, restent actifs jusqu'à la fin de la session (sauf `once: true`).
- Le `model` et l'`effort` du skill ne valent que pour le tour : le modèle de la session reprend au prompt suivant.

Si vous modifiez `SKILL.md` en cours de session, la nouvelle version est détectée, mais la copie déjà présente dans la conversation ne change pas : réinvoquez le skill.

## 4. Compaction

Il n'y a pas de « libération » manuelle d'un skill. Le contenu reste jusqu'à ce que la conversation soit compactée (automatiquement ou avec `/compact`) ou effacée (`/clear`).

Lors de l'auto-compaction, Claude Code réattache après le résumé la dernière invocation de chaque skill, **limitée à ses 5 000 premiers tokens**, dans un budget total de **25 000 tokens** rempli à partir du skill le plus récent. Conséquences :

- placez les consignes essentielles **en haut** de `SKILL.md` ;
- avec beaucoup de skills invoqués, les plus anciens peuvent être perdus ;
- si Claude cesse de suivre un skill après une compaction, invoquez-le de nouveau.

## 5. Fin de session et nettoyage

À la fin de la session, rien ne reste en mémoire. Les seules traces sont les effets de bord produits par Claude ou par les scripts : fichiers temporaires, processus lancés en arrière-plan, branches Git. Si votre skill en crée, prévoyez une section explicite :

```markdown
## Nettoyage

Une fois la tâche terminée :
- supprimez le dossier `tmp/rapport-${CLAUDE_SESSION_ID}/` ;
- arrêtez le serveur de prévisualisation que vous avez lancé.
```

Pour un nettoyage garanti plutôt qu'au jugement de Claude, utilisez un hook `SessionEnd` ou `Stop`.

## Observer le cycle de vie

- `/skills` : skills chargés, source et nombre de tokens (touche `t`) ;
- `/context` : poids de la liste des skills dans le contexte ;
- `claude --debug` ou `/debug` : erreurs de parsing YAML et avertissements de budget ;
- `/skill-doctor` : coût et fréquence d'usage de chaque skill ;
- `/status` : skills dont l'`allowed-tools` a été ignoré par une politique d'entreprise.
