Publier un skill, c'est le rendre installable par d'autres avec des mises à jour. Dans Claude Code, le format de distribution officiel n'est pas npm mais le **plugin**, listé dans une **marketplace** (un simple fichier JSON dans un dépôt Git). Ce guide part d'un skill qui fonctionne et va jusqu'à sa publication.

## Choisir le bon canal

| Canal | Pour qui | Mises à jour |
|---|---|---|
| Committer dans `.claude/skills/` du dépôt | L'équipe qui travaille sur ce dépôt | Via `git pull` |
| Envoyer le dossier ou un `.zip` | Quelques personnes | Aucune, ils rechargent la copie |
| Plugin dans votre marketplace | Quiconque peut cloner le dépôt (public ou privé) | `claude plugin update` ou auto-update |
| Annuaire d'Anthropic (claude.ai/directory) | Utilisateurs de claude.ai, Cowork et Claude Code | Après validation de chaque version |
| Managed settings | Toute l'organisation | Pilotées par l'admin |

Pour un skill d'équipe sur un seul dépôt, le commit suffit. Dès qu'il sert dans plusieurs projets ou à l'extérieur, passez au plugin.

## Transformer le skill en plugin

Un plugin minimal contient un manifeste et un dossier `skills/` :

```text
generateur-migrations/
├── .claude-plugin/
│   ├── plugin.json
│   └── marketplace.json
├── skills/
│   └── generer-migration/
│       ├── SKILL.md
│       └── scripts/valider.py
└── README.md
```

```json
{
  "name": "generateur-migrations",
  "displayName": "Générateur de migrations",
  "version": "1.0.0",
  "description": "Génère et valide des migrations SQL Supabase",
  "author": { "name": "Acme" },
  "homepage": "https://github.com/acme/generateur-migrations",
  "repository": "https://github.com/acme/generateur-migrations"
}
```

Le skill s'invoquera en `/generateur-migrations:generer-migration`. Dans les chemins de scripts, utilisez `${CLAUDE_SKILL_DIR}` (dossier du skill) ou `${CLAUDE_PLUGIN_ROOT}` (racine du plugin).

Raccourci : un dossier de skill qui contient `.claude-plugin/plugin.json` se charge déjà comme un plugin.

## Ajouter le fichier de marketplace

Pour publier depuis le dépôt du plugin lui-même, placez `marketplace.json` à côté de `plugin.json`, avec une entrée dont la source est la racine :

```json
{
  "name": "acme-outils",
  "owner": { "name": "Acme" },
  "plugins": [
    { "name": "generateur-migrations", "source": "./" }
  ]
}
```

Gardez le même `name` dans l'entrée et dans `plugin.json`, sinon l'installation échoue avec `Plugin "<nom>" not found in marketplace`. Poussez le dépôt : le plugin est publié, sans formulaire.

## Checklist avant chaque release

1. **Nom définitif** en kebab-case. Les utilisateurs installent par `nom@marketplace` : renommer casse les installations existantes. Changez plutôt `displayName`.
2. **Stratégie de version** : incrémentez `version` à chaque release, ou omettez-la pour que Claude Code utilise le SHA du commit. Si vous gardez une `version` figée, `claude plugin update` répond « already at the latest version ».
3. **Validation** :

   ```bash
   claude plugin validate --strict .
   ```

   `--strict` échoue aussi sur les avertissements (champ inconnu, `version` manquante) : idéal en CI.
4. **Test d'installation** depuis une marketplace locale :

   ```bash
   claude plugin marketplace add ./
   claude plugin install generateur-migrations@acme-outils
   ```

5. **Métadonnées** : `description`, `author`, `homepage`, `repository` et un `README.md` pour les humains (le `SKILL.md` s'adresse à Claude).
6. **Évaluations** : `claude plugin eval .` si vous avez une suite de tests (voir [Tester un skill](/wiki/skills/tester-skill)).

## Ce que font vos utilisateurs

```bash
claude plugin marketplace add acme/generateur-migrations
claude plugin install generateur-migrations@acme-outils
```

Ou en une commande dans une session (v2.1.275 et plus) :

```text
/plugin install generateur-migrations --marketplace acme/generateur-migrations
```

L'auto-update est désactivé par défaut pour une marketplace tierce. Chaque utilisateur peut l'activer dans `/plugin` > **Marketplaces**, ou un admin via `"autoUpdate": true` dans les managed settings.

## Soumettre à l'annuaire d'Anthropic

L'annuaire (claude.ai/directory) touche les utilisateurs de claude.ai, de Cowork et de Claude Code. La soumission se fait depuis le portail développeur `claude.ai/directory/manage` et demande une offre claude.ai payante. Avant de soumettre :

- `claude plugin validate --strict` doit passer (le portail applique des règles supplémentaires) ;
- vérifiez quels composants se chargent hors de Claude Code : par exemple, les champs de frontmatter propres à Claude Code ne sont pas acceptés sur claude.ai, qui n'admet que `name`, `description`, `license`, `compatibility`, `metadata` et `allowed-tools`.

La marketplace officielle `claude-plugins-official` ne prend pas de soumissions par ce portail.

## Et npm ?

Une entrée de marketplace peut avoir une source `npm`, mais ce n'est pas le chemin recommandé : la version calculée vaut alors `unknown` si le manifeste n'en fixe pas. Préférez une source Git (`github`, `url`, `git-subdir`), épinglable sur un `ref` ou un `sha`.
