Claude Code s'étend de plusieurs façons : les **skills**, les **subagents**, les **serveurs MCP**, les **hooks** et les **plugins** qui les regroupent. Ils se ressemblent en surface mais ne résolvent pas le même problème. Cet article vous aide à choisir le bon outil avant d'écrire une ligne.

## Le skill : des instructions chargées à la demande

Un skill est un dossier qui contient un fichier `SKILL.md` : un frontmatter YAML puis des instructions en Markdown. Claude lit en permanence le nom et la description de chaque skill. Le corps n'entre dans le contexte que lorsque le skill est invoqué, par vous (`/nom-du-skill`) ou par Claude lui-même quand la demande correspond à la description.

```yaml
---
name: remplir-formulaire-pdf
description: Remplit des formulaires PDF interactifs avec pypdf. À utiliser quand l'utilisateur demande de remplir un formulaire PDF.
allowed-tools: Bash(python3 *) Read
---

1. Lisez les champs du formulaire avec `python3 ${CLAUDE_SKILL_DIR}/scripts/champs.py <fichier>`.
2. Demandez les valeurs manquantes à l'utilisateur.
3. Remplissez puis enregistrez une copie suffixée `-rempli.pdf`.
```

Points clés :

- pas de processus séparé : le contenu est injecté dans la conversation courante ;
- il peut embarquer des scripts et des fichiers de référence lus seulement si besoin ;
- il remplace les anciennes slash commands personnalisées : un fichier `.claude/commands/deploy.md` et un skill `.claude/skills/deploy/SKILL.md` créent tous deux `/deploy`.

## Le subagent : une tâche déléguée dans un contexte vierge

Un subagent est une instance de Claude lancée par la session principale via l'outil `Agent` (anciennement `Task`). Il a sa propre fenêtre de contexte, son prompt système, ses outils et éventuellement son modèle. Il ne voit pas votre historique et ne renvoie qu'un résumé. Vous en définissez dans `.claude/agents/` ou `~/.claude/agents/`, et Claude Code fournit des types intégrés comme `Explore`, `Plan` et `general-purpose`.

Il convient pour :

- explorer un gros codebase sans remplir le contexte principal ;
- paralléliser des tâches indépendantes (les subagents tournent en arrière-plan par défaut) ;
- isoler un travail risqué, par exemple avec `isolation: worktree`.

Un subagent repart de zéro à chaque lancement : il relit les fichiers dont il a besoin, ce qui consomme des tokens.

## Le serveur MCP : un pont vers l'extérieur

Un serveur **Model Context Protocol** est un processus (local en stdio, ou distant en Streamable HTTP) qui expose des outils, des ressources et des prompts via JSON-RPC. Claude Code s'y connecte comme client.

```bash
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

Choisissez MCP quand il faut :

- appeler une API ou une base de données avec une authentification gérée hors du prompt (OAuth via `/mcp`) ;
- réutiliser les mêmes outils dans Claude Code, l'application Claude et d'autres clients compatibles.

Les outils MCP apparaissent sous la forme `mcp__<serveur>__<outil>`, et les prompts MCP deviennent des commandes `/mcp__<serveur>__<prompt>`.

## Le hook : une règle qui s'applique à chaque fois

Un skill est suivi avec jugement, pas de façon garantie. Si une règle doit s'appliquer **à chaque fois** (bloquer une commande, formater après chaque édition), utilisez un hook : Claude Code l'exécute à chaque événement (`PreToolUse`, `PostToolUse`, etc.), que Claude y pense ou non.

## Le plugin : l'emballage pour distribuer

Un plugin n'est pas un mécanisme de plus : c'est un **paquet** qui regroupe skills, subagents, hooks, serveurs MCP et mods, avec un manifeste `.claude-plugin/plugin.json`. On l'installe depuis une marketplace avec `/plugin install nom@marketplace`. Ses skills sont préfixés : `/mon-plugin:review`.

## Tableau récapitulatif

| Critère | Skill | Subagent | Serveur MCP | Hook |
|---|---|---|---|---|
| Forme | Dossier avec `SKILL.md` | Fichier `.md` dans `agents/` | Processus stdio ou HTTP | Commande déclarée dans les settings |
| Déclenchement | `/nom` ou choix de Claude | Délégation par Claude ou `@agent` | Appel d'outil | Événement du cycle de vie |
| Contexte | Conversation courante | Contexte isolé | Résultat d'outil dans la conversation | Hors contexte (sauf retour) |
| Coût permanent | Nom + description | Nom + description | Définitions d'outils (avec tool search) | Aucun |
| Idéal pour | Savoir-faire, procédures | Tâches lourdes et isolées | Services externes | Règles déterministes |

## Combiner les mécanismes

Les deux directions entre skills et subagents existent :

- un skill avec `context: fork` s'exécute dans un subagent (choisi par le champ `agent`) ;
- un subagent avec le champ `skills:` précharge le contenu complet de skills au démarrage.

Exemple réaliste pour traiter un ticket :

1. un serveur MCP Linear expose les tickets ;
2. un skill `/traiter-ticket` décrit la procédure maison (branche, tests, PR) ;
3. le skill délègue l'exploration du code à un subagent `Explore` pour garder le contexte principal propre ;
4. un hook `PreToolUse` bloque tout `git push --force`.

Pour partager l'ensemble avec l'équipe, emballez-le dans un plugin.
