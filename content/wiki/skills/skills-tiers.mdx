Au-delà des skills d'Anthropic, de nombreux éditeurs et développeurs publient des skills au format ouvert [Agent Skills](https://agentskills.io), compatibles avec Claude Code. Cette page présente quelques sources sérieuses et, surtout, une méthode pour juger un skill avant de lui donner accès à votre machine.

## Où chercher

| Source | Ce que vous y trouvez | Comment l'utiliser |
|---|---|---|
| Marketplace communautaire d'Anthropic (`claude-community`) | Plugins tiers soumis à Anthropic | `/plugin marketplace add anthropics/claude-plugins-community` |
| Marketplace officielle (`claude-plugins-official`) | Plugins d'Anthropic et de partenaires | Déjà ajoutée : `/plugin`, onglet **Discover** |
| Claude Marketplace | Catalogue web avec nombre d'installations et mention « Anthropic verified » | claude.com/marketplace/plugins |
| skills.sh | Annuaire et classement de skills de l'écosystème ouvert | Installation via `npx skills add` |
| Dépôts GitHub d'éditeurs | Skills maintenus par l'éditeur d'un outil | `npx skills add` ou leur propre marketplace |

## Vercel : agent-skills

Vercel Labs publie le dépôt `vercel-labs/agent-skills` et la CLI `skills`. Parmi les skills proposés :

- `react-best-practices` : règles de performance React et Next.js classées par impact ;
- `web-design-guidelines` : audit d'interface (accessibilité, focus, formulaires, UX) ;
- `vercel-optimize` : audit coût et performance d'un projet déployé sur Vercel.

```bash
npx skills add vercel-labs/agent-skills --list
npx skills add vercel-labs/agent-skills --skill react-best-practices -a claude-code
```

## Supabase : agent-skills

Supabase maintient `supabase/agent-skills`, avec notamment un skill `supabase` et un skill `supabase-postgres-best-practices`. Deux façons de l'installer :

```bash
# Via la CLI skills
npx skills add supabase/agent-skills --skill supabase-postgres-best-practices

# Ou comme plugin Claude Code
claude plugin marketplace add supabase/agent-skills
claude plugin install supabase@supabase-agent-skills
```

Utile sur un projet Supabase pour éviter les erreurs courantes de migrations et de politiques RLS.

## claude-mem : mémoire persistante entre sessions

`claude-mem` (dépôt `thedotmack/claude-mem`) est un **plugin** plutôt qu'un simple skill : il s'appuie sur des hooks pour observer les sessions, compresse ces observations et réinjecte le contexte utile dans les sessions suivantes. Installation recommandée par son auteur :

```text
/plugin marketplace add thedotmack/claude-mem
/plugin install claude-mem
```

Un `npm install -g claude-mem` n'installe que la bibliothèque, pas les hooks. Avant de l'adopter, comparez avec la mémoire native de Claude Code (`CLAUDE.md`, mémoire automatique, `/memory`) : vous n'en aurez peut-être pas besoin.

## Partenaires mis en avant par Anthropic

Le README de `anthropics/skills` cite par exemple les skills Notion. D'autres éditeurs (bases de données, outils de design, CI) publient leurs plugins dans la marketplace officielle : cherchez le nom de votre outil dans `/plugin` avant d'installer une version communautaire.

## Évaluer un skill tiers avant de l'installer

Anthropic est explicite : un skill malveillant peut pousser Claude à exécuter du code ou à exfiltrer des données. Anthropic ne vérifie pas les marketplaces tierces. Checklist :

1. **Lisez `SKILL.md`** en entier, en particulier `allowed-tools`, `hooks` et les commandes `` !`...` `` exécutées avant même que Claude lise le skill.
2. **Lisez chaque script** de `scripts/` et cherchez les appels réseau inattendus.
3. **Méfiez-vous des URL externes** : un skill qui charge des instructions depuis le Web peut changer de comportement sans changer de code.
4. **Vérifiez la maintenance** : commits récents, issues traitées, licence claire.
5. **Mesurez le coût** : chaque skill ajoute sa description au contexte à chaque tour. `/skill-doctor` montre ensuite ce que chaque skill coûte et s'il sert.
6. **Épinglez une version** pour un usage en équipe (référence Git, ou `ref`/`sha` dans votre propre marketplace), car l'auto-update peut modifier des fichiers déjà relus.

Les organisations peuvent restreindre les marketplaces autorisées via les managed settings, et désactiver l'exécution des commandes `` !`...` `` des skills avec `disableSkillShellExecution`.
