Un build verbeux, une suite de tests complète ou un dump SQL peuvent produire bien plus de texte que ce qu'il est utile de mettre dans le contexte de Claude. Claude Code applique donc des limites par outil : au-delà, la sortie est écrite dans un fichier et Claude n'en reçoit qu'un aperçu. Connaître ces seuils vous aide à écrire des commandes qui donnent à Claude l'essentiel, sans saturer la fenêtre de contexte.

## Les limites par outil

| Outil | Limite | Au-delà |
|-------|--------|---------|
| Bash (succès) | Environ 30 000 caractères en ligne | Chemin d'un fichier de sortie + aperçu des 2 000 premiers caractères ; Claude lit ou cherche dans le fichier si besoin |
| Bash (échec) | Environ 10 000 caractères | Extrait début + fin, sans chemin de fichier |
| Bash (toute commande) | 5 Go de sortie | Commande arrêtée |
| Read | Limite en tokens par lecture | Première page + avis `PARTIAL view` ; lecture de la suite avec `offset` et `limit` |
| Grep | Pagination `head_limit` et `offset` | Claude affine ou pagine |
| Glob | 100 fichiers | Indicateur de troncature ; Claude resserre le motif |
| Outils MCP | Avertissement à 10 000 tokens, maximum 25 000 par défaut | Sortie enregistrée dans un fichier, Claude reçoit le chemin |
| WebFetch | Page tronquée à une taille fixe | Le prompt d'extraction filtre de toute façon le contenu |

## Échec ou succès : pourquoi c'est important

Pour Bash, Claude Code traite différemment un résultat valide et un échec. Un code de sortie 1 est considéré comme valide seulement pour `grep`, `rg`, `egrep`, `fgrep`, `find`, `diff`, `test`, `[`, `git diff` et `git grep`. Pour les autres commandes (y compris `jq -e` ou `cmp`), un code 1 est un échec : la sortie est plafonnée à environ 10 000 caractères, en extrait début + fin. Si une commande « qui échoue normalement » produit beaucoup de texte utile, redirigez-la vers un fichier.

## Réglages disponibles

| Réglage | Effet |
|---------|-------|
| `BASH_MAX_OUTPUT_LENGTH` | Taille de la fenêtre relue depuis le fichier de sortie (30 000 par défaut, 150 000 maximum). N'augmente pas le plafond en ligne d'un succès |
| `bashOutputMaxChars` (settings, v2.1.261+) | Plafond en ligne d'un succès et fenêtre de relecture ensemble, jusqu'à 128 000 caractères. Remplace la variable précédente |
| `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` | Relève la limite de Read |
| `MAX_MCP_OUTPUT_TOKENS` | Relève le plafond des sorties MCP |

Relever ces plafonds fait entrer plus de texte dans le contexte à chaque appel. C'est rarement la meilleure option : mieux vaut une commande qui sort moins.

## Stratégies efficaces

### Rediriger, puis filtrer

```bash
npm run build > /tmp/build.log 2>&1; echo "exit=$?"
grep -nE "error|Error|failed" /tmp/build.log | head -50
```

Le log complet reste sur disque. Claude lit ensuite la zone utile avec `Read` et `offset`.

### Choisir des sorties compactes

| Au lieu de | Préférez |
|------------|----------|
| `cat huge.log` | `tail -100 huge.log` ou `grep -n motif huge.log` |
| `npm install` | `npm install --no-audit --no-fund --loglevel=error` |
| `pytest -v` | `pytest -q --tb=short` |
| `cargo build` | `cargo build --quiet` |
| `git diff` sur 200 fichiers | `git diff --stat`, puis `git diff -- chemin/fichier` |
| `git log` | `git log --oneline -20` |

### Compter avant de lire

```bash
npm run lint 2>&1 | grep -c "error"
npm run lint 2>&1 | grep "error" | head -20
```

### Longues commandes en arrière-plan

Avec `run_in_background`, la sortie s'écrit dans un fichier que Claude relit avec `Read` au moment utile (l'ancien outil `TaskOutput` est déprécié au profit de cette lecture). Pour suivre une sortie au fil de l'eau et réagir à des lignes précises, l'outil `Monitor` envoie chaque nouvelle ligne comme un événement.

### Déléguer l'exploration volumineuse

Analyser 40 fichiers de logs ou tout un module : confiez-le à un sous-agent. Il absorbe les sorties dans son propre contexte et ne renvoie qu'un résumé.

## Surveiller votre contexte

- `/context` montre ce qui occupe la fenêtre de contexte.
- `Ctrl+O` ouvre la transcription détaillée, avec les sorties complètes des outils.
- `/compact` résume la conversation quand elle s'alourdit ; `/rewind` propose aussi « Summarize from here » pour compresser une phase de débogage verbeuse.

## Pièges fréquents

**Tests verbeux.** Un reporter détaillé multiplie la sortie. Utilisez le mode compact et ne relancez en détaillé que le test qui échoue.

**Lire un binaire avec cat.** Images et PDF passent par `Read`, qui les gère nativement.

**Croire qu'une sortie est complète.** Si la fin attendue manque (code de sortie, résumé des tests), la sortie a été coupée : redirigez vers un fichier et lisez par tranches.
