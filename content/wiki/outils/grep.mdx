`Grep` cherche un motif **dans le contenu** des fichiers, là où Glob cherche par nom. Il repose sur ripgrep : rapide, compatible `.gitignore`, avec la syntaxe d'expressions régulières de ripgrep. Sur macOS, Linux et WSL, l'outil n'est pas chargé par défaut : Claude lance alors `grep` (une version intégrée d'`ugrep`) ou `rg` via Bash.

## Disponibilité

Mêmes règles que Glob : présent par défaut sous Windows, absent sur macOS, Linux et WSL. Il revient si vous le nommez dans `--tools` ou `--allowedTools`, si Bash est retiré de la session, ou dans un sous-agent qui le liste sans `Bash`. Les recherches faites via Bash apparaissent dans vos hooks et vos permissions comme des appels `Bash`.

## Paramètres

| Paramètre | Rôle |
|-----------|------|
| `pattern` | Expression régulière (syntaxe ripgrep), obligatoire |
| `path` | Fichier ou dossier où chercher |
| `glob` | Filtre de fichiers, par exemple `**/*.tsx` |
| `type` | Filtre par langage : `ts`, `py`, `rust`… |
| `output_mode` | `files_with_matches` (défaut), `content` ou `count` |
| `-i` | Insensible à la casse |
| `-n` | Numéros de ligne (mode `content`) |
| `-A`, `-B`, `-C` | Lignes de contexte après, avant, autour |
| `multiline` | Permet à un motif de couvrir plusieurs lignes |
| `head_limit`, `offset` | Pagination des résultats |

## Les trois modes de sortie

| Mode | Renvoie | Usage |
|------|---------|-------|
| `files_with_matches` | Chemins des fichiers seulement | Cartographier |
| `content` | Lignes trouvées avec fichier et numéro | Comprendre un usage |
| `count` | Nombre de correspondances par fichier, puis un total | Prioriser |

En mode `count`, le total couvre toutes les correspondances même quand `head_limit` ou `offset` tronquent la liste. En mode `content`, un `offset` au-delà de la dernière correspondance renvoie `No entries at this offset` : cela ne veut pas dire que le motif est absent.

## Exemples d'appels

Lister les routes API qui exportent un `POST` :

```json
{
  "pattern": "export async function POST",
  "glob": "app/api/**/route.ts",
  "output_mode": "content",
  "-n": true
}
```

Compter les `console.log` par fichier TypeScript :

```json
{
  "pattern": "console\\.log",
  "type": "ts",
  "output_mode": "count"
}
```

## Syntaxe ripgrep : ce qui change par rapport à grep

- Les métacaractères s'échappent : pour trouver `interface{}` en Go, le motif est `interface\{\}` ; pour un point littéral, `\.`.
- Par défaut, un motif ne traverse pas les fins de ligne. Pour un bloc sur plusieurs lignes, activez `multiline: true`.
- Dans le JSON d'un appel, chaque `\` est doublé : `console\\.log` arrive à ripgrep sous la forme `console\.log`.
- Un motif, un glob ou un type rejeté par ripgrep renvoie une erreur avec le diagnostic de ripgrep (avant la version 2.1.208, cela renvoyait à tort `No files found`).

## .gitignore

Grep **respecte `.gitignore`** : `node_modules/`, `dist/` ou `.env` ignorés ne sont pas fouillés. Pour chercher dans un fichier ignoré, Claude passe son chemin directement dans `path`.

## Équivalents en ligne de commande

Quand l'outil n'est pas chargé, Claude obtient les mêmes résultats via Bash :

```bash
# Fichiers qui importent Supabase
rg -l "from ['\"]@supabase" src

# TODO et FIXME avec numéro de ligne et une ligne de contexte
rg -n -C 1 "(TODO|FIXME):"

# Nombre de console.log par fichier
rg -c "console\.log" --type ts

# Sans rg : grep récursif en excluant node_modules
grep -rn --exclude-dir=node_modules "useEffect" src
```

## Pièges fréquents

**Point non échappé.** `app.config.js` trouve aussi `app-config-js`. Écrivez `app\.config\.js`.

**Résultats trop nombreux.** Commencez par `files_with_matches` ou `count`, puis passez en `content` sur un dossier précis avec `head_limit`.

**`glob` ou `type` ?** `type: "ts"` utilise la table de types de ripgrep, qui couvre plusieurs extensions TypeScript. `glob` filtre sur un motif de chemin exact. Les deux se combinent.

**Permissions.** Grep ne demande pas d'autorisation dans le répertoire de travail. Ses règles de chemin s'écrivent avec `Read(...)`, et une règle `Read(...)` en `deny` s'applique au mieux à Grep aussi.
