`Read` est l'outil que Claude Code utilise pour charger le contenu d'un fichier dans son contexte. Il lit du code, mais aussi des images, des PDF et des notebooks Jupyter. Vous ne l'appelez jamais vous-même : Claude le déclenche quand il a besoin de voir un fichier, et vous gardez la main via les permissions.

## Ce que fait Read

Read prend un chemin de fichier et renvoie son contenu avec les numéros de ligne. Claude est instruit de toujours passer des **chemins absolus**.

Claude s'en sert pour :

- comprendre un fichier avant de le modifier avec `Edit` ou `Write` ;
- explorer une configuration, un schéma de base de données, un composant ;
- regarder une capture d'écran ou une maquette ;
- parcourir un PDF ou un notebook `.ipynb` avec ses sorties.

Read ne lit que des fichiers, jamais des répertoires. Pour lister un dossier, Claude passe par une commande shell comme `ls`.

## Paramètres

| Paramètre | Obligatoire | Rôle |
|-----------|-------------|------|
| `file_path` | oui | Chemin absolu du fichier |
| `offset` | non | Ligne de départ |
| `limit` | non | Nombre de lignes à lire |
| `pages` | non | Plage de pages d'un PDF, par exemple `"1-5"` |

Voici à quoi ressemble un appel, tel que Claude l'envoie (vous ne le tapez pas) :

```json
{
  "file_path": "/home/vous/projet/app/page.tsx",
  "offset": 120,
  "limit": 80
}
```

## Fichiers trop longs : la vue partielle

Par défaut, Read renvoie le fichier depuis le début. Si le fichier entier dépasse la limite de tokens, Read renvoie la première page avec un avertissement `PARTIAL view`. Ce message indique à Claude quelle part du fichier il a reçue et comment lire la suite avec `offset` et `limit`.

Deux comportements à connaître :

- une lecture avec `offset` ou `limit` explicite qui dépasse encore la limite renvoie une **erreur** : Claude doit réduire la plage ;
- une seule ligne gigantesque (JSON minifié, bundle) peut suffire à dépasser la limite. Claude cherche alors le contenu utile avec une recherche plutôt qu'avec Read.

Si vous devez vraiment lire de gros fichiers en entier, la variable d'environnement `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` relève la limite. Gardez en tête que tout ce qui est lu occupe votre fenêtre de contexte.

## Images, PDF et notebooks

| Type | Comportement |
|------|--------------|
| Images (PNG, JPG, etc.) | Renvoyées comme contenu visuel. Les grandes images sont redimensionnées et recompressées ; au-delà de 500 Ko après redimensionnement, elles sont réencodées en JPEG. |
| PDF courts | Lus en entier. |
| PDF de plus de 10 pages | Lecture par plages avec `pages`, 20 pages maximum par appel. Nécessite `pdftoppm` (paquet poppler). |
| Notebooks `.ipynb` | Toutes les cellules avec leurs sorties. Un notebook de plus de 100 Mo est refusé. |

Pour lire un PDF par plages, installez poppler :

```bash
# macOS
brew install poppler
# Debian / Ubuntu
sudo apt-get install poppler-utils
```

Sans lui, la lecture échoue avec `pdftoppm is not installed`.

Astuce pour les captures d'écran : comme Claude peut voir une version réduite d'une grande image, demandez-lui de recadrer la zone utile (par exemple avec ImageMagick) quand un détail fin compte.

## Permissions

En mode Manuel (`default`), Read ne demande **pas** d'autorisation pour les fichiers du répertoire de travail et des répertoires ajoutés (`--add-dir`, `/add-dir`). Il demande pour les chemins situés en dehors.

Pour interdire la lecture d'un fichier sensible, ajoutez une règle `deny` dans `.claude/settings.json` :

```json
{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)"
    ]
  }
}
```

Points importants :

- un fichier `.claudeignore` n'a **aucun effet** : transférez ses entrées dans des règles `Read` en `deny` ;
- une règle `Read(...)` en `deny` bloque aussi `Edit` et `Write` sur le même chemin ;
- Claude Code applique au mieux ces règles aux recherches (`Grep`, `Glob`) et aux commandes shell reconnues (`cat`, `head`, `tail`…), mais pas à un script Python ou Node qui ouvrirait le fichier lui-même. Pour une vraie barrière, activez le sandbox (voir l'article Bash).

## Pièges fréquents

**Confondre fichier vide et fichier absent.** Un fichier vide renvoie un avis indiquant qu'il existe mais n'a pas de contenu. Un `offset` au-delà de la dernière ligne renvoie le nombre de lignes du fichier.

**Lire en aveugle.** Lire cinq gros fichiers « pour voir » remplit le contexte. Mieux vaut chercher d'abord (`grep`, `rg` ou l'outil Grep) puis lire la zone utile.

**Oublier la lecture avant modification.** Selon le modèle, Claude doit avoir lu un fichier avant de l'éditer. Une lecture tronquée par `PARTIAL view` ne compte pas. Les détails sont dans l'article sur Edit.

## Bon réflexe pour un nouveau dépôt

Pour découvrir un projet, trois lectures suffisent souvent : le `README.md`, le manifeste de dépendances (`package.json`, `pyproject.toml`…) et le point d'entrée principal. Votre `CLAUDE.md` est chargé automatiquement au démarrage, inutile de le faire relire.
