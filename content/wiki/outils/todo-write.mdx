Claude Code peut tenir une **liste de tâches** visible pendant qu'il travaille : chaque étape passe de « à faire » à « en cours » puis « terminée ». Cette fonction a beaucoup changé : `TodoWrite` a été remplacé par quatre outils `Task*`, et sur les modèles récents (Opus 5.5, Sonnet 5.5, Fable 5.1…), aucun de ces outils n'est fourni par défaut.

## Ce qui a changé

| Période | Outils de suivi |
|---------|-----------------|
| Historique | `TodoWrite` : Claude réécrivait toute la liste à chaque mise à jour |
| Ensuite | `TaskCreate`, `TaskGet`, `TaskList`, `TaskUpdate` remplacent `TodoWrite` (qui reste disponible avec `CLAUDE_CODE_ENABLE_TASKS=0`) |
| Depuis la version 2.1.268 | Ces outils ne sont fournis par défaut que sur les modèles Claude 3.x, Opus 4 à 4.7, Sonnet 4 à 4.6 et Haiku 4.5 |

La raison donnée par Anthropic : les modèles récents suivent un travail en plusieurs étapes sans checklist écrite, et les définitions d'outils et rappels associés consomment du contexte. Sur ces modèles, la liste reste donc vide, et c'est normal.

## Les quatre outils Task

| Outil | Rôle |
|-------|------|
| `TaskCreate` | Crée une tâche (titre `subject`, forme progressive `activeForm` pour l'affichage) |
| `TaskUpdate` | Change le statut, les dépendances ou les détails d'une tâche, ou la supprime |
| `TaskGet` | Lit le détail d'une tâche |
| `TaskList` | Liste toutes les tâches avec leur statut |

Statuts : `pending`, `in_progress`, `completed`. Pour supprimer une tâche devenue inutile, Claude passe `status: "deleted"` dans un `TaskUpdate`. Contrairement à `TodoWrite`, chaque tâche a un identifiant et se met à jour individuellement.

## Activer la liste sur un modèle récent

Choisissez l'une de ces options :

```bash
# Pour toute la session, sur tous les modèles et fournisseurs
CLAUDE_CODE_ENABLE_TODO_TOOLS=1 claude

# En nommant un des outils au lancement
claude --allowedTools TaskCreate
```

Vous pouvez aussi mettre la variable dans `.claude/settings.json` :

```json
{
  "env": {
    "CLAUDE_CODE_ENABLE_TODO_TOOLS": "1"
  }
}
```

Dans les sessions en arrière-plan (agent view) et les sessions cloud, les outils sont fournis sur tous les modèles, sans réglage. Un sous-agent n'a ces outils que si votre session les a.

## Utiliser la liste au quotidien

- `Ctrl+T` affiche ou masque la checklist (jusqu'à cinq tâches visibles à la fois).
- Pour tout voir ou tout effacer, demandez-le simplement : « montre toutes les tâches », « vide la liste ».
- La liste survit aux compactages du contexte.
- Pour partager une liste entre plusieurs sessions, nommez-la : `CLAUDE_CODE_TASK_LIST_ID=mon-projet claude`. Elle est stockée dans `~/.claude/tasks/`.
- Ne confondez pas avec `/tasks`, qui liste les commandes et sous-agents **en cours d'exécution**.

## Quand cela vaut le coup

L'activer est utile si :

- vous voulez suivre visuellement une longue tâche (migration, refactoring en plusieurs zones) ;
- vous coordonnez une équipe d'agents (agent teams) via leur liste de tâches partagée ;
- vous développez avec l'Agent SDK et affichez la progression dans votre propre interface (les appels `TaskCreate` et `TaskUpdate` arrivent dans le flux de messages) ;
- vos hooks réagissent aux événements `TaskCreated` et `TaskCompleted`.

Sinon, sur un modèle récent, une alternative légère consiste à demander un plan numéroté dans la réponse, ou à passer par le mode plan.

## Bonnes pratiques si vous l'activez

- **3 à 8 tâches** pour une demande ; au-delà, découpez en plusieurs demandes ou déléguez à des sous-agents.
- **Un verbe d'action** en tête : « Ajouter la route /api/feedback », « Corriger le test d'authentification ».
- **Une seule tâche en cours** à la fois, sauf travail réellement parallèle.
- **« Terminé » veut dire vérifié** : une tâche dont les tests échouent n'est pas terminée.
