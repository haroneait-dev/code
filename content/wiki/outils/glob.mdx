`Glob` trouve des fichiers par leur **nom ou leur chemin** à partir d'un motif comme `**/*.tsx`. Il ne regarde pas le contenu (c'est le rôle de Grep). Point important en 2026 : sur macOS, Linux et WSL, Glob n'est plus chargé par défaut, et Claude cherche avec `find` via Bash.

## Glob est-il disponible chez vous ?

| Plateforme | Par défaut |
|------------|-----------|
| Windows | Glob et Grep sont présents |
| macOS, Linux, WSL | Glob et Grep sont absents ; Claude utilise `find` et `grep` dans Bash |

Sur macOS, Linux et WSL, ces deux commandes lancent dans le shell de Claude des versions intégrées de `bfs` et `ugrep`. Conséquence pratique : ces recherches passent par vos hooks et vos règles de permission en tant qu'appels **`Bash`**. `find` et `grep` font partie des commandes en lecture seule qui ne demandent pas d'autorisation.

Glob et Grep reviennent dans ces cas :

- vous les nommez au lancement : `claude --allowedTools Glob` (nommer l'un dans `--allowedTools` rétablit les deux), ou en les listant dans `--tools` (vous obtenez alors seulement ceux que vous nommez) ;
- Bash est retiré de la session (règle `deny`, `--disallowedTools Bash` ou `--restricted`) ;
- un sous-agent liste `Glob` ou `Grep` dans son champ `tools` sans `Bash`.

Une règle `allow` dans un fichier de settings ne suffit pas à les faire revenir.

## Syntaxe des motifs

| Motif | Correspond à |
|-------|--------------|
| `*.ts` | Fichiers `.ts` du dossier courant uniquement |
| `**/*.ts` | Tous les `.ts`, à toute profondeur |
| `src/**/*.{ts,tsx}` | `.ts` et `.tsx` sous `src/` |
| `app/**/route.ts` | Toutes les routes API d'un projet Next.js App Router |
| `.claude/skills/*/SKILL.md` | Les skills d'un projet |

## Paramètres

| Paramètre | Rôle |
|-----------|------|
| `pattern` | Motif glob, obligatoire |
| `path` | Dossier de départ (par défaut, le répertoire de travail) |

Exemple d'appel :

```json
{
  "pattern": "**/*.sql",
  "path": "/home/vous/projet/supabase/migrations"
}
```

## Résultats : tri, plafond et .gitignore

- Les résultats sont **triés par date de modification** : les fichiers récemment touchés remontent en premier.
- Ils sont **plafonnés à 100 fichiers**. Au-delà, Claude voit un indicateur de troncature et resserre le motif.
- Glob **ne respecte pas `.gitignore`** par défaut : il peut renvoyer des fichiers de `node_modules/` ou `dist/`. Pour changer ce comportement, lancez Claude Code avec `CLAUDE_CODE_GLOB_NO_IGNORE=false`. Grep, lui, ignore les fichiers du `.gitignore`.

## Permissions

Glob ne demande pas d'autorisation dans le répertoire de travail, mais en demande hors de celui-ci. Les règles de chemin s'écrivent avec **`Read(...)`** : une règle `Glob(docs/**)` est ignorée (avec un avertissement), sauf passée dans `--allowedTools`.

## Équivalents avec find

Si Glob n'est pas chargé, Claude obtient la même chose avec `find` :

```bash
# Tous les composants .tsx hors node_modules
find . -name "*.tsx" -not -path "*/node_modules/*"

# Les 10 fichiers modifiés le plus récemment (GNU find)
find src -type f -printf '%T@ %p\n' | sort -rn | head -10

# Fichiers modifiés depuis moins d'un jour
find . -type f -mtime -1 -not -path "./.git/*"
```

## Pièges fréquents

**Confondre `*` et `**`.** `src/*.ts` ne trouve pas `src/auth/login.ts`. Utilisez `src/**/*.ts`.

**Motifs trop larges.** `**/*` sur un monorepo atteint vite le plafond de 100 résultats. Ajoutez une extension ou un sous-dossier dans `path`.

**Casse.** Sur macOS et Linux, `*.MD` ne trouve pas `README.md`.

**Chercher du contenu.** « Les fichiers qui importent Supabase » est une recherche de contenu : c'est Grep (ou `grep -rl`), pas Glob.
