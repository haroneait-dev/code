`Bash` permet à Claude Code d'exécuter des commandes shell dans votre environnement : tests, build, Git, gestionnaires de paquets, scripts. C'est l'outil le plus puissant du harness, donc le plus encadré : règles de permission, mode auto avec classifieur, sandbox optionnel et timeouts.

## À quoi sert Bash

- lancer les tests et le build (`npm test`, `pytest`, `cargo build`) ;
- interagir avec Git et GitHub (`git diff`, `gh pr view`) ;
- installer des dépendances ;
- chercher dans le code (`rg`, `grep`, `find`) : sur macOS, Linux et WSL, c'est même le chemin par défaut, car les outils Glob et Grep n'y sont pas chargés ;
- lancer un serveur de dev en arrière-plan.

## Paramètres

| Paramètre | Rôle |
|-----------|------|
| `command` | Commande à exécuter |
| `description` | Courte description affichée dans l'interface |
| `timeout` | Délai en millisecondes, choisi par Claude si besoin |
| `run_in_background` | Lance la commande comme tâche d'arrière-plan |
| `dangerouslyDisableSandbox` | Demande une nouvelle tentative hors sandbox (voir plus bas) |

## Ce qui persiste entre deux commandes

Chaque commande tourne dans un processus séparé, mais :

- **le répertoire courant persiste** : après un `cd` dans le projet ou un répertoire ajouté (`--add-dir`, `/add-dir`), les commandes suivantes partent de là. Si `cd` sort de ces répertoires, Claude Code revient au dossier du projet et ajoute `Shell cwd was reset to <dir>` au résultat. Les sous-agents ne conservent jamais un changement de répertoire ;
- **les variables d'environnement ne persistent pas** : un `export` est perdu à la commande suivante ;
- **vos alias et fonctions** définis dans `~/.zshrc`, `~/.bashrc` ou `~/.profile` sont capturés au démarrage et disponibles.

Activez votre virtualenv ou environnement conda **avant** de lancer `claude`. Pour des variables persistantes, pointez `CLAUDE_ENV_FILE` vers un script shell avant le lancement, ou remplissez-le avec un hook `SessionStart`.

## Timeouts

| Variable | Défaut | Effet |
|----------|--------|-------|
| `BASH_DEFAULT_TIMEOUT_MS` | 120000 (2 min) | Délai quand Claude n'en précise pas |
| `BASH_MAX_TIMEOUT_MS` | 600000 (10 min) | Plafond de ce que Claude peut demander |

Quand une commande atteint son timeout sans finir, Claude Code ne la tue pas : il la **bascule en arrière-plan** (sauf si elle commence par `sleep`). Le résultat l'indique avec l'identifiant de tâche et le fichier où la sortie s'écrit.

## Commandes en arrière-plan

Pour un serveur de dev ou un build long, Claude passe `run_in_background: true` et continue à travailler. Vous pouvez aussi appuyer sur `Ctrl+B` pendant qu'une commande tourne (deux fois sous tmux). La commande `/tasks` liste et arrête les tâches en cours.

- La sortie est écrite dans un fichier que Claude relit avec `Read`.
- En session locale (terminal, application de bureau, VS Code), pas de limite de durée.
- En session sans surveillance (`claude -p`, Agent SDK, CI, cloud), limite de 30 minutes par défaut, jusqu'à 2 heures avec un `timeout` explicite.
- Une tâche dont la sortie dépasse 5 Go est arrêtée.
- `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` désactive tout le mécanisme.

Pour **réagir** à une sortie au fil de l'eau (log, CI, fichier), Claude dispose de l'outil `Monitor`, qui renvoie chaque nouvelle ligne comme un événement.

## Limites de sortie

| Résultat | Ce que Claude reçoit |
|----------|----------------------|
| Succès | Jusqu'à environ 30 000 caractères en ligne ; au-delà, le chemin d'un fichier et un aperçu des 2 000 premiers caractères |
| Échec | Jusqu'à environ 10 000 caractères ; au-delà, un extrait début + fin |

Un code de sortie 1 est considéré comme normal pour `grep`, `rg`, `find`, `diff`, `test`, `[`, `git diff` et `git grep`. Le détail et les réglages (`BASH_MAX_OUTPUT_LENGTH`, `bashOutputMaxChars`) sont dans l'article sur la gestion des sorties.

## Permissions

En mode Manuel, Bash demande votre accord, sauf pour un ensemble intégré de commandes en lecture seule (`ls`, `cat`, `echo`, `pwd`, `head`, `tail`, `grep`, `find`, `wc`, `which`, `diff`, `stat`, `du`, `cd` et les formes en lecture de `git`). Depuis août 2026, le mode par défaut est `auto` : un classifieur examine les commandes à votre place.

Les règles se placent dans `.claude/settings.json` :

```json
{
  "permissions": {
    "allow": ["Bash(npm run test *)", "Bash(npm run lint)", "Bash(git diff *)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Bash(rm -rf *)", "Bash(curl *)"]
  }
}
```

À retenir :

- `*` remplace n'importe quel texte. L'ancienne forme `Bash(npm:*)` reste équivalente à `Bash(npm *)`, mais seulement en fin de motif ;
- les opérateurs `&&`, `||`, `;`, `|` sont compris : `Bash(npm test *)` n'autorise pas `npm test && rm -rf build`. Chaque sous-commande doit être autorisée ;
- une règle `deny` sur Bash n'est pas une frontière de sécurité absolue : le même programme peut être appelé sous une autre forme. Pour une vraie barrière, utilisez le sandbox.

## Le sandbox

Le sandbox Bash limite, au niveau du système d'exploitation, ce que les commandes peuvent écrire et les domaines qu'elles peuvent joindre. Il est **désactivé par défaut**. Activez-le avec `/sandbox` ou `"sandbox": { "enabled": true }` dans vos settings. Il fonctionne sur macOS, Linux et WSL2 (sous Linux, il nécessite `bubblewrap` et `socat`).

Par défaut, une commande sandboxée peut écrire dans le répertoire de travail, un dossier temporaire et les répertoires ajoutés. Quand une commande échoue à cause du sandbox, Claude peut proposer de la relancer hors sandbox avec `dangerouslyDisableSandbox`. Refusez si vous ne comprenez pas pourquoi, ou désactivez cette échappatoire avec `"allowUnsandboxedCommands": false`.

## PowerShell sous Windows

Sous Windows, l'outil `PowerShell` exécute les commandes nativement. Il est actif automatiquement sans Git Bash, et par défaut pour les comptes claude.ai et Console avec Git Bash (`CLAUDE_CODE_USE_POWERSHELL_TOOL=0` pour le couper). Sous Linux, macOS et WSL, il est optionnel et nécessite PowerShell 7 (`pwsh`). Dans vos hooks, utilisez le matcher `Bash|PowerShell` pour couvrir les deux.

## Pièges fréquents

**Commandes interactives.** `git rebase -i`, `vim`, un `ssh` qui demande un mot de passe : Claude ne peut pas répondre. Préférez les variantes non interactives.

**Hooks Git qui attendent une saisie.** Un pre-commit interactif bloque le commit. Ne contournez pas avec `--no-verify` sans le décider vous-même.

**Commandes qui saturent la sortie.** `npm install` verbeux, tests en mode `-v` : filtrez ou redirigez vers un fichier.

**Mémoire.** Sous Linux et WSL, `CLAUDE_CODE_TOOL_MEMORY_LIMIT=4G` plafonne la mémoire de toutes les commandes Bash, PowerShell et Monitor d'une session.

## Exécuter vous-même une commande

Préfixez votre saisie par `!` pour lancer une commande sans passer par Claude : `! npm test`. La commande et sa sortie sont ajoutées au contexte de la conversation.
