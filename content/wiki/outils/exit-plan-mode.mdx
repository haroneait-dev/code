Le **mode plan** demande à Claude d'étudier le code et de proposer une démarche sans modifier vos sources. Quand le plan est prêt, Claude appelle l'outil `ExitPlanMode` : il vous présente le plan et attend votre approbation avant de toucher au moindre fichier. C'est le bon réflexe avant une migration, un gros refactoring ou toute opération difficile à défaire.

## Entrer en mode plan

| Méthode | Effet |
|---------|-------|
| `Shift+Tab` | Fait défiler les modes. Depuis `auto`, l'ordre est : manuel (`default`), `acceptEdits`, `plan`, puis retour |
| `/plan` en début de prompt | Plan mode pour ce seul prompt |
| `claude --permission-mode plan` | Démarre la session en plan |
| `"defaultMode": "plan"` dans `.claude/settings.json` | Plan par défaut pour le projet en terminal |

La barre d'état affiche `⏸ plan mode on`. Un nouvel appui sur `Shift+Tab` quitte le mode plan sans approuver de plan. Claude peut aussi proposer d'y entrer lui-même via l'outil `EnterPlanMode`.

Dans VS Code, réglez `claudeCode.initialPermissionMode` sur `plan` pour démarrer les conversations en plan.

## Ce que Claude fait pendant la planification

Claude lit des fichiers, lance des commandes d'exploration et rédige un plan, mais **n'édite pas** vos sources. Il peut s'appuyer sur le sous-agent intégré `Plan` (lecture seule) pour rassembler le contexte.

Pour les commandes shell, le premier cas applicable s'impose :

| Situation | Commandes shell pendant le plan |
|-----------|--------------------------------|
| Mode auto disponible et `useAutoModeDuringPlan` actif (par défaut) | Le classifieur les examine : approuvées, elles s'exécutent ; rejetées, elles sont bloquées |
| Mode auto indisponible ou réglage désactivé | Hors commandes en lecture seule, elles demandent votre accord |
| Terminal interactif lancé avec le contournement des permissions disponible | Pas de blocage : Claude est seulement instruit de ne pas éditer |

Dans les exécutions non interactives (`-p`), l'Agent SDK et le panneau VS Code, les blocages du mode plan restent toujours appliqués.

## Approuver le plan

Quand Claude appelle `ExitPlanMode`, vous voyez le plan et plusieurs choix :

- **Yes, and use auto mode** : approuver et continuer en mode auto (si le mode auto n'est pas disponible, l'option devient « Yes, auto-accept edits ») ;
- **Yes, manually approve edits** : approuver et valider chaque modification une par une ;
- **No, keep planning** : rester en plan et dire à Claude ce qu'il faut changer.

Deux raccourcis utiles :

- `Ctrl+G` ouvre le plan dans votre éditeur de texte pour le corriger directement avant que Claude ne commence ;
- avec le réglage `showClearContextOnPlanAccept`, une option supplémentaire approuve le plan **et vide le contexte de planification**, pratique quand l'exploration a beaucoup rempli la fenêtre.

L'approbation fait sortir du mode plan et bascule la session dans le mode choisi. Elle donne aussi un titre à la session à partir du plan, si vous ne l'avez pas déjà nommée. `ExitPlanMode` fait partie des outils qui demandent une autorisation, et l'approbation du plan ne se valide jamais toute seule par inactivité.

## Ce qu'est un bon plan

Un plan utile se lit en deux minutes et contient :

```markdown
## Objectif
Migrer l'authentification de Clerk vers Supabase Auth.

## Fichiers touchés
- proxy.ts : remplacer le middleware Clerk
- app/auth/callback/route.ts : callback OAuth PKCE
- components/UserMenu.tsx : remplace <UserButton>

## Hors périmètre
- Migration des utilisateurs existants (second temps)

## Étapes
1. Installer @supabase/ssr et créer le client serveur
2. Réécrire proxy.ts avec createServerClient
3. Adapter le callback OAuth
4. Remplacer les composants Clerk
5. Supprimer @clerk/nextjs, lancer build et tests

## Risques
- Sessions actives invalidées
- Variables d'environnement à mettre à jour sur Vercel
```

Si le plan est vague (« je vais migrer l'auth »), choisissez « No, keep planning » et demandez les fichiers, l'ordre et les risques.

## Quand ne pas l'utiliser

Pour une typo, un import ou un renommage local, le mode plan ajoute une étape inutile. Réservez-le aux changements à fort impact ou mal compris.

## Pièges fréquents

**Planifier sans explorer.** Un plan écrit sans lire le code repose sur des suppositions. Laissez Claude lire les fichiers clés d'abord.

**Explorer sans fin.** Trente fichiers lus remplissent le contexte. Demandez un plan dès que la structure est claire, quitte à préciser ensuite.

**Changer de cap après approbation.** Si l'approche doit changer en cours de route, revenez en mode plan (`Shift+Tab` ou `/plan`) pour faire valider la nouvelle version.
