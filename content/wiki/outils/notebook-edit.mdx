Un notebook Jupyter (`.ipynb`) est un fichier JSON qui contient des cellules de code, de Markdown, leurs sorties et des métadonnées. `NotebookEdit` le modifie **une cellule à la fois**, en ciblant la cellule par son identifiant, au lieu de faire du remplacement de texte dans le JSON comme le ferait `Edit`.

## Ce que permet NotebookEdit

| Mode (`edit_mode`) | Effet |
|--------------------|-------|
| `replace` (défaut) | Remplace la source de la cellule ciblée |
| `insert` | Ajoute une nouvelle cellule **après** la cellule ciblée ; sans `cell_id`, au début du notebook. Exige `cell_type` (`code` ou `markdown`) |
| `delete` | Supprime la cellule ciblée |

## Paramètres

| Paramètre | Rôle |
|-----------|------|
| `notebook_path` | Chemin absolu du `.ipynb` |
| `cell_id` | Identifiant de la cellule ciblée |
| `new_source` | Nouveau contenu de la cellule (inutile pour `delete`) |
| `cell_type` | `code` ou `markdown`, obligatoire pour `insert` |
| `edit_mode` | `replace`, `insert` ou `delete` |

## Étape 1 : lire le notebook

Claude lit d'abord le notebook avec `Read`, qui renvoie toutes les cellules avec leurs sorties (code, Markdown, graphiques). C'est là qu'il récupère les `cell_id`. Pour un notebook, la lecture préalable est exigée sur tous les modèles avant un `Write`. Un notebook de plus de 100 Mo est refusé par Read : Claude en extrait alors une tranche de cellules avec une commande shell.

## Exemples d'appels

Remplacer une cellule de code :

```json
{
  "notebook_path": "/home/vous/analyse/ventes.ipynb",
  "cell_id": "a1b2c3",
  "new_source": "import pandas as pd\ndf = pd.read_csv('ventes.csv')\ndf.head()"
}
```

Insérer une cellule Markdown après la précédente :

```json
{
  "notebook_path": "/home/vous/analyse/ventes.ipynb",
  "cell_id": "a1b2c3",
  "edit_mode": "insert",
  "cell_type": "markdown",
  "new_source": "## Exploration\nAperçu des 5 premières lignes."
}
```

Supprimer une cellule :

```json
{
  "notebook_path": "/home/vous/analyse/ventes.ipynb",
  "cell_id": "d4e5f6",
  "edit_mode": "delete"
}
```

## Permissions

NotebookEdit demande votre accord en mode Manuel. Ses règles s'écrivent au format `Edit(...)` :

```json
{
  "permissions": {
    "allow": ["Edit(/notebooks/**)"],
    "deny": ["Edit(/notebooks/archives/**)"]
  }
}
```

Piège : contrairement à Edit et Write, NotebookEdit **n'est pas couvert** par une règle `Read(...)` en `deny`. Pour qu'aucun outil ne puisse modifier un chemin, ajoutez aussi une règle `Edit(...)` en `deny`. Une règle écrite `NotebookEdit(chemin)` est ignorée (avec un avertissement au démarrage).

## Pièges fréquents

**Confondre identifiant et position.** `cell_id` est une chaîne lue dans le notebook, pas « la troisième cellule ». Demandez à Claude de relire le notebook si vous avez ajouté des cellules entre-temps.

**Oublier `cell_type` en insertion.** L'insertion l'exige.

**Sorties devenues incohérentes.** Changer le code d'une cellule ne réexécute rien. Les sorties affichées ne correspondent plus au nouveau code : réexécutez le notebook (par exemple `jupyter nbconvert --to notebook --execute --inplace ventes.ipynb`).

**Éditer le JSON à la main.** Un `Edit` ou un `sed` sur le `.ipynb` peut casser la structure. Si un doute existe, validez avec `nbformat` :

```bash
python -c "import nbformat; nbformat.validate(nbformat.read('ventes.ipynb', as_version=4)); print('OK')"
```

## Cas particuliers

- **Notebooks au format texte (Jupytext, `# %%`)** : ce sont des `.py` ou `.md`, donc Claude utilise `Edit` classique.
- **Colab, Kaggle** : le format `.ipynb` est standard. Téléchargez le notebook localement pour que Claude puisse le modifier.
- **Diffs Git lisibles** : `nbstripout` retire les sorties avant commit, ce qui évite des diffs énormes.
