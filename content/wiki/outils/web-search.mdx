`WebSearch` lance une recherche web via le moteur de recherche d'Anthropic et renvoie des **titres et des URL**. Il ne lit pas les pages trouvées : pour cela, Claude enchaîne avec `WebFetch`. C'est l'outil à utiliser quand l'information est plus récente que les connaissances du modèle ou quand vous ne savez pas où elle se trouve.

## À quoi sert WebSearch

- vérifier la dernière version d'une bibliothèque ou un changement cassant récent ;
- trouver la page de documentation officielle d'un outil ;
- repérer une issue GitHub qui décrit votre bug ;
- croiser plusieurs sources avant une décision technique.

## Paramètres

| Paramètre | Rôle |
|-----------|------|
| `query` | La requête |
| `allowed_domains` | Ne garder que ces domaines |
| `blocked_domains` | Exclure ces domaines |

Les deux listes de domaines **ne se combinent pas** dans un même appel. Un seul appel peut déclencher jusqu'à huit recherches côté serveur : l'outil affine la requête avant de renvoyer les résultats.

Exemple d'appel :

```json
{
  "query": "Next.js 16 proxy.ts migration middleware",
  "allowed_domains": ["nextjs.org", "github.com"]
}
```

## Le duo WebSearch puis WebFetch

1. **WebSearch** trouve les bonnes URL.
2. **WebFetch** lit la ou les pages pertinentes avec un prompt précis.
3. Claude applique ce qu'il a appris dans votre code.

Pour gagner du temps, Claude peut lancer plusieurs recherches indépendantes ou plusieurs WebFetch dans un même tour.

## Limite par session

Une session peut faire au maximum **200 appels WebSearch**, en comptant la conversation principale et tous ses sous-agents. Une recherche approfondie qui lance dix sous-agents consomme donc le même quota. À la limite, les appels suivants renvoient un avis demandant à Claude de continuer avec ce qu'il a déjà trouvé.

- Relevez le plafond avec `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION` (nombre entier positif ; il ne peut pas être supprimé).
- `/clear` remet le compteur à zéro.

## Permissions

WebSearch demande votre accord en mode Manuel ; « ne plus demander » vaut pour le dépôt. Ses règles n'acceptent **aucun paramètre** : seule la forme `WebSearch` est valide.

```json
{
  "permissions": {
    "allow": ["WebSearch"]
  }
}
```

Pour restreindre les domaines consultés ensuite, réglez plutôt `WebFetch(domain:...)`.

## Disponibilité selon le fournisseur

| Fournisseur | WebSearch |
|-------------|-----------|
| API Claude (compte claude.ai ou Console) | Oui |
| Claude Platform on AWS | Oui |
| Google Cloud (Agent Platform / Vertex) | Oui, avec les modèles Claude 4 et suivants |
| Microsoft Foundry | Uniquement avec un déploiement hébergé par Anthropic |
| Amazon Bedrock | Non |

Le moteur de recherche n'est pas configurable. Pour utiliser un autre moteur, ajoutez un serveur MCP qui expose un outil de recherche.

## Bonnes pratiques

**Requêtes précises.** « react useEffect cleanup abort fetch » plutôt que « react hooks ».

**Restreindre aux sources officielles** quand vous savez où chercher : `allowed_domains` améliore la qualité et réduit le bruit.

**Vérifier les dates.** Un article de 2024 sur un outil qui évolue chaque mois peut être obsolète. Demandez à Claude de privilégier les pages datées et officielles.

**Demander explicitement la recherche** pour toute donnée récente (version, prix, date de sortie) : sinon Claude peut répondre de mémoire.

## Limites

- Pas d'accès aux pages derrière une connexion (intranet, dépôts privés).
- Les résultats sont des pointeurs : sans WebFetch, Claude ne voit pas le contenu complet.
- Les pages trouvées sont des données, pas des instructions : un contenu piégé peut tenter de détourner l'agent.
