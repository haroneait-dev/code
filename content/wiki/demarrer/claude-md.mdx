Le fichier `CLAUDE.md` contient les **instructions permanentes** que Claude Code charge au début de chaque session : commandes de build, conventions, pièges du projet. C'est le levier le plus rentable pour éviter de répéter le même contexte à chaque conversation. À ne pas confondre avec [`settings.json`](/wiki/cli/settings-json), qui sert à la configuration technique (permissions, hooks, variables).

Point important : Claude traite `CLAUDE.md` comme du **contexte**, pas comme une règle imposée. Pour bloquer une action quoi qu'il arrive, utilisez un [hook](/wiki/hooks/introduction-hooks) `PreToolUse` ou une règle `deny`.

## Où placer les fichiers

| Portée | Emplacement | Usage |
|---|---|---|
| Organisation | `/Library/Application Support/ClaudeCode/CLAUDE.md` (macOS), `/etc/claude-code/CLAUDE.md` (Linux, WSL), `C:\Program Files\ClaudeCode\CLAUDE.md` (Windows) | Règles d'entreprise déployées par l'IT |
| Utilisateur | `~/.claude/CLAUDE.md` | Vos préférences pour tous les projets |
| Projet | `./CLAUDE.md` ou `./.claude/CLAUDE.md` | Consignes partagées avec l'équipe via git |
| Local | `./CLAUDE.local.md` | Vos réglages personnels sur ce projet (à mettre dans `.gitignore`) |

Comment ils se combinent :

- Claude Code charge les `CLAUDE.md` et `CLAUDE.local.md` du dossier courant **et de tous les dossiers parents**. Ils sont **concaténés**, pas remplacés : le fichier le plus proche du dossier de lancement est lu en dernier.
- Les `CLAUDE.md` des **sous-dossiers** ne sont chargés que lorsque Claude lit un fichier dans ces sous-dossiers.
- Les commentaires HTML (`<!-- note -->`) sont retirés avant l'envoi à Claude : pratique pour laisser des notes aux humains sans consommer de tokens.

Pour vérifier ce qui est réellement chargé, lancez `/context` et regardez la liste **Memory files**.

## Et AGENTS.md ?

Beaucoup de dépôts ont déjà un `AGENTS.md`, le format partagé par plusieurs agents de code. Depuis la version 2.1.277 (septembre 2026), Claude Code le lit directement :

| Fichiers présents | Ce que Claude lit |
|---|---|
| `AGENTS.md` seul | `AGENTS.md` |
| `AGENTS.md` et un `CLAUDE.md` (ou `CLAUDE.local.md`) | Les `CLAUDE.md` uniquement |
| Un `CLAUDE.md` qui importe `@AGENTS.md` | Les deux, sans doublon |

Ce comportement se règle dans `/config`, option **Project instructions** : `claude-md-or-agents-md` (par défaut), `claude-md-and-agents-md`, `claude-md` ou `managed-only`. Il est assuré par le plugin intégré `agents-md`, que vous pouvez désactiver dans `/plugin`.

Si vous utilisez plusieurs outils, gardez les consignes communes dans `AGENTS.md` et ajoutez un `CLAUDE.md` qui l'importe, suivi de ce qui est propre à Claude :

```markdown
@AGENTS.md

## Spécifique à Claude Code
- Lancer `npm run verify` avant chaque commit.
```

Piège fréquent : créer un `CLAUDE.local.md` dans un projet qui repose sur `AGENTS.md` suffit à faire ignorer `AGENTS.md`. Passez alors **Project instructions** à `claude-md-and-agents-md`.

## Importer d'autres fichiers

La syntaxe `@chemin/fichier` insère un autre fichier dans le contexte, au lancement :

```markdown
Voir @README.md pour la présentation et @package.json pour les scripts npm.

## Git
- Workflow : @docs/git-instructions.md
```

- Les chemins relatifs partent du fichier qui contient l'import.
- Les imports peuvent s'enchaîner sur **quatre niveaux** au maximum.
- Un `@chemin` placé entre backticks n'est pas importé.
- Un import qui pointe hors du projet déclenche une demande d'approbation la première fois.

Attention : un import **ne réduit pas** le coût en contexte, puisque le fichier importé est chargé dès le démarrage. Pour du contenu utile seulement par moments, préférez une règle par chemin ou un [skill](/wiki/skills/structure-skill).

## Les règles par chemin (`.claude/rules/`)

Dans un gros dépôt, découpez les consignes en fichiers thématiques dans `.claude/rules/`. Sans frontmatter, une règle est chargée à chaque session. Avec un champ `paths`, elle n'est chargée que lorsque Claude lit ou modifie un fichier correspondant :

```markdown
---
paths:
  - "src/api/**/*.ts"
---

# Règles API
- Valider toutes les entrées avec zod.
- Utiliser le format d'erreur standard de `lib/errors.ts`.
```

Vos règles personnelles valables pour tous les projets vont dans `~/.claude/rules/`.

## Que mettre dans un CLAUDE.md

La documentation officielle recommande de rester **sous 200 lignes par fichier** : au-delà, le contexte s'alourdit et Claude suit moins bien les consignes. Ajoutez une ligne quand Claude refait deux fois la même erreur, ou quand vous retapez la même correction d'une session à l'autre.

```markdown
# Mon SaaS

Application SaaS de gestion de tâches multi-tenants.

## Stack
- Next.js 16 App Router + TypeScript strict
- Supabase (Auth + Postgres + RLS)

## Commandes
- `pnpm dev` · `pnpm test` · `pnpm build`

## Conventions
- Composants en PascalCase dans `components/`
- Server Components par défaut ; `'use client'` seulement si nécessaire
- Pas de `any` : utiliser `unknown` si le type est inconnu

## À éviter
- Ne pas modifier `supabase/migrations/` à la main : passer par `pnpm db:migrate`
- Pas de `console.log` livré (utiliser `lib/logger.ts`)
```

| Section | Pourquoi elle rapporte |
|---|---|
| Commandes | Claude lance la bonne commande du premier coup |
| À éviter | Moins de régressions sur le code fragile |
| Conventions | Style cohérent dès la première écriture |
| Architecture | Moins de rappels sur l'organisation du code |

## Erreurs courantes

- **Trop long** : un fichier de plusieurs milliers de mots dilue les consignes. Déplacez le contenu ponctuel vers `.claude/rules/` ou des skills.
- **Trop vague** : « respecter les bonnes pratiques » n'aide pas. Écrivez « indentation de 2 espaces » ou « lancer `npm test` avant chaque commit ».
- **Contradictoire ou périmé** : deux consignes opposées font choisir Claude au hasard. La commande `/doctor prompt-audit` repère les instructions obsolètes, les fichiers inexistants et les contradictions, puis propose des corrections.
- **Doc pour humains** : `CLAUDE.md` s'adresse à Claude. L'explication du projet pour les développeurs reste dans le README.

## /init et /memory

- **`/init`** analyse le projet et génère un premier `CLAUDE.md` (ou propose des améliorations s'il existe déjà). Avec la variable `CLAUDE_CODE_NEW_INIT=1`, il pose des questions et peut aussi préparer skills et hooks.
- **`/memory`** liste vos fichiers de mémoire (utilisateur, projet, local), les ouvre dans votre éditeur et permet d'activer ou couper la mémoire automatique.

## La mémoire automatique

En plus de vos fichiers, Claude prend ses propres notes au fil des sessions : vos préférences, vos corrections, les décisions du projet. Elles sont stockées sur votre machine dans `~/.claude/projects/<projet>/memory/`, avec un index `MEMORY.md` dont les 200 premières lignes (ou 25 Ko) sont chargées à chaque session.

- Activée par défaut ; coupez-la via `/memory`, avec `"autoMemoryEnabled": false` dans les réglages, ou avec `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`.
- Ce sont des fichiers Markdown que vous pouvez relire, corriger ou supprimer.

Pour aller plus loin : [mémoire et oubli sélectif](/wiki/cli/memoire-oubli-selectif).

## La compaction du contexte

Une longue session accumule lectures de fichiers, sorties d'outils et impasses. Quand la conversation approche de la limite, Claude Code la **compacte** : il résume le passé pour libérer de la place. Sur les modèles à 1 million de tokens (Opus 5.5, Sonnet 5.5, Fable 5.1), cela se produit par défaut vers 967 000 tokens.

Vous pouvez :

- compacter vous-même avec `/compact`, en précisant éventuellement sur quoi le résumé doit insister ;
- avancer le seuil avec `/autocompact 500k` (enregistré pour le modèle courant) ou le réglage `autoCompactWindow` ;
- désactiver la compaction automatique avec `DISABLE_AUTO_COMPACT=1` ([variables d'environnement](/wiki/cli/variables-env)) ;
- **déléguer** les recherches lourdes à des [sous-agents](/wiki/subagents/creer-subagent-custom), qui travaillent dans leur propre contexte et ne renvoient qu'un résumé.

Une consigne donnée seulement dans la conversation peut disparaître à la compaction. Ce qui doit durer va dans `CLAUDE.md`.

## Contexte propre plutôt que gros contexte

Une grande fenêtre ne garantit pas de meilleures réponses : un contexte ciblé et structuré bat un contexte rempli de bruit. `CLAUDE.md` court, règles par chemin, skills chargés à la demande et sous-agents sont vos outils pour garder ce contexte propre. Voir aussi [Fenêtre de contexte et compaction](/wiki/modeles/contexte-200k).
