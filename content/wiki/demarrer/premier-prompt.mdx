Claude Code est installé et vous êtes connecté. Il est temps de l'essayer sur un vrai projet. Ce guide montre comment ouvrir une session, ce que vous voyez à l'écran et comment écrire une première demande qui produit un résultat exploitable dès le premier essai.

## Lancer une session

Ouvrez un terminal **à la racine de votre projet**, puis lancez `claude` :

```bash
cd ~/projets/mon-app
claude
```

Vous pouvez aussi passer la première demande directement en argument :

```bash
claude "explique-moi l'architecture de ce projet"
```

Au premier lancement, Claude Code ouvre le navigateur pour la connexion (voir [Authentification](/wiki/demarrer/authentification)). Il vous demande aussi si vous faites confiance au dossier : acceptez seulement pour un projet que vous connaissez.

> Lancez toujours Claude Code depuis la racine du projet. Il travaille dans le dossier courant et ses sous-dossiers, et charge le `CLAUDE.md` de ce dossier et des dossiers parents. S'il lui faut un autre dossier, ajoutez-le avec `/add-dir` ou `--add-dir`.

## Ce que vous voyez à l'écran

- **La zone de saisie** en bas : vous y tapez vos demandes. `Shift+Entrée` (après `/terminal-setup` dans certains terminaux) ou `\` puis `Entrée` insère un retour à la ligne.
- **L'indicateur de mode** : depuis la version 2.1.283, une nouvelle session démarre en mode `auto` (un classifieur vérifie chaque action à votre place). `Shift+Tab` fait défiler les modes ; le mode `Manual` vous demande votre accord avant chaque modification. Voir [Permissions et sandbox](/wiki/demarrer/permissions-sandbox).
- **La conversation** : les réponses de Claude et chaque appel d'outil (lecture de fichier, commande shell, modification) affichés au fil de l'eau.

Commandes à connaître dès le premier jour :

| Commande | Effet |
|---|---|
| `/help` | Liste les commandes disponibles |
| `/status` | Version, modèle, compte connecté |
| `/model` | Changer de modèle (Opus 5.5 par défaut) |
| `/clear` | Repartir d'une conversation vide |
| `/rewind` | Revenir en arrière (conversation et/ou fichiers) |
| `/usage` | Consommation de la session et limites du forfait |
| `/exit` | Quitter (ou `Ctrl+C` deux fois) |

`Échap` interrompt Claude en pleine action sans perdre la conversation. Tapez `/` seul pour voir toutes les commandes.

## Écrire une première demande utile

Le réflexe naturel est d'écrire « explique mon projet ». Le résultat sera vague. Une bonne demande dit **quoi lire**, **quoi produire** et **sous quelle forme** :

```text
Lis package.json et README.md, puis résume ce projet en 5 points :
stack technique, scripts disponibles, structure des dossiers,
et 2 améliorations que tu recommandes, avec le fichier concerné.
```

Pourquoi ça marche :

- **les fichiers à lire** sont nommés, Claude ne part pas à l'aveugle ;
- **le format** (5 points) cadre la réponse ;
- **les 2 améliorations avec le fichier concerné** demandent une analyse vérifiable, pas une description.

## Exemples par objectif

| Objectif | Exemple de demande |
|---|---|
| Découvrir un projet | « Lis le README et l'arborescence, puis explique l'architecture en 3 paragraphes. Ne modifie rien. » |
| Corriger un bug | « `npm test` échoue sur `auth.test.ts` avec cette erreur : [coller l'erreur]. Trouve la cause, propose un correctif, puis relance le test. » |
| Ajouter une fonctionnalité | « Ajoute une route GET `/api/health` qui renvoie `{ status: "ok" }`, en suivant les conventions des autres routes de `app/api`. » |
| Refactoriser | « `utils/db.ts` fait 400 lignes. Découpe-le en modules cohérents sans changer son API publique. Lance les tests à la fin. » |
| Documenter | « Rédige un `CONTRIBUTING.md` en français, dans le style du README. » |

## Donner le bon contexte

Claude Code lit seul les fichiers dont il a besoin, mais vous gagnez du temps en les désignant :

- tapez `@` suivi d'un chemin pour joindre un fichier ou un dossier (l'autocomplétion vous aide) ;
- citez les contraintes du projet : « TypeScript strict », « pas de nouvelle dépendance », « garde le style existant » ;
- collez le message d'erreur complet plutôt qu'un résumé ;
- dites comment vérifier : « lance `npm test` », « vérifie avec `npm run build` ».

```text
@src/api/users.ts @src/types/user.ts

Ajoute une fonction findByEmail(email: string) qui réutilise le client
Supabase déjà importé. Si l'utilisateur n'existe pas, renvoie null.
Ajoute un test dans __tests__/users.test.ts et lance-le.
```

Pour une tâche plus large, demandez d'abord un plan : `/plan ajoute la pagination à la liste des articles`. Claude explore et propose, sans rien modifier tant que vous n'avez pas validé.

## Avancer par petites étapes

Une session réussie ressemble à une conversation, pas à une commande unique. Commencez petit, lisez le résultat, puis affinez :

```text
1. « Liste les routes API du dossier app/api et leur rôle. »
2. « Ajoute une route POST /api/feedback sur le même modèle que /api/wiki,
    avec validation Zod. »
3. « Ajoute un test minimal pour cette route et lance-le. »
```

Si Claude part dans une mauvaise direction, appuyez sur `Échap` et reformulez. Si le résultat ne vous convient pas, `/rewind` restaure l'état d'avant.

## Quitter et reprendre

Pour quitter : `/exit` ou `Ctrl+C` deux fois. Pour reprendre plus tard :

```bash
claude -c          # reprend la dernière conversation de ce dossier
claude --resume    # ouvre la liste des sessions pour en choisir une
```

Donnez un nom à une session importante avec `/rename` ou `claude -n "refonte-auth"`, puis reprenez-la avec `claude --resume refonte-auth`.
