Claude Code s'utilise de deux façons. En **mode interactif**, vous dialoguez avec lui dans le terminal. En **mode non interactif** (`claude -p`), vous lui passez une demande, il travaille, affiche le résultat et rend la main : idéal pour les scripts, la CI et les tâches répétitives.

## Le mode interactif

C'est le mode par défaut :

```bash
claude
# ou avec une première demande
claude "explique le dossier src/auth"
```

Vous gardez la main pendant toute la session : vous voyez chaque fichier lu, chaque commande lancée, vous interrompez avec `Échap`, vous revenez en arrière avec `/rewind`. Choisissez-le pour :

- découvrir un projet ;
- une tâche qui demande des allers-retours (debug, conception) ;
- tout ce que vous voulez relire avant validation.

## Le mode non interactif : `claude -p`

Le flag `-p` (ou `--print`) exécute une demande puis quitte. La réponse sort sur la sortie standard, ce qui la rend utilisable dans un pipe :

```bash
claude -p "Liste les TODO du dossier src/ avec leur fichier et leur ligne"
```

Vous pouvez aussi envoyer des données sur l'entrée standard (10 Mo maximum) :

```bash
cat build-error.txt | claude -p "Explique la cause de cette erreur de build" > analyse.txt
git diff main | claude -p "Signale les fautes de frappe de ce diff, une par ligne"
```

Le code de sortie vaut 0 en cas de succès et une autre valeur en cas d'échec : vos scripts peuvent donc réagir.

## Comparaison rapide

| Critère | Interactif | Non interactif (`-p`) |
|---|---|---|
| Lancement | `claude` | `claude -p "<demande>"` |
| Interaction | Conversation, interruption, `/rewind` | Aucune pendant l'exécution |
| Sortie | Interface du terminal | Texte, JSON ou flux JSON sur stdout |
| Permissions | Mode `auto` par défaut (v2.1.283+), vous répondez aux demandes | Mode `default` le plus souvent ; ce qui demanderait une validation est refusé |
| Idéal pour | Développement, exploration | Scripts, CI/CD, cron |

## Formats de sortie

```bash
# Texte brut (par défaut)
claude -p "Résume ce projet"

# JSON : résultat dans .result, plus session_id, coût et métadonnées
claude -p "Résume ce projet" --output-format json | jq -r '.result'

# Flux JSON ligne par ligne (exige --verbose)
claude -p "Analyse le dossier logs/" --output-format stream-json --verbose
```

Le JSON contient notamment `result`, `session_id` et `total_cost_usd` (une estimation calculée côté client, qui peut différer de la facture).

Pour obtenir une sortie qui respecte un schéma précis, ajoutez `--json-schema` ; le résultat validé arrive dans `structured_output` :

```bash
claude -p "Extrais les noms des fonctions exportées de auth.ts" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}' \
  | jq '.structured_output'
```

## Gérer les permissions sans humain

Personne n'est là pour répondre aux demandes d'autorisation. Une action non autorisée est donc refusée et Claude continue sans elle. Pré-autorisez ce dont la tâche a besoin :

```bash
# Autoriser précisément quelques outils
claude -p "Lance les tests et corrige les échecs" \
  --allowedTools "Read,Edit,Bash(npm test *)"

# Accepter les modifications de fichiers, rien de plus
claude -p "Applique les corrections du linter" --permission-mode acceptEdits

# CI verrouillée : tout ce qui n'est pas explicitement autorisé est refusé
claude -p "Lance la suite de tests" --permission-mode dontAsk \
  --allowedTools "Bash(npm test)" "Read"

# Analyse sans aucune modification
claude -p "Audite la sécurité de ce dépôt" --permission-mode plan
```

Autres garde-fous utiles en script : `--max-turns 5` limite le nombre de tours, `--max-budget-usd 2.00` plafonne la dépense.

> N'utilisez `--dangerously-skip-permissions` (équivalent de `--permission-mode bypassPermissions`) que dans un conteneur ou une VM jetable, avec un utilisateur non root. Les règles `deny` s'appliquent toujours, mais plus rien d'autre ne vous protège.

## Démarrer vite et de façon reproductible : `--bare`

Par défaut, `claude -p` charge tout ce qu'une session interactive chargerait : `CLAUDE.md`, hooks, skills, serveurs MCP du projet et de `~/.claude`. En CI, le flag `--bare` ignore tout cela et démarre plus vite, avec le même comportement sur toutes les machines :

```bash
claude --bare -p "Résume README.md" --allowedTools "Read"
```

Attention : en mode `--bare`, Claude Code ne lit pas votre connexion par abonnement. Il faut `ANTHROPIC_API_KEY` (ou un `apiKeyHelper`). Ajoutez le contexte voulu par flags : `--append-system-prompt`, `--settings`, `--mcp-config`.

Autre point de sécurité : sans `--bare`, un `claude -p` lancé dans un dépôt inconnu exécute ses hooks et connecte ses serveurs MCP **sans** demande de confiance. N'utilisez pas `-p` sur un dépôt que vous n'avez pas relu.

## Enchaîner plusieurs appels

Chaque appel `-p` peut reprendre la conversation précédente :

```bash
claude -p "Passe en revue ce code pour les problèmes de performance"
claude -p "Concentre-toi maintenant sur les requêtes SQL" --continue

# Ou viser une session précise
session_id=$(claude -p "Démarre une revue" --output-format json | jq -r '.session_id')
claude -p "Poursuis cette revue" --resume "$session_id"
```

## Exemple : un message de commit généré

```bash
claude -p "Regarde mes changements indexés et crée un commit au format Conventional Commits" \
  --allowedTools "Bash(git diff *),Bash(git status *),Bash(git commit *)"
```

L'espace avant `*` compte : `Bash(git diff *)` autorise toute commande qui commence par `git diff `, alors que `Bash(git diff*)` couvrirait aussi `git diff-index`.

## Quand choisir quoi ?

**Interactif** quand vous découvrez un projet, quand la tâche demande des allers-retours ou quand vous voulez valider chaque étape.

**Non interactif** quand la tâche est bien définie, qu'elle revient souvent (cron, CI), que sa sortie doit alimenter un autre outil ou qu'aucun humain n'est présent.

Entre les deux existent aussi les sessions en arrière-plan (`claude --bg`, suivies avec `claude agents`) et les routines dans le cloud : voir [Agent view et sessions](/wiki/cli/agent-view-sessions).
