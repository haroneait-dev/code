Le fichier `~/.claude/settings.json` règle le comportement de Claude Code dans **tous vos projets** : modèle, permissions, variables d'environnement, hooks, thème, ligne de statut. Il ne remplace pas `CLAUDE.md`, qui donne des instructions au modèle : ici, vous configurez l'outil lui-même.

## Où sont les fichiers et qui gagne ?

| Niveau (du plus fort au plus faible) | Fichier | Portée |
|---|---|---|
| 1. Réglages gérés | `managed-settings.json`, MDM ou console d'administration claude.ai | Toute l'organisation, non modifiable |
| 2. Ligne de commande | `claude --settings '{...}'`, `--model`… | Cette session uniquement |
| 3. Projet local | `.claude/settings.local.json` | Vous, dans ce projet |
| 4. Projet partagé | `.claude/settings.json` | Toute l'équipe (committé) |
| 5. Utilisateur | `~/.claude/settings.json` | Vous, dans tous vos projets |

Deux règles à retenir :

- pour une clé simple (`model`, `theme`), **le niveau le plus haut gagne** ;
- pour les listes (`permissions.allow`, `permissions.deny`), **les niveaux s'additionnent**. Et un `deny` posé à n'importe quel niveau bloque, même si un autre niveau autorise.

Sous Windows, `~/.claude` correspond à `%USERPROFILE%\.claude`. Pour placer vos réglages ailleurs (ou séparer deux comptes), utilisez la variable `CLAUDE_CONFIG_DIR`.

### Et `~/.claude.json` ?

C'est un autre fichier, géré par Claude Code lui-même : connexion, serveurs MCP de portée utilisateur ou locale, décisions de confiance par projet, et quelques préférences d'interface (`verbose`, `autoConnectIde`, `diffTool`…). Vous n'avez normalement pas à l'éditer : passez par `/config` et `claude mcp add`.

## Modèle commenté

Les fichiers de réglages sont du **JSON strict** : pas de commentaires, pas de virgule finale. Les explications sont donc sous le bloc.

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "opus",
  "effortLevel": "high",
  "language": "french",
  "theme": "dark",
  "autoUpdatesChannel": "stable",
  "cleanupPeriodDays": 60,
  "env": {
    "EDITOR": "code --wait"
  },
  "permissions": {
    "defaultMode": "auto",
    "allow": [
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(gh pr view *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(~/.ssh/**)",
      "Read(~/.aws/**)"
    ]
  },
  "attribution": {
    "commit": "",
    "pr": ""
  },
  "hooks": {
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "afplay /System/Library/Sounds/Glass.aiff" }
        ]
      }
    ]
  }
}
```

| Clé | Rôle |
|---|---|
| `$schema` | Autocomplétion et validation dans VS Code, Cursor et tout éditeur compatible JSON Schema |
| `model` | Modèle des nouvelles sessions : alias (`opus`, `sonnet`, `haiku`) ou identifiant complet (`claude-opus-5-5`) |
| `effortLevel` | Effort par défaut : `low`, `medium`, `high` ou `xhigh` (`max` ne se règle que pour une session) |
| `language` | Langue des réponses de Claude |
| `theme` | Thème de l'interface |
| `autoUpdatesChannel` | `latest` (par défaut) ou `stable` (version d'environ une semaine, sans régression majeure) |
| `cleanupPeriodDays` | Durée de conservation des transcriptions de session |
| `env` | Variables d'environnement injectées dans chaque session et ses sous-processus |
| `permissions` | Mode de départ et règles `allow` / `ask` / `deny` |
| `attribution` | Texte ajouté aux commits et PR (une chaîne vide le masque) ; remplace l'ancien `includeCoAuthoredBy` |
| `hooks` | Commandes lancées à des moments précis (ici, un son quand Claude a fini) |

Autres clés utiles : `statusLine` (ligne de statut personnalisée), `outputStyle` (style de réponse), `spinnerTipsEnabled` (masquer les astuces), `editorMode` (`"vim"`), `sandbox` (voir [Permissions et sandbox](/wiki/demarrer/permissions-sandbox)), `apiKeyHelper` (voir [Authentification](/wiki/demarrer/authentification)), `enabledPlugins`, `fallbackModel`.

## Permissions globales : rester raisonnable

Au niveau utilisateur, mettez surtout des **interdictions** valables partout (secrets, clés SSH, identifiants cloud) et des autorisations pour des commandes en lecture seule. Les autorisations spécifiques à un projet (`npm run test *`, scripts maison) vont dans le `.claude/settings.json` du projet.

Attention aux chemins dans le fichier utilisateur : `Read(/secrets/**)` y désigne `~/.claude/secrets/**`, pas un dossier de votre projet. Utilisez `~/` ou `//` (chemin absolu) pour viser un emplacement précis.

## Variables d'environnement

Le bloc `env` évite de surcharger votre `~/.zshrc`. Exemples fréquents :

```json
{
  "env": {
    "HTTPS_PROXY": "http://proxy.example.com:8080",
    "NODE_EXTRA_CA_CERTS": "/chemin/vers/ca-entreprise.pem",
    "DISABLE_AUTOUPDATER": "1"
  }
}
```

Évitez d'y mettre une `ANTHROPIC_API_KEY` en clair : préférez `/login` ou un `apiKeyHelper` qui lit un gestionnaire de secrets. Liste complète : [Variables d'environnement](/wiki/cli/variables-env).

## Modifier sans se tromper

- **`/config`** ouvre un panneau pour les réglages personnels courants (thème, mode d'édition, canal de mise à jour…) et les enregistre au bon endroit. Forme directe : `/config theme=dark`.
- **`/permissions`** gère les règles sans éditer de JSON.
- **`/model`** change le modèle et l'enregistre comme défaut (touche `s` dans le sélecteur pour ne changer que la session en cours).
- **Pour tester sans rien écrire** : `claude --settings '{"model": "sonnet"}'`.

Claude Code recharge les fichiers modifiés en cours de session (permissions, hooks, `apiKeyHelper`). Exceptions : `model` et `effortLevel` sont lus au démarrage ; utilisez `/model` et `/effort` pour changer en cours de route.

## Vérifier ce qui est chargé

```text
/status
```

La ligne « Setting sources » liste les fichiers lus. Si un fichier contient une erreur de JSON, Claude Code l'annonce au démarrage (« Settings Error ») et propose de le corriger. En dehors d'une session, `claude doctor` liste les entrées rejetées.

## Bonnes pratiques

- Gardez le fichier court : seulement ce qui vaut pour tous vos projets.
- Ne committez jamais de secret, ni ici ni dans un fichier de projet.
- Sauvegardez `~/.claude/settings.json` (dépôt de dotfiles privé) pour retrouver votre configuration sur une autre machine.
- Relisez de temps en temps vos `.claude/settings.local.json` : les « don't ask again » s'y accumulent.
