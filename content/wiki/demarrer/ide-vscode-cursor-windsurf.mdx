Claude Code n'est pas réservé au terminal. Une extension officielle existe pour VS Code et ses forks (Cursor, Windsurf, Kiro…), un plugin pour les IDE JetBrains, et Zed l'intègre comme agent externe. Cette page explique comment installer chacun et comment relier le CLI à votre éditeur.

## Vue d'ensemble

| Éditeur | Intégration | Installation |
|---|---|---|
| VS Code (1.94 ou plus) | Extension officielle avec panneau graphique | Marketplace : `anthropic.claude-code` |
| Cursor | Même extension | Vue Extensions ou lien `cursor:extension/anthropic.claude-code` |
| Windsurf, Kiro et autres forks | Même extension | Registre Open VSX (`Anthropic/claude-code`) |
| IntelliJ, PyCharm, WebStorm, GoLand, PhpStorm, Android Studio | Plugin officiel (le CLI tourne dans le terminal de l'IDE) | JetBrains Marketplace, plugin « Claude Code » |
| Zed | Agent externe via le protocole ACP | Panneau agent de Zed, bouton `+`, « Claude Code » |
| N'importe quel éditeur | CLI dans le terminal intégré | `claude` |

## VS Code et ses forks

### Installer

Dans VS Code, ouvrez la vue Extensions (`Cmd+Shift+X` sur Mac, `Ctrl+Shift+X` sur Windows et Linux), cherchez « Claude Code » et installez l'extension publiée par Anthropic. En ligne de commande :

```bash
code --install-extension anthropic.claude-code
```

Dans Cursor, la même extension s'installe depuis sa vue Extensions. Dans Windsurf et les autres forks qui utilisent Open VSX, cherchez aussi « Claude Code ».

### Ouvrir Claude

L'icône Spark représente Claude Code partout dans l'éditeur :

- icône Spark en haut à droite de l'éditeur (quand un fichier est ouvert) ;
- icône Spark dans la barre d'activité à gauche (liste des sessions) ;
- **✻ Claude Code** dans la barre d'état en bas à droite ;
- palette de commandes (`Cmd+Shift+P`), tapez « Claude Code ».

Au premier lancement, cliquez sur **Sign in** et validez dans le navigateur. Un abonnement payant (Pro, Max, Team, Enterprise) ou un compte Console suffit, sans clé API.

### Ce que l'extension apporte

- **Diffs dans l'éditeur** : vous acceptez ou rejetez chaque modification proposée.
- **Contexte automatique** : Claude voit votre sélection et le fichier ouvert.
- **Revue de plan** : en mode plan, vous pouvez modifier le plan avant de l'accepter.
- **Plusieurs conversations** en onglets ou fenêtres séparés, avec historique.
- **Checkpoints** : survolez un message pour revenir en arrière (code, conversation, ou les deux).
- **Plugins et MCP** : gérés depuis le panneau (`/mcp`, gestion des plugins), partagés avec le CLI.

### Raccourcis utiles

| Action | Mac | Windows / Linux |
|---|---|---|
| Basculer le focus entre l'éditeur et Claude | `Cmd+Esc` | `Ctrl+Esc` |
| Nouvelle conversation dans un onglet | `Cmd+Shift+Esc` | `Ctrl+Shift+Esc` |
| Insérer une référence `@fichier#5-10` de la sélection | `Option+K` | `Alt+K` |
| Rouvrir la dernière session fermée | `Cmd+Shift+T` | `Ctrl+Shift+T` |

Sur macOS Tahoe et plus, `Cmd+Esc` peut être capturé par le raccourci système Game Overlay : désactivez-le dans les réglages clavier de macOS.

### Réglages de l'extension

Ouvrez les réglages (`Cmd+,`), section Extensions puis Claude Code. Les plus utiles :

```json
{
  "claudeCode.preferredLocation": "sidebar",
  "claudeCode.initialPermissionMode": "plan",
  "claudeCode.useCtrlEnterToSend": true,
  "claudeCode.attachOpenFile": true
}
```

Les permissions, hooks, variables d'environnement et serveurs MCP ne se règlent pas ici : ils vivent dans `~/.claude/settings.json` et `.claude/settings.json`, partagés avec le CLI. Voir [Configuration globale](/wiki/demarrer/config-globale).

### Extension ou CLI ?

L'extension couvre l'essentiel, mais certaines fonctions restent propres au CLI : toutes les commandes `/`, le préfixe `!` pour lancer une commande shell, la complétion par Tab. Pour les utiliser, ouvrez le terminal intégré (`` Ctrl+` ``) et lancez `claude`.

> L'extension embarque sa propre copie de Claude Code mais **n'ajoute pas `claude` à votre PATH**. Pour taper `claude` dans un terminal, installez le CLI séparément (voir [Installation](/wiki/demarrer/installation)).

Si vous préférez l'interface du CLI dans VS Code, cochez le réglage `claudeCode.useTerminal`.

## IDE JetBrains

Le plugin JetBrains ne contient pas le CLI : il lance `claude` dans le terminal de l'IDE et s'y connecte. Installez donc d'abord le CLI, puis le plugin « Claude Code » depuis le JetBrains Marketplace, et redémarrez l'IDE.

Ce que vous obtenez :

- `Cmd+Esc` (Mac) ou `Ctrl+Esc` pour ouvrir Claude Code ;
- les modifications affichées dans le visualiseur de diff de l'IDE ;
- la sélection et l'onglet actif partagés automatiquement ;
- `Cmd+Option+K` (Mac) ou `Alt+Ctrl+K` pour insérer une référence `@src/auth.ts#L1-99` ;
- les diagnostics de l'IDE (erreurs de lint, de syntaxe) lisibles par Claude.

Pour WSL, renseignez dans **Settings → Tools → Claude Code** une commande du type `wsl -d Ubuntu -- bash -lic "claude"`. En développement à distance, installez le plugin sur l'hôte distant.

## Zed

Zed exécute Claude Code comme agent externe via l'Agent Client Protocol (ACP). Ouvrez le panneau agent (`cmd-?` sur Mac, `ctrl-?` ailleurs), cliquez sur `+` et choisissez **Claude Code**. L'authentification est indépendante de celle de l'assistant intégré de Zed.

## Relier un terminal externe avec `/ide`

Si vous lancez `claude` dans un terminal séparé (iTerm, Ghostty, Windows Terminal), connectez-le à l'IDE ouvert :

```text
/ide
```

Claude Code confirme par un message du type `Connected to IntelliJ IDEA.` Lancez `claude` depuis la racine du projet ouvert dans l'IDE pour que les deux voient les mêmes fichiers. Dans `/config`, le réglage **Diff tool** choisit si les diffs s'affichent dans l'IDE (`auto`) ou dans le terminal (`terminal`).

## Sécurité

- Les éditeurs ont leur propre notion de dossier de confiance (« Workspace Trust » dans VS Code). N'accordez pas la confiance à un dépôt inconnu : ses hooks et réglages pourraient s'exécuter.
- Pour qu'un fichier sensible ne soit jamais partagé via la sélection ou le fichier ouvert, ajoutez une règle `Read(./.env)` en `deny` : elle bloque aussi ce partage automatique.
- En mode `acceptEdits` ou `auto`, Claude peut modifier des fichiers de configuration de l'IDE qui s'exécutent ensuite. Sur un projet sensible, préférez le mode Manual.
