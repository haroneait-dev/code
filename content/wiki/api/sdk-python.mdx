Le SDK Python officiel, `anthropic`, vous évite de gérer à la main les en-têtes, la sérialisation JSON, les retries et les types de réponse. Cette fiche couvre l'essentiel de la version 1.x : client, requêtes, options utiles, sorties structurées et erreurs.

## Installation

```bash
pip install anthropic
# ou, avec uv
uv add anthropic
```

La branche 1.x demande **Python 3.10 ou plus**. Extras utiles : `anthropic[aiohttp]` (client asynchrone à forte concurrence), `anthropic[bedrock]` et `anthropic[vertex]` (clouds partenaires).

> Vous migrez depuis 0.x ? Les changements principaux : la couche HTTP passe de `httpx` à `httpx2`, l'ancienne API Text Completions est supprimée, et `temperature`, `top_p`, `top_k` ne figurent plus dans la signature de `messages.create()`. Le guide officiel `MIGRATION.md` du dépôt détaille chaque point.

## Initialiser le client

```python
import anthropic

client = anthropic.Anthropic()            # lit ANTHROPIC_API_KEY
async_client = anthropic.AsyncAnthropic() # version asynchrone

# Réglages globaux
client = anthropic.Anthropic(
    timeout=60.0,     # secondes (défaut : 10 minutes)
    max_retries=4,    # défaut : 2
)
```

Créez le client une seule fois au démarrage et réutilisez-le. Le SDK relance automatiquement les erreurs de connexion, 408, 409, 429 et 5xx avec un backoff exponentiel, en respectant l'en-tête `retry-after`.

## Envoyer un message

```python
import anthropic

client = anthropic.Anthropic()

message = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=16000,
    system="Vous êtes un assistant pédagogique. Répondez en français.",
    messages=[{"role": "user", "content": "Expliquez la récursion en une phrase."}],
)

text = next(b.text for b in message.content if b.type == "text")
print(text)
print(message.stop_reason, message.usage.input_tokens, message.usage.output_tokens)
print(message._request_id)  # à fournir au support en cas de problème
```

`message.content` est une liste de blocs (`TextBlock`, `ThinkingBlock`, `ToolUseBlock`...). Testez toujours `block.type` avant de lire `.text`.

## Les paramètres qui comptent en 2026

```python
message = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=16000,
    output_config={"effort": "high"},          # low | medium | high | xhigh | max
    thinking={"type": "adaptive", "display": "summarized"},
    stop_sequences=["</fin>"],
    metadata={"user_id": "usr_7f3a"},          # identifiant opaque de l'utilisateur final
    messages=[{"role": "user", "content": "Compare REST et GraphQL."}],
)
```

- **`output_config.effort`** remplace l'ancien réglage de « budget de réflexion ». Sur Opus 5.5, le défaut est `medium` ; sur Sonnet 5.5, `high`.
- **`thinking`** : sur Opus 5.5 la réflexion est toujours active (`{"type": "disabled"}` renvoie une erreur 400). `display: "summarized"` renvoie un résumé lisible de la réflexion, sinon le bloc est vide.
- **`temperature`, `top_p`, `top_k`** : dépréciés. Les modèles sortis après Opus 4.6 refusent toute valeur autre que le défaut. Pilotez le style par le prompt.
- **Préremplissage (prefill)** : un dernier message `assistant` provoque une erreur 400 sur les modèles récents.

## Conversation multi-tours

L'API est sans état : vous renvoyez tout l'historique à chaque appel.

```python
history = [
    {"role": "user", "content": "Quel est le plus grand océan ?"},
]
reply = client.messages.create(model="claude-opus-5-5", max_tokens=4000, messages=history)

history.append({"role": "assistant", "content": reply.content})  # renvoyez les blocs tels quels
history.append({"role": "user", "content": "Et sa profondeur maximale ?"})
reply = client.messages.create(model="claude-opus-5-5", max_tokens=4000, messages=history)
```

Renvoyez `reply.content` sans le modifier : les blocs `thinking` sont signés, et toute modification provoque une erreur.

## Sorties structurées avec Pydantic

`messages.parse()` contraint la réponse à votre schéma et la valide :

```python
from pydantic import BaseModel
import anthropic

class Contact(BaseModel):
    nom: str
    email: str
    demo_demandee: bool

client = anthropic.Anthropic()
response = client.messages.parse(
    model="claude-opus-5-5",
    max_tokens=4000,
    messages=[{"role": "user", "content": "Jeanne Martin (jeanne@exemple.fr) veut une démo."}],
    output_format=Contact,
)
contact = response.parsed_output
print(contact.nom, contact.demo_demandee)
```

C'est la méthode recommandée pour extraire du JSON fiable. Pour donner des outils à Claude, utilisez le **tool runner** (`client.beta.messages.tool_runner` avec le décorateur `@beta_tool`), décrit dans l'article [Tool use](/wiki/api/tool-use).

## Gestion des erreurs

Interceptez les classes typées, de la plus spécifique à la plus générale :

```python
import anthropic

try:
    message = client.messages.create(
        model="claude-opus-5-5",
        max_tokens=4000,
        messages=[{"role": "user", "content": "Bonjour"}],
    )
except anthropic.BadRequestError as e:      # 400 : requête invalide, ne pas relancer
    print("Requête invalide :", e.message)
except anthropic.RateLimitError as e:       # 429 : déjà relancée par le SDK
    print("Limite atteinte :", e.response.headers.get("retry-after"))
except anthropic.APIStatusError as e:       # autres codes HTTP (dont 529)
    print(f"Erreur {e.status_code} :", e.message)
except anthropic.APIConnectionError:
    print("Problème réseau")
```

## Lire les en-têtes de réponse

```python
raw = client.messages.with_raw_response.create(
    model="claude-opus-5-5",
    max_tokens=1000,
    messages=[{"role": "user", "content": "Bonjour"}],
)
print(raw.headers.get("anthropic-ratelimit-input-tokens-remaining"))
message = raw.parse()
```

Sur le client asynchrone 1.x, `parse()` doit être attendu (`await raw.parse()`).
