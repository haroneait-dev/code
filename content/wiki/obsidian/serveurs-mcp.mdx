Le Model Context Protocol (MCP) permet à Claude d'utiliser des outils externes. Pour Obsidian, un serveur MCP donne à Claude un accès « à chaud » au vault pendant que l'application est ouverte : lecture, écriture, recherche, note active, commandes. Cette page explique comment l'installer pour Claude Code et Claude Desktop, et comment résoudre les problèmes courants.

> Pour la vue d'ensemble (fichiers directs, CLI officielle, MCP), voir [Obsidian et Claude : le guide complet](/wiki/obsidian/guide-complet).

## Quelle solution choisir ?

| Solution | Type | Transport | Pour qui |
|---|---|---|---|
| **Local REST API** (MCP intégré) | Plugin Obsidian | Streamable HTTP sur `https://127.0.0.1:27124/mcp/` | Recommandé : Claude Code et Claude Desktop |
| `mcp-obsidian` (MarkusPfundstein) | Serveur Python, via le plugin Local REST API | stdio | Si vous préférez un serveur stdio lancé par `uvx` |
| `obsidian-claude-code-mcp` (iansinnott) | Plugin Obsidian | WebSocket (Claude Code) et HTTP+SSE (Claude Desktop) | Connexion à Claude Code via `/ide` |

## Étape commune : installer le plugin Local REST API

1. Dans Obsidian, ouvrez **Paramètres → Modules complémentaires tiers** et activez-les si besoin.
2. Cliquez sur **Parcourir**, cherchez « Local REST API », installez puis activez le plugin.
3. Dans les réglages du plugin, copiez la **clé d'API**.

Par défaut, le plugin écoute en HTTPS sur le port **27124** (le port HTTP **27123** est optionnel et désactivé par défaut). Il crée sa propre autorité de certification au premier démarrage, limitée à `127.0.0.1` et `localhost`.

## Solution 1 : le serveur MCP intégré à Local REST API

Le plugin embarque désormais un serveur MCP qui tourne dans Obsidian et accède directement aux métadonnées du vault, à la note active et à la palette de commandes. Il expose une quinzaine d'outils : lister, lire, écrire, modifier partiellement, déplacer, copier et supprimer des notes, chercher, lister les tags, exécuter une commande Obsidian, ouvrir une note.

### Dans Claude Code

```bash
claude mcp add --transport http obsidian https://127.0.0.1:27124/mcp/ \
  --header "Authorization: Bearer <votre-cle-api>"
```

Par défaut, le serveur est enregistré pour le projet courant uniquement (portée `local`). Ajoutez `--scope user` pour l'avoir dans tous vos projets. Évitez `--scope project` : il écrirait la clé d'API dans `.mcp.json`, un fichier destiné à être versionné.

**Le certificat.** Claude Code doit faire confiance à l'autorité de certification du plugin. Téléchargez-la puis indiquez son chemin :

```bash
curl -k -o ~/obsidian-local-rest-api.crt https://127.0.0.1:27124/obsidian-local-rest-api.crt
export NODE_EXTRA_CA_CERTS=~/obsidian-local-rest-api.crt
claude
```

Vous pouvez aussi ajouter ce certificat au magasin de certificats de votre système : Claude Code le lit aussi (installeur natif, ou Node 22.15+ pour une installation npm). Autre option, moins sûre : activer le port HTTP 27123 et utiliser `http://127.0.0.1:27123/mcp/`.

Vérifiez ensuite avec `/mcp` dans Claude Code : le serveur `obsidian` doit apparaître comme connecté.

### Dans Claude Desktop

Claude Desktop passe par la passerelle `mcp-remote` (Node.js requis) :

```json
{
  "mcpServers": {
    "obsidian": {
      "command": "npx",
      "args": [
        "mcp-remote@latest",
        "https://127.0.0.1:27124/mcp/",
        "--header",
        "Authorization: Bearer <votre-cle-api>"
      ],
      "env": {
        "NODE_EXTRA_CA_CERTS": "/chemin/vers/obsidian-local-rest-api.crt"
      }
    }
  }
}
```

Redémarrez complètement Claude Desktop après chaque modification.

## Solution 2 : `mcp-obsidian` (serveur Python)

Un serveur stdio qui dialogue avec le plugin Local REST API. Il faut `uv` installé (pour `uvx`). Outils proposés : `list_files_in_vault`, `list_files_in_dir`, `get_file_contents`, `search`, `patch_content`, `append_content`, `delete_file`.

Dans Claude Code :

```bash
claude mcp add mcp-obsidian \
  -e OBSIDIAN_API_KEY=<votre-cle-api> \
  -e OBSIDIAN_HOST=127.0.0.1 \
  -e OBSIDIAN_PORT=27124 \
  -- uvx mcp-obsidian
```

Dans Claude Desktop :

```json
{
  "mcpServers": {
    "mcp-obsidian": {
      "command": "uvx",
      "args": ["mcp-obsidian"],
      "env": {
        "OBSIDIAN_API_KEY": "<votre-cle-api>",
        "OBSIDIAN_HOST": "127.0.0.1",
        "OBSIDIAN_PORT": "27124"
      }
    }
  }
}
```

`OBSIDIAN_HOST` et `OBSIDIAN_PORT` valent par défaut `127.0.0.1` et `27124` : vous pouvez les omettre.

## Solution 3 : `obsidian-claude-code-mcp` (plugin dédié)

Ce plugin implémente lui-même un serveur MCP, sur le port **22360** par défaut (modifiable ; un port différent par vault si vous en ouvrez plusieurs). Il fournit la note active et la structure du vault.

- **Claude Code** : lancez `claude`, tapez `/ide` et choisissez « Obsidian » dans la liste. La connexion WebSocket est automatique.
- **Claude Desktop** : passez par `mcp-remote` vers l'ancien transport HTTP+SSE.

```json
{
  "mcpServers": {
    "obsidian": {
      "command": "npx",
      "args": ["mcp-remote", "http://localhost:22360/sse"]
    }
  }
}
```

Ce plugin utilise volontairement le transport HTTP+SSE (spécification 2024-11-05), désormais déprécié au profit de Streamable HTTP. Préférez la solution 1 pour une nouvelle installation.

## Où se trouve la configuration de Claude Desktop ?

- **macOS** : `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows** : `%APPDATA%\Claude\claude_desktop_config.json`

Vous pouvez aussi l'ouvrir depuis Claude Desktop : **Paramètres → Développeur → Modifier la configuration**. Pour réutiliser dans Claude Code des serveurs déjà déclarés dans Claude Desktop : `claude mcp add-from-claude-desktop`.

## Et Claude sur le web ?

Les connecteurs personnalisés de claude.ai se connectent depuis les serveurs d'Anthropic : ils ne peuvent pas joindre un serveur qui écoute sur `127.0.0.1`. Pour Claude sur le web ou mobile, il faut un serveur MCP distant accessible par Internet, ce qui suppose d'exposer votre vault avec une authentification solide. Pour un usage local, restez sur Claude Code ou Claude Desktop.

## Dépannage

| Symptôme | Piste |
|---|---|
| `uvx` ou `npx` introuvable | Installez `uv` ou Node.js et vérifiez qu'ils sont dans le `PATH`. Sur macOS, Claude Desktop ne voit pas toujours le `PATH` du terminal : indiquez le chemin complet de la commande. |
| Erreur de certificat (`self-signed certificate`, `UNABLE_TO_VERIFY_LEAF_SIGNATURE`) | Configurez `NODE_EXTRA_CA_CERTS` avec le certificat du plugin, ou ajoutez-le au magasin système. |
| Erreur 401 | Clé d'API absente ou erronée dans l'en-tête `Authorization: Bearer ...`. |
| Connexion refusée | Obsidian est fermé, le plugin est désactivé ou le port est différent. |
| Claude n'utilise pas les outils | Vérifiez l'état avec `/mcp`, puis demandez explicitement « utilise les outils obsidian ». |
| Réponses tronquées sur de grosses notes | Augmentez `MAX_MCP_OUTPUT_TOKENS` (25 000 par défaut dans Claude Code). |
| Serveur lent à démarrer | Augmentez `MCP_TIMEOUT` (en millisecondes), par exemple `MCP_TIMEOUT=10000 claude`. |

Pour inspecter un serveur hors de Claude, utilisez MCP Inspector : `npx @modelcontextprotocol/inspector`. Les journaux MCP de Claude Desktop se trouvent dans `~/Library/Logs/Claude/` sur macOS et `%APPDATA%\Claude\logs\` sur Windows.
