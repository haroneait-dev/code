Un vault Obsidian n'est qu'un dossier de fichiers Markdown sur votre disque. Claude sait lire, écrire, relier et réorganiser ces fichiers. Ce guide présente les trois manières de connecter Claude à votre vault, quand choisir laquelle, et les précautions à prendre.

## Les trois approches en bref

| Approche | Ce qu'il faut | Points forts | Limites |
|---|---|---|---|
| **Fichiers directs** avec Claude Code | Claude Code, rien d'autre | Simple, puissant pour les gros chantiers | Ne voit pas l'état d'Obsidian (note active, index) |
| **CLI officielle + skills** | Obsidian 1.12.4 ou plus, CLI activée, skills `kepano/obsidian-skills` | Recherche et notes quotidiennes via Obsidian, syntaxe Obsidian maîtrisée | Obsidian doit être ouvert |
| **Serveur MCP** | Plugin Local REST API (MCP intégré) ou autre serveur | Accès « à chaud » depuis Claude Code et Claude Desktop | Configuration, clé d'API, certificat |

Le détail de la configuration MCP est dans [Serveurs MCP Obsidian](/wiki/obsidian/serveurs-mcp).

## Ce que Claude peut faire sur un vault

- **Restructurer** : renommer, déplacer, fusionner des notes, harmoniser titres et frontmatter YAML.
- **Créer des notes liées** avec des liens `[[...]]` corrects.
- **Construire des notes index** (MOC, *Maps of Content*) qui organisent un dossier ou un thème.
- **Chercher et synthétiser** : retrouver toutes les notes sur un sujet et en faire un résumé.
- **Repérer les notes orphelines** et proposer des liens.
- **Rédiger** à partir de vos notes, qui servent de matière première et de mémoire externe.

## Approche 1 : les fichiers directs avec Claude Code

Aucune installation spécifique : ouvrez Claude Code dans le dossier du vault.

```bash
cd ~/Documents/MonVault
claude
```

Exemples de demandes :

- « Liste les notes sans tag et propose des tags cohérents avec ceux qui existent déjà. »
- « Crée `Index - Productivité.md` qui relie toutes les notes du dossier `productivite/`, regroupées par thème. »
- « Repère les notes orphelines (aucun lien entrant) et propose trois liens pertinents pour chacune. »
- « Uniformise le frontmatter de toutes les notes : champs `title`, `date`, `tags`. Montre-moi d'abord le plan. »

### Donnez à Claude les règles de votre vault

Créez un fichier `CLAUDE.md` à la racine du vault. Claude Code le lit à chaque session.

```markdown
# Règles du vault

- Notes en français, titres en minuscules sauf noms propres.
- Frontmatter obligatoire : title, date (AAAA-MM-JJ), tags (liste).
- Liens internes au format [[Nom de la note]], jamais de liens Markdown vers des notes.
- Ne jamais modifier le dossier `templates/` ni `.obsidian/`.
- Notes quotidiennes dans `journal/AAAA-MM-JJ.md`.
```

Pour un remaniement important, démarrez en mode plan (`Shift+Tab` jusqu'à « plan », ou `claude --permission-mode plan`) : Claude propose ses changements avant d'y toucher.

**Limite** : Claude voit les fichiers, pas l'application. Il ignore la note ouverte, les résultats de recherche d'Obsidian ou les propriétés calculées. Un renommage fait hors d'Obsidian ne met pas à jour automatiquement les liens : demandez explicitement à Claude de corriger les `[[liens]]` concernés.

## Approche 2 : la CLI officielle d'Obsidian et les skills

Depuis la version **1.12.4 (27 février 2026)**, Obsidian propose une interface en ligne de commande. Activez-la dans **Paramètres → Général**, option « Command line interface » (libellé selon la langue de l'interface), puis suivez les instructions d'enregistrement. L'application doit être ouverte pour que la CLI fonctionne.

Quelques commandes :

```bash
obsidian search query="réunion client" limit=10
obsidian read file="Projet Alpha"
obsidian create name="Nouvelle idée" content="# Nouvelle idée" silent
obsidian append file="Projet Alpha" content="- Relancer le fournisseur"
obsidian daily:append content="- [ ] Préparer la démo"
```

Le créateur d'Obsidian, Steph Ango (kepano), publie un ensemble de **skills** officielles qui apprennent à Claude Code à utiliser cette CLI et les formats d'Obsidian : `obsidian-markdown` (liens, callouts), `obsidian-bases`, `json-canvas`, `obsidian-cli`, entre autres. Installation dans Claude Code :

```text
/plugin marketplace add kepano/obsidian-skills
```

Vous pouvez aussi copier le contenu du dépôt dans le dossier `.claude/` à la racine du vault. Ensuite, Claude choisit seul la bonne skill, ou vous l'appelez par son nom.

## Approche 3 : un serveur MCP

Un serveur MCP expose le vault « vivant » à Claude : note active, recherche d'Obsidian, commandes. C'est la voie à suivre pour **Claude Desktop**, qui n'a pas d'accès direct à vos fichiers, et utile dans Claude Code quand vous voulez interagir avec l'application ouverte.

La solution la plus simple aujourd'hui : le plugin communautaire **Local REST API**, qui intègre désormais son propre serveur MCP. Dans Claude Code :

```bash
claude mcp add --transport http obsidian https://127.0.0.1:27124/mcp/ \
  --header "Authorization: Bearer <votre-cle-api>"
```

Le pas-à-pas complet (certificat, Claude Desktop, alternatives, dépannage) est dans [Serveurs MCP Obsidian](/wiki/obsidian/serveurs-mcp).

## Laquelle choisir ?

| Objectif | Approche conseillée | Exemple de demande |
|---|---|---|
| Remaniement massif du vault | Fichiers directs | « Renomme les notes au format `AAAA-MM-JJ - titre` et corrige tous les liens. » |
| Nettoyage du frontmatter | Fichiers directs | « Uniformise les champs YAML et corrige les tags incohérents. » |
| Journal et tâches du jour | CLI + skills | « Ajoute à ma note du jour les trois tâches issues de cette réunion. » |
| Travail sur la note ouverte | MCP | « Crée une note pour chaque concept cité dans la note active et relie-les. » |
| Depuis Claude Desktop | MCP | « Trouve mes notes sur X et résume leurs points communs. » |

En résumé : **fichiers directs pour les gros chantiers**, **CLI et skills pour le quotidien**, **MCP pour Claude Desktop et le travail sur l'application ouverte**.

## Bonnes pratiques et sécurité

- **Versionnez le vault avec Git** (ou faites une sauvegarde) avant tout remaniement. C'est votre meilleur filet de sécurité.
- **Testez sur une copie** avant de lancer une opération de masse sur votre vault principal.
- **Gardez la clé d'API secrète.** Le serveur de Local REST API écoute en local (`127.0.0.1`) : ne l'exposez pas sur votre réseau ni sur Internet.
- **Excluez ce qui est sensible.** Rangez les notes privées dans un dossier que vous interdisez à Claude (règle dans `CLAUDE.md`, et règle `deny` dans les permissions de Claude Code si nécessaire).
- **Soyez explicite** : « utilise le vault Obsidian » ou « utilise les outils MCP obsidian » aide Claude à choisir les bons outils.
