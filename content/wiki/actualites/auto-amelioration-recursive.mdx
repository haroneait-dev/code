Le 4 juin 2026, Anthropic a publié *When AI builds itself*, un rapport signé Marina Favaro et Jack Clark. Il mesure la part que Claude prend déjà dans le développement des modèles suivants et pose la question de l'« auto-amélioration récursive ». Cet article résume les chiffres vérifiables, leurs limites et ce qu'un praticien peut en retirer.

## Claude écrit la majorité du code d'Anthropic

Selon le rapport :

- **Avant février 2025** (lancement de Claude Code en aperçu de recherche) : Claude écrivait une part « à un chiffre » du code fusionné chez Anthropic.
- **Mai 2026** : **plus de 80 %** du code fusionné dans la base de code d'Anthropic est rédigé par Claude.
- **T2 2026** : un ingénieur type fusionne environ **8 fois plus de code par jour** qu'en 2024.

Anthropic précise elle-même que le nombre de lignes est une mesure imparfaite (quantité plutôt que qualité) et que son système d'attribution du code a des trous.

Sur la qualité, la formulation est prudente : le code écrit par Claude était « un peu moins bon » que le code humain fin 2025, il est « à peu près à parité » au moment du rapport, et Anthropic s'attend à ce qu'il soit meilleur « dans l'année ». C'est une projection, pas un résultat.

> « 80 % du code » ne veut pas dire « 80 % du travail d'ingénierie ». Le choix des problèmes, l'architecture, la revue et la responsabilité restent humains.

## L'expérience d'optimisation : de 3× à 52×

Le test : on confie à l'agent le code qui entraîne un petit modèle, avec pour consigne de le rendre le plus rapide possible tout en passant les mêmes contrôles d'exactitude.

| Date | Modèle | Accélération moyenne |
|---|---|---|
| Mai 2025 | Claude Opus 4 | environ 3× |
| Avril 2026 | Claude Mythos Preview | environ 52× |
| Référence humaine | Chercheur qualifié, 4 à 8 heures | environ 4× |

Le périmètre est étroit : une tâche bien définie, avec un succès mesurable automatiquement. Le résultat ne dit rien de la recherche ouverte en général.

## Les autres indicateurs du rapport

- **Durée des tâches autonomes** : elle double environ tous les quatre mois (contre sept auparavant). Le rapport cite des tâches de quelques minutes pour Claude 3 Opus (mars 2024), environ 90 minutes pour Claude 3.7 Sonnet, et des tâches de l'ordre de 12 heures pour Claude Opus 4.6.
- **Recherche de sécurité menée par des agents** : sur un problème de supervision d'un modèle fort par un modèle faible, deux chercheurs humains ont récupéré environ 23 % de l'écart de performance en une semaine ; des agents Claude en ont récupéré 97 % en 800 heures cumulées (environ 18 000 $ de calcul). Anthropic note que le résultat ne s'est pas transposé proprement aux modèles de production et que les humains avaient choisi le problème et la grille d'évaluation.
- **Mise à jour du 18 septembre 2026** : un graphique ajouté suit le taux de réussite des sessions Claude Code d'août 2025 à septembre 2026. Les quatre types de tâches convergent vers 88 à 92 % ; les problèmes ouverts progressent le plus (d'environ 26 % à 91 %).

## La position d'Anthropic

Le rapport affirme : « nous n'y sommes pas encore » et l'auto-amélioration récursive « n'est pas inévitable ». Anthropic plaide en revanche pour :

- une coordination internationale qui garde la possibilité de **ralentir ou suspendre temporairement** le développement des modèles les plus avancés ;
- des mécanismes de vérification capables de constater qu'un laboratoire a réellement ralenti ;
- un débat associant décideurs publics, chercheurs et société civile.

Ces chiffres viennent d'évaluations internes, publiées par une entreprise partie prenante. Lisez-les comme un signal fort, pas comme une mesure indépendante.

## Ce que vous pouvez en retenir en pratique

1. **Déléguez ce qui se vérifie.** L'accélération spectaculaire porte sur des tâches où un test dit objectivement « c'est bon ». Avec Claude Code, une bonne suite de tests est ce qui rend la délégation sûre.
2. **Gardez la main sur le choix et la revue.** Même chez Anthropic, les humains choisissent les problèmes et définissent les critères de réussite.
3. **Mesurez votre propre usage.** Un pourcentage de code « écrit par l'IA » ne dit rien de la qualité. Suivez plutôt les régressions, le temps de revue et les incidents.
