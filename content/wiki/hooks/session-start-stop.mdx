Trois hooks rythment une session Claude Code : `SessionStart` à l'ouverture, `Stop` à la fin de chaque réponse et `SessionEnd` à la fermeture. Ils servent à injecter du contexte dynamique, à vérifier le travail avant de rendre la main et à ranger derrière soi.

## Qui se déclenche quand ?

| Événement | Fréquence | Peut bloquer ? | Usage typique |
|---|---|---|---|
| `SessionStart` | Démarrage, reprise, `/clear`, après compaction, fork | Non | Contexte git, variables d'environnement, titre de session |
| `Stop` | À chaque fin de réponse de Claude | Oui (force Claude à continuer) | Vérifier les tests, notifier |
| `StopFailure` | Fin de tour sur erreur d'API (à la place de `Stop`) | Non | Alerte rate limit, surcharge |
| `SubagentStop` | Fin d'un sous-agent | Oui | Contrôle qualité d'un sous-agent |
| `SessionEnd` | Fermeture de la session | Non | Archivage, arrêt de services |

`Stop` ne se déclenche pas sur une interruption de l'utilisateur (Échap). Les erreurs d'API déclenchent `StopFailure`, détaillé dans [Réagir aux erreurs](/wiki/hooks/erreurs-stopfailure).

## SessionStart : préparer le terrain

Le matcher filtre sur le champ `source` :

| Matcher | Quand |
|---|---|
| `startup` | Nouvelle session |
| `resume` | `--resume`, `--continue` ou `/resume` |
| `clear` | `/clear` |
| `compact` | Après une compaction automatique ou manuelle |
| `fork` | Session dérivée : `--fork-session`, `/fork`, `/branch`, passage en arrière-plan |

Seuls les types `command` et `mcp_tool` sont acceptés, et les hooks `mcp_tool` sont ignorés au lancement (les serveurs MCP ne sont pas encore prêts). L'entrée peut contenir `model` (pas toujours présent), `agent_type` si vous lancez `claude --agent`, et `session_title` si la session a un titre. Sur une reprise, Claude Code ajoute `seconds_since_last_response`, `context_tokens`, `prompt_cache_likely_expired` et `estimated_cache_write_usd`, utiles pour signaler le coût d'une vieille session.

Pour `SessionStart`, **le texte brut écrit sur stdout est ajouté au contexte de Claude**. Pas besoin de JSON pour un simple contexte :

```bash
#!/bin/bash
# .claude/hooks/session-context.sh
cd "$CLAUDE_PROJECT_DIR" || exit 0
echo "Branche courante : $(git branch --show-current 2>/dev/null)"
echo "Dernier commit : $(git log -1 --oneline 2>/dev/null)"
echo "Fichiers modifiés non commités : $(git status --porcelain 2>/dev/null | wc -l | tr -d ' ')"
exit 0
```

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume|compact",
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/session-context.sh",
            "args": []
          }
        ]
      }
    ]
  }
}
```

Le matcher `compact` est le bon moyen de réinjecter des consignes critiques après une compaction. Pour un contexte statique qui ne change jamais, `CLAUDE.md` reste préférable.

### Les sorties JSON de SessionStart

| Champ (`hookSpecificOutput`) | Effet |
|---|---|
| `additionalContext` | Texte ajouté au contexte avant le premier prompt |
| `sessionTitle` | Nomme la session (comme `/rename`) ; ignoré sur `clear` et `compact` |
| `initialUserMessage` | Premier message utilisateur, en mode `-p` uniquement |
| `watchPaths` | Chemins absolus à surveiller pour `FileChanged` |
| `reloadSkills` | `true` pour rescanner les skills installées par le hook |

```json
{
  "hookSpecificOutput": {
    "hookEventName": "SessionStart",
    "additionalContext": "Ticket actif : #4211 migration OAuth2",
    "sessionTitle": "auth-refactor"
  }
}
```

### Persister des variables d'environnement

`SessionStart` reçoit la variable `CLAUDE_ENV_FILE`. Ce que vous y écrivez est rejoué avant chaque commande `Bash` de la session :

```bash
#!/bin/bash
if [ -n "$CLAUDE_ENV_FILE" ]; then
  echo 'export NODE_ENV=development' >> "$CLAUDE_ENV_FILE"
  echo 'export PATH="$PATH:./node_modules/.bin"' >> "$CLAUDE_ENV_FILE"
fi
exit 0
```

Utilisez `>>` pour ne pas écraser les variables écrites par d'autres hooks.

### Performance

En session interactive, les hooks `SessionStart` tournent en arrière-plan au lancement : vous pouvez taper tout de suite, mais la première réponse de Claude attend leur fin. Un hook lent retarde donc chaque premier échange. Gardez-le sous la seconde.

## Stop : contrôler la fin d'un tour

L'entrée de `Stop` contient notamment :

- `stop_hook_active` : `true` si Claude continue déjà à cause d'un hook `Stop` ;
- `last_assistant_message` : le texte de la dernière réponse (plus fiable que la lecture du transcript, écrit de façon asynchrone) ;
- `background_tasks` et `session_crons` : les tâches de fond en cours et les réveils programmés, pour distinguer « session finie » de « session en attente ».

### Notifier la fin d'une réponse

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude a terminé\" with title \"Claude Code\"'"
          }
        ]
      }
    ]
  }
}
```

Sous Linux, remplacez par `notify-send 'Claude Code' 'Claude a terminé'`. `Stop` se déclenche à chaque réponse, même courte : préférez un signal discret, ou le hook [Notification](/wiki/hooks/notification) avec `idle_prompt` qui ne prévient qu'après une minute d'inactivité.

### Empêcher Claude de s'arrêter

Avec `decision: "block"` (ou `exit 2`), Claude reçoit la `reason` comme consigne et continue :

```bash
#!/bin/bash
INPUT=$(cat)

# Ne jamais boucler : si un hook Stop a déjà relancé Claude, on laisse finir
if [ "$(jq -r '.stop_hook_active' <<<"$INPUT")" = "true" ]; then
  exit 0
fi

cd "$CLAUDE_PROJECT_DIR" || exit 0
if ! npm test --silent >/dev/null 2>&1; then
  jq -n '{decision: "block", reason: "Des tests échouent. Lancez npm test, corrigez les échecs puis terminez."}'
fi
exit 0
```

Garde-fous intégrés : après huit relances consécutives par des hooks `Stop`, Claude Code ignore le blocage suivant et termine le tour (plafond réglable via `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`). Pour un retour non bloquant, renvoyez plutôt `hookSpecificOutput.additionalContext` : la conversation continue, mais le transcript l'affiche comme un retour de hook et non comme une erreur.

Pour un objectif du type « continue tant que les tests ne passent pas », la commande `/goal` crée un hook `Stop` à base de prompt pour la session, sans configuration (voir [/goal, /loop et Monitor](/wiki/cli/goal-loop-monitor)).

### Et les sous-agents ?

`SubagentStop` fonctionne comme `Stop` pour un sous-agent (outil `Agent`). Son entrée ajoute `agent_id`, `agent_type`, `agent_transcript_path` et `last_assistant_message`. Un `block` relance le sous-agent avec la `reason` comme consigne. Le matcher filtre sur le type d'agent (`Explore`, `Plan`, nom d'un agent personnalisé).

## SessionEnd : nettoyer derrière soi

Le matcher et le champ `reason` valent `clear`, `resume`, `logout`, `prompt_input_exit` ou `other`. `SessionEnd` ne peut rien bloquer et Claude Code ignore sa sortie JSON.

**Attention au délai : les hooks `SessionEnd` partagent un budget de 1,5 seconde.** Au-delà, ils sont annulés. Deux façons d'allonger :

- un `timeout` explicite sur le hook (le budget suit, jusqu'à 60 secondes) ;
- la variable `CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS`, par exemple `5000`.

```bash
#!/bin/bash
# .claude/hooks/archive.sh
INPUT=$(cat)
SESSION=$(jq -r '.session_id' <<<"$INPUT")
TRANSCRIPT=$(jq -r '.transcript_path' <<<"$INPUT")

mkdir -p "$HOME/.claude-archive"
[ -f "$TRANSCRIPT" ] && cp -- "$TRANSCRIPT" "$HOME/.claude-archive/$SESSION.jsonl"
exit 0
```

```json
{
  "hooks": {
    "SessionEnd": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/archive.sh",
            "args": [],
            "timeout": 5
          }
        ]
      }
    ]
  }
}
```

Pour un traitement long (upload, compression lourde), lancez un processus détaché depuis le hook plutôt que d'attendre.

## Une configuration complète

```json
{
  "hooks": {
    "SessionStart": [{ "matcher": "startup|resume|compact", "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/session-context.sh", "args": [] }] }],
    "Stop": [{ "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/check-tests.sh", "args": [] }] }],
    "SessionEnd": [{ "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/archive.sh", "args": [], "timeout": 5 }] }]
  }
}
```
