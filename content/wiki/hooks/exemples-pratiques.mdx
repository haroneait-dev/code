Voici trois hooks à copier dans `.claude/settings.json` qui couvrent les besoins les plus fréquents : qualité du code, sécurité et traçabilité. Chaque recette donne la configuration, le script complet et une façon de le tester. Elles supposent que `jq` est installé (`brew install jq`, `apt-get install jq`).

Placez les scripts dans `.claude/hooks/`, rendez-les exécutables (`chmod +x .claude/hooks/*.sh`) et versionnez-les pour que toute l'équipe en profite.

## 1. Formatage automatique après chaque édition

Dès que Claude écrit ou modifie un fichier, il est formaté avec l'outil du projet.

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/auto-format.sh",
            "args": [],
            "timeout": 30
          }
        ]
      }
    ]
  }
}
```

```bash
#!/bin/bash
# .claude/hooks/auto-format.sh
FILE=$(jq -r '.tool_input.file_path // empty')
[ -z "$FILE" ] || [ ! -f "$FILE" ] && exit 0

cd "$CLAUDE_PROJECT_DIR" || exit 0
case "$FILE" in
  *.ts|*.tsx|*.js|*.jsx|*.json|*.css|*.md)
    npx --no-install prettier --write -- "$FILE" >/dev/null 2>&1 ;;
  *.py)
    command -v ruff >/dev/null && ruff format -- "$FILE" >/dev/null 2>&1 ;;
  *.go)
    command -v gofmt >/dev/null && gofmt -w "$FILE" ;;
esac
exit 0
```

`--no-install` empêche `npx` de télécharger Prettier s'il manque, et le `exit 0` final garantit que le hook ne signale jamais d'erreur pour un simple formatage raté.

**Tester** : demandez à Claude d'ajouter une ligne avec des guillemets simples dans un fichier JavaScript. Avec la configuration par défaut de Prettier, ils deviennent des guillemets doubles.

**Limite** : ce hook ne voit que `Edit` et `Write`. Un fichier réécrit par un script lancé via `Bash` n'est pas formaté ; pour un fichier précis, l'événement `FileChanged` couvre ce cas.

## 2. Bloquer les secrets avant écriture

Ce `PreToolUse` lit le contenu que Claude s'apprête à écrire (`content` pour `Write`, `new_string` pour `Edit`) et bloque si un motif de secret apparaît.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/anti-secrets.sh",
            "args": [],
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

```bash
#!/bin/bash
# .claude/hooks/anti-secrets.sh
INPUT=$(cat)
FILE=$(jq -r '.tool_input.file_path // ""' <<<"$INPUT")
CONTENT=$(jq -r '(.tool_input.content // "") + "\n" + (.tool_input.new_string // "")' <<<"$INPUT")

# Les fichiers d'exemple peuvent contenir de faux secrets
case "$FILE" in *.example|*.sample|*/fixtures/*) exit 0 ;; esac

PATTERNS=(
  'AKIA[0-9A-Z]{16}'                                  # AWS Access Key
  'gh[pousr]_[A-Za-z0-9]{36,}'                        # Tokens GitHub
  'sk-ant-[A-Za-z0-9_-]{20,}'                         # Clés Anthropic
  'sk-(proj-)?[A-Za-z0-9_-]{32,}'                     # Clés de type OpenAI
  'xox[baprs]-[A-Za-z0-9-]{10,}'                      # Tokens Slack
  '-----BEGIN [A-Z ]*PRIVATE KEY-----'                # Clés privées
  'eyJ[A-Za-z0-9_-]{10,}\.eyJ[A-Za-z0-9_-]{10,}\.'    # JWT
)

for P in "${PATTERNS[@]}"; do
  if printf '%s' "$CONTENT" | grep -qE -- "$P"; then
    echo "Écriture bloquée : le contenu destiné à $FILE ressemble à un secret. Utilisez une variable d'environnement ou un fichier .env non versionné." >&2
    exit 2
  fi
done
exit 0
```

L'`exit 2` bloque l'appel et transmet le stderr à Claude, qui peut proposer une alternative (lecture depuis `process.env`, par exemple). Un `exit 1` laisserait passer l'écriture.

**Tester** sans Claude :

```bash
echo '{"tool_name":"Write","tool_input":{"file_path":"/tmp/a.ts","content":"const k = \"AKIAABCDEFGHIJKLMNOP\""}}' \
  | .claude/hooks/anti-secrets.sh; echo "code: $?"
# code: 2
```

**Limites** : une regex ne détecte que les formats connus et produit des faux positifs. Ce hook ne remplace pas un scanner en CI (gitleaks, trufflehog) ni la protection des fichiers `.env` par des règles de permission `deny`.

## 3. Journal d'audit JSONL

Un événement par ligne, facile à interroger avec `jq`. Utile pour la conformité ou pour comprendre après coup ce qu'a fait une session.

```json
{
  "hooks": {
    "UserPromptSubmit": [
      { "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/audit.sh", "args": ["prompt"] }] }
    ],
    "PreToolUse": [
      { "matcher": "*", "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/audit.sh", "args": ["pre"] }] }
    ],
    "PostToolUse": [
      { "matcher": "*", "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/audit.sh", "args": ["post"] }] }
    ],
    "PostToolUseFailure": [
      { "matcher": "*", "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/audit.sh", "args": ["fail"] }] }
    ]
  }
}
```

```bash
#!/bin/bash
# .claude/hooks/audit.sh <phase>
PHASE="${1:-unknown}"
LOG="$CLAUDE_PROJECT_DIR/.claude/audit.jsonl"

jq -c --arg ts "$(date -u +%Y-%m-%dT%H:%M:%SZ)" --arg phase "$PHASE" --arg user "$USER" '{
  ts: $ts, phase: $phase, user: $user,
  session: .session_id, prompt_id: .prompt_id, tool_use_id: .tool_use_id,
  agent: .agent_type, tool: .tool_name, cwd: .cwd,
  input: .tool_input, prompt: .prompt, error: .error, duration_ms: .duration_ms
} | with_entries(select(.value != null))' >> "$LOG"
exit 0
```

`tool_use_id` relie l'entrée `pre` à son `post` ou `fail`, et `prompt_id` relie tous les outils au prompt qui les a déclenchés. Ajoutez `.claude/audit.jsonl` au `.gitignore` : le journal contient vos prompts et les commandes exécutées.

Exploiter le journal :

```bash
# Toutes les commandes Bash du jour
jq -r --arg d "$(date -u +%F)" 'select(.tool == "Bash" and .phase == "pre" and (.ts | startswith($d))) | .input.command' .claude/audit.jsonl

# Top 10 des fichiers édités
jq -r 'select(.phase == "pre" and (.tool == "Edit" or .tool == "Write")) | .input.file_path' .claude/audit.jsonl \
  | sort | uniq -c | sort -rn | head

# Échecs d'outils
jq -c 'select(.phase == "fail") | {tool, error}' .claude/audit.jsonl
```

Les hooks d'un même événement tournent en parallèle et un sous-agent peut écrire en même temps : des lignes JSONL courtes ajoutées avec `>>` restent en pratique lisibles, mais pour un audit réglementaire, préférez la télémétrie OpenTelemetry native qui centralise ces données sans script.

## Combiner les trois

Les trois recettes cohabitent dans un même `settings.json` : fusionnez simplement les tableaux par événement. Les hooks qui correspondent au même événement s'exécutent en parallèle ; si l'anti-secrets bloque, l'entrée d'audit `pre` est tout de même écrite, ce qui est utile pour tracer la tentative.
