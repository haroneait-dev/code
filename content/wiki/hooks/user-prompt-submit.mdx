`UserPromptSubmit` se déclenche quand un prompt est soumis, avant que Claude ne le traite. Il sert à ajouter du contexte dynamique (branche git, ticket lié), à bloquer un prompt qui contient un secret, ou à journaliser les demandes. Il ne peut pas réécrire le prompt lui-même.

## Quand il se déclenche

Pas seulement quand vous tapez un message. Claude Code l'exécute aussi :

- quand une tâche programmée se déclenche, y compris une itération de `/loop` ;
- quand un sous-agent en arrière-plan rend compte à la session qui l'a lancé ;
- quand une autre session envoie un message à votre conversation.

Gardez cela en tête si votre hook bloque ou journalise : il verra passer des « prompts » que vous n'avez pas écrits.

L'événement n'accepte pas de `matcher` : il s'applique à chaque prompt. Pour réagir à une commande précise (`/deploy`, une skill), utilisez `UserPromptExpansion`, dont le matcher porte sur le nom de la commande.

## Le JSON reçu

```json
{
  "session_id": "abc123",
  "transcript_path": "/home/me/.claude/projects/.../transcript.jsonl",
  "cwd": "/home/me/projet",
  "permission_mode": "default",
  "hook_event_name": "UserPromptSubmit",
  "prompt": "Refactorise le module auth"
}
```

Le texte collé et replié en `[Pasted text #N]` arrive développé dans `prompt`. Le champ `session_title` est présent si la session a un titre personnalisé.

## Ce que le hook peut renvoyer

| Sortie | Effet |
|---|---|
| Texte brut sur stdout (exit 0) | Ajouté au contexte de Claude |
| `hookSpecificOutput.additionalContext` | Idem, au format JSON |
| `decision: "block"` + `reason` | Le prompt n'atteint pas Claude ; `reason` est montrée à **vous**, pas à Claude |
| `exit 2` + stderr | Même blocage, stderr affiché à l'utilisateur |
| `hookSpecificOutput.sessionTitle` | Nomme la session d'après le prompt |
| `hookSpecificOutput.suppressOriginalPrompt` | Retire le texte du prompt du message de blocage |

Le contexte ajouté n'apparaît pas comme un message dans l'interface : Claude le reçoit sous forme de rappel système qui commence par le nom du hook. Pour vérifier qu'il est bien injecté, consultez le journal de debug.

## Configuration de base

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/prompt-context.sh",
            "args": []
          }
        ]
      }
    ]
  }
}
```

**Délai par défaut : 30 secondes** (contre 600 pour la plupart des autres événements). Le hook bloque le traitement du prompt jusqu'à sa fin. S'il dépasse son `timeout`, il est annulé, son contexte est perdu et le prompt part quand même.

## Exemple 1 : injecter l'état git

```bash
#!/bin/bash
cd "$CLAUDE_PROJECT_DIR" || exit 0
BRANCH=$(git branch --show-current 2>/dev/null)
DIRTY=$(git status --porcelain 2>/dev/null | wc -l | tr -d ' ')

echo "Branche git : $BRANCH. Fichiers modifiés non commités : $DIRTY."
exit 0
```

Formulez le contexte comme des faits (« La branche est… ») plutôt que comme des ordres système. Un texte qui se présente comme une instruction hors bande peut déclencher les défenses de Claude contre l'injection de prompt.

## Exemple 2 : bloquer un prompt qui contient un secret

```bash
#!/bin/bash
INPUT=$(cat)
PROMPT=$(jq -r '.prompt' <<<"$INPUT")

if printf '%s' "$PROMPT" | grep -qE 'sk-ant-[A-Za-z0-9_-]{20,}|AKIA[0-9A-Z]{16}|ghp_[A-Za-z0-9]{36}|-----BEGIN [A-Z ]*PRIVATE KEY-----'; then
  jq -n '{
    decision: "block",
    reason: "Votre prompt semble contenir une clé ou un token. Retirez-le puis renvoyez le message.",
    hookSpecificOutput: {
      hookEventName: "UserPromptSubmit",
      suppressOriginalPrompt: true
    }
  }'
fi
exit 0
```

Sans `suppressOriginalPrompt`, le message de blocage se termine par `Original prompt:` suivi du texte, et il est écrit dans le transcript sur disque.

> Un hook bloquant n'efface pas le secret de votre machine : le texte peut rester dans l'historique des prompts et dans les fichiers de session. C'est une protection contre l'envoi au modèle, pas un outil de nettoyage. En cas de fuite, révoquez la clé.

## Exemple 3 : enrichir avec un ticket

Si le prompt cite un identifiant de ticket, le hook récupère son résumé. Le timeout court impose un appel réseau rapide :

```bash
#!/bin/bash
PROMPT=$(jq -r '.prompt')
TICKET=$(printf '%s' "$PROMPT" | grep -oE 'PROJ-[0-9]+' | head -1)
[ -z "$TICKET" ] && exit 0

SUMMARY=$(curl -s --max-time 5 -u "$JIRA_USER:$JIRA_TOKEN" \
  "$JIRA_BASE/rest/api/3/issue/$TICKET" | jq -r '.fields.summary // empty')

[ -n "$SUMMARY" ] && echo "Ticket $TICKET : $SUMMARY"
exit 0
```

Les identifiants `JIRA_*` viennent de votre environnement : ne les écrivez jamais dans un `settings.json` versionné.

## Exemple 4 : journal d'audit des prompts

```bash
#!/bin/bash
jq -c --arg ts "$(date -u +%FT%TZ)" --arg user "$USER" \
  '{ts: $ts, user: $user, session: .session_id, prompt_id: .prompt_id, prompt: .prompt}' \
  >> "$HOME/.claude/prompts-audit.jsonl"
exit 0
```

Le champ `prompt_id` correspond à l'attribut `prompt.id` de la télémétrie OpenTelemetry : vous pouvez relier ce journal aux événements natifs (voir [Hooks pour l'observabilité](/wiki/hooks/observabilite-otel)).

## UserPromptSubmit ou CLAUDE.md ?

| | `CLAUDE.md` | `UserPromptSubmit` |
|---|---|---|
| Chargement | Au début de la session | À chaque prompt |
| Contenu | Statique | Dynamique (git, date, API) |
| Coût en tokens | Une fois | À chaque tour |
| Peut bloquer | Non | Oui |

Règle pratique : les conventions stables vont dans `CLAUDE.md`, les informations qui changent d'un prompt à l'autre dans le hook. Le contexte injecté est rejoué tel quel lors d'un `--resume` (le hook n'est pas relancé pour les tours passés), donc une date ou un SHA peut devenir obsolète.

## Bonnes pratiques

- Gardez le hook rapide : il retarde chaque prompt.
- Mettez des `--max-time` sur les appels réseau et sortez en `exit 0` si le service ne répond pas.
- Testez vos regex de blocage sur de vrais prompts pour limiter les faux positifs.
- Gardez le contexte injecté court : il consomme des tokens à chaque tour. Au-delà de 10 000 caractères, Claude Code le remplace par un fichier et un aperçu des 2 000 premiers caractères.
