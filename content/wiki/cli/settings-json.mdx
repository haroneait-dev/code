`settings.json` configure le comportement de Claude Code : permissions, variables d'environnement, modèle, hooks, sandbox, plugins. Il ne contient pas d'instructions pour Claude : celles-ci vont dans [`CLAUDE.md`](/wiki/demarrer/claude-md).

## Les quatre fichiers (et les réglages gérés)

| Portée | Fichier | Qui est concerné | Pour quoi |
|---|---|---|---|
| Utilisateur | `~/.claude/settings.json` | Vous, dans tous vos projets | Thème, modèle par défaut, vos règles personnelles |
| Projet partagé | `.claude/settings.json` | Toute l'équipe (à commiter) | Permissions, hooks, plugins, `env` du projet |
| Projet local | `.claude/settings.local.json` | Vous, dans ce projet uniquement | Exceptions personnelles, tests avant partage |
| Géré | `managed-settings.json`, MDM ou console claude.ai | Toute l'organisation | Politique de sécurité et conformité |

Sous Windows, `~/.claude` correspond à `%USERPROFILE%\.claude`. La variable `CLAUDE_CONFIG_DIR` déplace tout le dossier.

Claude Code tient aussi `~/.claude.json`, qu'il écrit lui-même : connexion, serveurs MCP de portée utilisateur et locale, état par projet. Vous n'avez normalement pas à l'éditer.

## Quel réglage l'emporte

Du plus prioritaire au moins prioritaire :

1. **Réglages gérés** : rien ne les surcharge (hormis quelques clés de sécurité où la valeur la plus stricte gagne).
2. **Ligne de commande** : `--settings '{...}'`, `--model`, `--permission-mode`, pour la session en cours.
3. **Projet local** (`.claude/settings.local.json`).
4. **Projet partagé** (`.claude/settings.json`).
5. **Utilisateur** (`~/.claude/settings.json`).

Deux règles complètent cet ordre :

- **Les listes se cumulent.** `permissions.allow` défini dans trois fichiers donne l'union des trois.
- **Les variables d'environnement ne sont pas un niveau.** Chaque paire variable/clé a sa propre règle : `ANTHROPIC_MODEL` exportée dans votre shell l'emporte sur la clé `model` de n'importe quel fichier.

Pour vérifier ce qui est chargé, lancez `/status` : la ligne `Setting sources` liste les fichiers lus. `claude doctor` détaille les entrées rejetées.

## Autocomplétion avec `$schema`

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": ["Bash(npm run lint)", "Bash(npm run test *)"],
    "deny": ["Read(./.env)", "Read(./.env.*)"]
  }
}
```

Le schéma active l'autocomplétion dans VS Code, Cursor et tout éditeur compatible. Il peut avoir un léger retard sur les dernières versions. Attention : les fichiers sont du JSON strict. Un commentaire `//` ou une virgule finale provoque une « Settings Error » au démarrage.

## Le bloc `permissions`

```json
{
  "permissions": {
    "defaultMode": "acceptEdits",
    "allow": ["Bash(git status)", "Bash(git log *)", "Bash(npm run *)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Bash(rm -rf *)", "Read(./.env)", "Read(./secrets/**)"],
    "additionalDirectories": ["../shared-lib"]
  }
}
```

Points à retenir :

- **Ordre d'évaluation : deny, puis ask, puis allow.** Un `deny` large bloque même un `allow` plus précis.
- **Le joker s'écrit avec un espace** : `Bash(git log *)`. L'ancienne forme `Bash(git log:*)` reste acceptée, mais uniquement en fin de motif.
- **`defaultMode`** fixe le mode de départ (`default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`). Les valeurs `auto` et `bypassPermissions` sont ignorées dans les fichiers de projet : mettez-les dans vos réglages utilisateur.
- **La confiance du dossier** : les `allow` et la plupart des `env` d'un `.claude/settings.json` commité ne s'appliquent qu'après que chaque coéquipier a accepté de faire confiance au dossier. Les `deny` et `ask` s'appliquent immédiatement.

Le détail des modes est dans [Modes de permissions](/wiki/cli/permissions-modes).

## Le bloc `env`

```json
{
  "env": {
    "NODE_ENV": "development",
    "CLAUDE_CODE_MAX_OUTPUT_TOKENS": "64000"
  }
}
```

Ces variables s'appliquent à chaque session et à ses sous-processus (commandes Bash, hooks, serveurs MCP). Les valeurs sont des chaînes. Ne mettez pas de secret dans le fichier partagé : utilisez `settings.local.json` ou un gestionnaire de secrets. Liste complète : [Variables d'environnement](/wiki/cli/variables-env).

## Modèle et réponses

```json
{
  "model": "claude-opus-5-5",
  "effortLevel": "high",
  "outputStyle": "Explanatory",
  "language": "french"
}
```

- `model` : modèle de départ. `/model` change le modèle en cours de session et l'enregistre par défaut ; `--model` et `ANTHROPIC_MODEL` l'emportent sur la clé.
- `effortLevel` : niveau d'effort par défaut (`low`, `medium`, `high` ou `xhigh`). `max` et `auto` se choisissent avec `/effort` ou `--effort`.
- `outputStyle` : style de sortie ([Output styles](/wiki/cli/output-styles)).
- `language` : langue des réponses de Claude.

## Autres clés utiles

| Clé | Rôle |
|---|---|
| `hooks` | Déclarer des [hooks](/wiki/hooks/introduction-hooks) (`PreToolUse`, `Stop`, `SessionStart`...) |
| `statusLine` | Commande qui affiche une [barre d'état](/wiki/cli/status-line-custom) |
| `sandbox.enabled` | Isoler les commandes Bash (macOS, Linux, WSL2) |
| `enabledPlugins`, `extraKnownMarketplaces` | Plugins activés et marketplaces du projet |
| `enableAllProjectMcpServers` | Approuver tous les serveurs du `.mcp.json` du projet |
| `attribution` | Modifier ou masquer la mention Claude dans les commits et PR |
| `autoMemoryEnabled` | Activer ou couper la mémoire automatique |
| `cleanupPeriodDays` | Durée de conservation des transcriptions (30 jours par défaut) |
| `autoUpdatesChannel` | Canal de mise à jour `latest` ou `stable` |
| `theme` | `auto`, `dark`, `light` et variantes |

Les serveurs MCP eux-mêmes ne se déclarent pas dans `settings.json` : ils vont dans `.mcp.json` (projet) ou dans `~/.claude.json` via `claude mcp add`.

## Changer un réglage

- **Menu** : `/config` ouvre l'onglet Config (thème, mode d'édition, verbosité). `/config verbose=true` règle une option directement.
- **Fichier** : éditez le JSON. La plupart des changements (permissions, hooks) sont rechargés à chaud. `model` et `effortLevel` ne sont lus qu'au démarrage : utilisez `/model` et `/effort` en cours de session.
- **Pour une seule session** : `claude --settings '{"model": "claude-sonnet-5-5"}'` ou `claude --settings ./ci-settings.json`.

## Bonnes pratiques

- Commitez `.claude/settings.json` pour partager la configuration d'équipe.
- Laissez `.claude/settings.local.json` hors de git. Claude Code l'ajoute à vos exclusions git globales quand il le crée ; si vous le créez à la main, ajoutez-le vous-même au `.gitignore`.
- Préférez des règles précises (`Bash(npm run test *)`) à un `Bash` global.
- Bloquez la lecture des secrets avec des règles `deny` : tout ce qu'un outil lit finit en clair dans les transcriptions.
