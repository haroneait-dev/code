Claude Code est un « harness » agentique : une couche logicielle autour du modèle Claude qui lui fournit des outils, gère son contexte et applique vos permissions. Comprendre ces briques vous aide à mieux formuler vos demandes, à diagnostiquer un comportement inattendu et à savoir où agir (CLAUDE.md, réglages, hooks, MCP).

## La boucle agentique

La documentation officielle décrit trois phases qui s'enchaînent : **rassembler le contexte**, **agir**, **vérifier le résultat**. Techniquement, chaque tour suit ce schéma :

1. Le modèle reçoit la conversation, vos fichiers de mémoire et la liste des outils disponibles.
2. Il répond avec du texte et/ou des appels d'outils (`tool_use`).
3. Claude Code vérifie chaque appel contre vos règles de permission et votre mode, puis exécute l'outil sur votre machine.
4. Le résultat (`tool_result`) est ajouté à la conversation.
5. La boucle continue jusqu'à ce que le modèle réponde sans appel d'outil.

Vous faites partie de la boucle. `Esc` arrête immédiatement l'outil en cours. Si vous tapez un message pendant que Claude travaille, il est mis en file et lu dès la fin des appels d'outils en cours, sans interrompre le tour.

## Les outils intégrés

Les outils sont exécutés par Claude Code, pas par le modèle. Voici les plus utilisés :

| Outil | Rôle |
|-------|------|
| `Read` | Lire un fichier (texte, image, PDF, notebook) |
| `Edit` / `Write` | Modifier une portion de fichier / créer ou écraser un fichier |
| `Bash` (`PowerShell` sous Windows) | Exécuter une commande shell |
| `Glob` / `Grep` | Rechercher des fichiers et du contenu |
| `WebFetch` / `WebSearch` | Lire une page web, faire une recherche |
| `Agent` | Lancer un sous-agent avec sa propre fenêtre de contexte |
| `Skill` | Exécuter une skill dans la conversation |
| `TaskCreate`, `TaskUpdate`, `TaskList` | Gérer la liste de tâches de la session |
| `EnterPlanMode` / `ExitPlanMode` | Passer en mode plan et présenter le plan |
| `AskUserQuestion` | Vous poser des questions à choix multiples |
| `LSP` | Intelligence de code (définitions, références, erreurs de type) via un plugin |

Un détail surprend souvent : sur macOS, Linux et WSL, `Glob` et `Grep` ne font plus partie des outils par défaut. Claude cherche avec `find` et `grep` via `Bash` (des versions embarquées de `bfs` et `ugrep`). Vos hooks et règles de permission voient donc ces recherches comme des appels `Bash`. Sous Windows, les deux outils restent présents.

La liste complète (plus de 40 outils, dont `Monitor`, `Workflow`, `CronCreate`, `SendMessage`) est sur la page [Tools reference](https://code.claude.com/docs/en/tools-reference). Vous étendez ce socle avec des serveurs MCP, des skills, des sous-agents et des hooks.

## Ce que Claude voit de votre projet

Quand vous lancez `claude` dans un dossier, il a accès à :

- vos fichiers (et d'autres dossiers avec votre accord ou via `--add-dir`) ;
- votre terminal : tout ce que vous pouvez lancer en ligne de commande ;
- l'état git : branche, modifications non commitées, historique récent ;
- vos fichiers `CLAUDE.md` (ou `AGENTS.md` si le projet n'a pas de `CLAUDE.md`) ;
- la mémoire automatique : les 200 premières lignes ou 25 Ko de `MEMORY.md` sont chargés au démarrage ;
- les extensions configurées : serveurs MCP, skills, sous-agents.

## La fenêtre de contexte

Le contexte contient l'historique, le contenu des fichiers lus, les sorties de commandes, les instructions système, vos fichiers de mémoire et les skills chargées. Quelques mécanismes limitent son remplissage :

- **Les skills se chargent à la demande** : seule leur description est visible au démarrage.
- **Les outils MCP sont différés** : seuls leurs noms occupent de la place jusqu'à leur utilisation (tool search).
- **Les sous-agents travaillent dans leur propre contexte** et ne renvoient qu'un résumé.

Quand la limite approche, Claude Code efface d'abord les anciennes sorties d'outils, puis résume la conversation (compaction automatique). Les consignes données tôt dans la conversation peuvent se perdre : mettez vos règles durables dans `CLAUDE.md`.

```text
/context                          # grille d'occupation du contexte et suggestions
/compact focus sur l'API de paiement   # résumé orienté
/clear                            # nouvelle conversation, contexte vide
/usage                            # coût de la session et limites du forfait (/cost est un alias)
```

## Le démarrage d'une session

Au lancement, Claude Code :

1. charge les réglages, du moins prioritaire au plus prioritaire : `~/.claude/settings.json` (utilisateur), `.claude/settings.json` (projet partagé), `.claude/settings.local.json` (projet local), arguments de ligne de commande, puis réglages gérés par l'organisation (`managed-settings.json`, MDM ou console claude.ai), qui l'emportent sur tout ;
2. découvre `CLAUDE.md`, skills, sous-agents, hooks, plugins et serveurs MCP ;
3. s'authentifie : compte claude.ai (Pro, Max, Team, Enterprise), clé `ANTHROPIC_API_KEY` ou fournisseur cloud (Bedrock, Google Cloud, Microsoft Foundry) ;
4. ouvre l'interface interactive, ou exécute une seule requête avec `-p`.

Les réglages sont surveillés : la plupart des modifications (permissions, hooks) s'appliquent sans redémarrage. `/status` affiche la ligne `Setting sources` qui liste les fichiers effectivement chargés.

## L'outil Bash

Chaque commande tourne dans un processus séparé :

- un `cd` est conservé pour les commandes suivantes tant qu'il reste dans le projet (ou un dossier ajouté) ;
- un `export` n'est **pas** conservé d'une commande à l'autre ;
- vos alias et fonctions (`~/.zshrc`, `~/.bashrc`) sont capturés au démarrage et appliqués à chaque commande.

Pour qu'une variable soit disponible partout, déclarez-la dans le bloc `env` de `settings.json` plutôt que de compter sur un `export`.

## Stockage local

Tout est stocké en clair dans `~/.claude/` (déplaçable avec `CLAUDE_CONFIG_DIR`) :

| Chemin | Contenu |
|--------|---------|
| `~/.claude/settings.json` | Vos réglages utilisateur |
| `~/.claude.json` | Connexion, serveurs MCP, état par projet (géré par Claude Code) |
| `~/.claude/projects/<projet>/<session>.jsonl` | Transcription complète de chaque session |
| `~/.claude/projects/<projet>/memory/` | Mémoire automatique du projet |
| `~/.claude/file-history/<session>/` | Instantanés des fichiers pour `/rewind` |
| `~/.claude/plans/` | Plans écrits en mode plan |
| `~/.claude/history.jsonl` | Historique de vos prompts (flèche haut, `Ctrl+R`) |
| `~/.claude/plugins/` | Plugins installés |

`<projet>` est le chemin du dossier de travail où chaque caractère non alphanumérique devient `-`. Les transcriptions sont supprimées après `cleanupPeriodDays` (30 jours par défaut). Elles contiennent tout ce qui passe par un outil, y compris un `.env` lu par erreur : bloquez ces lectures avec une règle `deny`. `claude purge` efface les données d'un projet.

## Permissions et checkpoints

Deux filets de sécurité encadrent la boucle :

- **Les checkpoints** : avant chaque modification de fichier, Claude Code prend un instantané. `Esc` deux fois ou `/rewind` permet de revenir en arrière. Les commandes shell et les actions distantes (base de données, déploiement) ne sont pas couvertes.
- **Les modes de permission** : `auto` (classifieur qui bloque les actions risquées, mode de départ par défaut depuis la v2.1.283), `default` (affiché « Manual », demande avant éditions et commandes), `acceptEdits`, `plan`, `dontAsk` et `bypassPermissions`. `Shift+Tab` les fait défiler.

Quand vous répondez « Yes, and don't ask again » à une demande, la règle est enregistrée dans `.claude/settings.local.json`, que Claude Code exclut de git.
