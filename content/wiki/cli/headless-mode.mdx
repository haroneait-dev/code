Avec `-p` (ou `--print`), Claude Code s'exécute comme une commande Unix : il reçoit un prompt, travaille avec ses outils, écrit le résultat sur la sortie standard et se termine. C'est la base des scripts, des tâches planifiées et de la CI. Le même moteur existe en bibliothèque Python et TypeScript (Agent SDK) si vous avez besoin d'un contrôle plus fin.

## Les bases

```bash
claude -p "Que fait le module d'authentification ?"
```

- Code de sortie `0` en cas de succès, non nul en cas d'échec : votre script peut tester `$?`.
- Un flag invalide est signalé sur stderr avant le démarrage. Une erreur pendant l'exécution (authentification manquante, par exemple) apparaît comme résultat sur stdout.
- Les skills et commandes personnalisées fonctionnent : incluez `/nom-de-la-skill` dans le prompt. Les commandes purement interactives (`/login`) ne sont pas disponibles. `/model sonnet`, `/effort high` ou `/config cle=valeur` acceptent leur valeur en argument.

## Démarrer vite et de façon reproductible : --bare

Sans option, `claude -p` charge le même contexte qu'une session interactive : `CLAUDE.md`, hooks, skills, plugins, serveurs MCP, mémoire automatique. Résultat : le comportement dépend de la machine.

```bash
claude --bare -p "Résume README.md" --allowedTools "Read"
```

`--bare` ignore toute cette découverte automatique et démarre plus vite. Ce que vous voulez charger se passe en flags : `--append-system-prompt-file`, `--settings`, `--mcp-config`, `--agents`, `--plugin-dir`. Attention : en mode bare, Claude Code n'utilise ni votre connexion à un abonnement ni le trousseau système. Il faut `ANTHROPIC_API_KEY` (ou un `apiKeyHelper` dans `--settings`). La documentation annonce que `--bare` deviendra le comportement par défaut de `-p`.

Point de sécurité : sans `--bare`, un `claude -p` lancé dans un dépôt inconnu exécute ses hooks (`.claude/settings.json`) et connecte ses serveurs MCP (`.mcp.json`), sans boîte de dialogue de confiance. Utilisez `--bare` sur du code que vous n'avez pas vérifié.

## Les formats de sortie

| Format | Usage |
|---|---|
| `text` (défaut) | Texte brut, idéal pour rediriger dans un fichier |
| `json` | Un objet final : `result`, `session_id`, `total_cost_usd`, usage par modèle |
| `stream-json` | Un événement JSON par ligne, en temps réel |

```bash
claude -p "Résume ce projet" --output-format json | jq -r '.result'
```

### Sortie structurée avec JSON Schema

Pour obtenir des données exploitables plutôt que du texte libre :

```bash
claude -p "Extrais les noms des fonctions exportées de src/auth.ts" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}' \
  | jq '.structured_output.functions'
```

Le résultat validé se trouve dans `structured_output`. Un schéma invalide fait échouer la commande avec un message explicite.

### Streaming

```bash
claude -p "Explique la récursivité" \
  --output-format stream-json --verbose --include-partial-messages \
  | jq -rj 'select(.type == "stream_event" and .event.delta.type? == "text_delta") | .event.delta.text'
```

Le premier événement `system/init` décrit la session (modèle, outils, serveurs MCP, plugins chargés). Ses champs `plugin_errors` et `mcp_server_errors` permettent de faire échouer une CI quand un plugin ou un serveur ne se charge pas. La dernière ligne est le `result` final.

## Permissions sans personne pour répondre

En `-p`, personne ne peut cliquer sur « Oui ». Une action qui demanderait une confirmation est refusée. Choisissez donc explicitement ce qui est permis :

```bash
# Autoriser des outils précis (syntaxe des règles de permission)
claude -p "Crée un commit pour les changements indexés" \
  --allowedTools "Bash(git diff *),Bash(git status *),Bash(git commit *)"

# Fixer un mode de base
claude -p "Applique les corrections de lint" --permission-mode acceptEdits
```

| Mode | Comportement en `-p` |
|---|---|
| `acceptEdits` | Éditions de fichiers et commandes de fichiers courantes (`mkdir`, `mv`, `cp`) sans confirmation ; le reste exige une règle `allow` |
| `dontAsk` | Refuse tout ce qui demanderait une confirmation : idéal pour une CI verrouillée |
| `auto` | Un classifieur évalue chaque action et bloque les risquées |
| `bypassPermissions` | Aucun contrôle. À réserver à un conteneur jetable et isolé |

Sans mode explicite, le run démarre dans le mode par défaut, qui peut être `auto` : précisez toujours celui que vous voulez.

L'espace avant `*` compte : `Bash(git diff *)` autorise `git diff --stat`, alors que `Bash(git diff*)` autoriserait aussi `git diff-index`.

Pour une tâche planifiée sans aucun humain, ajoutez `--permission-prompts none` : Claude sait que personne ne peut approuver et ne réessaie pas. Les refus sont listés dans `permission_denials` du résultat.

## Garde-fous

```bash
claude -p "Corrige les tests qui échouent" \
  --permission-mode acceptEdits \
  --allowedTools "Bash(npm test *)" \
  --max-turns 15 \
  --max-budget-usd 2
```

- `--max-turns` : nombre maximal de tours agentiques, puis erreur.
- `--max-budget-usd` : plafond de dépense (sous-agents compris).
- `--model` et `--effort` : fixez-les pour des résultats et des coûts prévisibles.
- `--no-session-persistence` : n'écrit pas la session sur disque.

## Reprendre une conversation

```bash
session=$(claude -p "Commence une revue de performance" --output-format json | jq -r '.session_id')
claude -p "Concentre-toi maintenant sur les requêtes SQL" --resume "$session"
claude -p "Fais la synthèse des problèmes trouvés" --continue
```

`--resume` retrouve la session depuis n'importe quel dossier de la machine. Avec `--continue` ou `--resume`, le coût rapporté est le total de la conversation, runs précédents compris.

## Comportements à connaître

- **Entrée standard limitée à 10 Mo** : au-delà, écrivez dans un fichier et donnez son chemin dans le prompt.
- **Tâches d'arrière-plan** : un serveur lancé en arrière-plan est arrêté environ cinq secondes après le résultat. Un sous-agent d'arrière-plan, lui, est attendu (10 minutes d'inactivité au maximum).
- **SIGTERM** termine avec le code 143 sans finir le tour en cours ; SIGINT termine proprement le tour.
