Un output style est un jeu d'instructions qui fixe le rôle, le ton et le format de toutes les réponses de Claude pendant une session. Il évite de répéter « sois bref » ou « explique tes choix » à chaque prompt, et peut même transformer Claude en assistant de rédaction ou en analyste de données.

## Les styles intégrés

Claude Code démarre en style **Default** : ses instructions standard d'ingénierie logicielle, sans ajout. Quatre autres styles conservent ces instructions et ajoutent les leurs :

| Style | Ce qui change | Quand l'utiliser |
|---|---|---|
| **Proactive** | Claude se lance tout de suite et fait des hypothèses raisonnables au lieu de poser des questions de routine | Vous voulez avancer vite et corriger si besoin |
| **Concise** | La réponse commence par le résultat, sans préambule ni récapitulatif | Les réponses par défaut vous semblent trop longues |
| **Explanatory** | Claude ajoute de courts blocs `Insight` qui expliquent ses choix | Vous découvrez une base de code |
| **Learning** | En plus des `Insight`, Claude vous laisse écrire certains morceaux de code (`TODO(human)`) | Vous voulez pratiquer en codant |

Quelques précisions :

- **Concise** reste complet quand c'est nécessaire : erreurs, tests en échec, alertes de sécurité et confirmations d'actions destructrices.
- **Proactive** ne change pas votre mode de permission. Claude vous demande toujours confirmation dans la conversation avant de supprimer des données ou de toucher un système partagé.
- **Learning** s'arrête après avoir placé un `TODO(human)` : écrivez votre code, puis dites à Claude que c'est fait.

Un bloc `Insight` ressemble à ceci :

```text
★ Insight ─────────────────────────────────────
- Toutes les routes passent par withAuth : le nouvel endpoint hérite des contrôles de session.
- Les limites de débit sont définies route par route dans limits.ts.
─────────────────────────────────────────────────
```

## Changer de style

```text
/output-style              # liste les styles et marque l'actif
/output-style concise      # bascule (la casse n'importe pas ici)
```

Vous pouvez aussi passer par `/config` puis **Output style**. Ces deux méthodes enregistrent le choix dans `.claude/settings.local.json`. Le nouveau style s'applique dès votre message suivant.

Pour un style par défaut dans tous vos projets, mettez-le dans `~/.claude/settings.json` :

```json
{
  "outputStyle": "Explanatory"
}
```

Attention : dans les fichiers de réglages, **la valeur est sensible à la casse**. `"explanatory"` ne correspond à aucun style et vous laisse en Default sans message d'erreur. Écrivez `Proactive`, `Concise`, `Explanatory` ou `Learning`.

## Créer un style personnalisé

Un style personnalisé est un fichier Markdown avec un frontmatter. Emplacements possibles :

- utilisateur : `~/.claude/output-styles/` ;
- projet : `.claude/output-styles/` (à commiter pour l'équipe) ;
- réglages gérés par l'organisation ;
- plugin : dossier `output-styles/` du plugin.

Exemple : `.claude/output-styles/tuteur.md`

```markdown
---
name: Tuteur
description: Explique chaque étape à un développeur junior, en français
keep-coding-instructions: true
---

Vous travaillez en binôme avec un développeur junior qui apprend.

Pour chaque modification :
1. Expliquez pourquoi avant d'agir.
2. Indiquez le fichier et la fonction concernés.
3. Après la modification, résumez en deux phrases ce qu'il faut retenir.
4. Terminez par une petite suggestion d'exercice.

Restez exigeant sur la qualité : pas de raccourci dans les explications.
```

Champs du frontmatter (tous facultatifs) :

| Champ | Rôle |
|---|---|
| `name` | Nom affiché (par défaut : le nom du fichier) |
| `description` | Description affichée dans `/config` |
| `keep-coding-instructions` | `true` pour conserver les instructions d'ingénierie de Claude Code. Par défaut `false` |
| `force-for-plugin` | Pour un plugin : applique le style automatiquement quand le plugin est activé |

Le point essentiel est `keep-coding-instructions`. Sans lui, votre style **remplace** les consignes de Claude Code sur la façon de cadrer, commenter et vérifier le code. C'est voulu pour un style non technique (rédaction, analyse), mais rarement ce que vous voulez pour du développement.

Claude Code lit les fichiers de style au démarrage : après avoir créé ou modifié un style, relancez Claude Code.

## Idées de styles

- **Revue** : « N'écris pas de code. Critique, pose des questions, propose des alternatives. »
- **Commits** : « Après chaque série de modifications, propose un message de commit conventionnel dans un bloc de code. »
- **Rédaction** (sans `keep-coding-instructions`) : « Tu es éditeur technique francophone. Corrige le style, la typographie et la clarté des fichiers Markdown. »

## Output style, CLAUDE.md, skill ou hook ?

| Vous voulez | Utilisez |
|---|---|
| Un ton, une longueur ou un rôle pour toute la session | Un output style |
| Que Claude connaisse les conventions du projet | [CLAUDE.md](/wiki/demarrer/claude-md) |
| Une procédure pour un type de tâche (checklist de release) | Une [skill](/wiki/skills/structure-skill) |
| Une action garantie à chaque fois (formatage, blocage) | Un [hook](/wiki/hooks/introduction-hooks) |
| Un assistant avec ses propres outils et son contexte | Un [sous-agent](/wiki/subagents/creer-subagent-custom) |

Un output style reste une instruction : Claude la suit, mais rien ne la garantit. Il s'applique à la conversation principale et aux forks, pas aux autres sous-agents, qui ont leur propre prompt système.

## Coût

Les instructions du style s'ajoutent à chaque requête (le cache de prompt en absorbe l'essentiel). Explanatory et Learning produisent des réponses plus longues, donc plus de tokens de sortie ; Concise fait l'inverse.
