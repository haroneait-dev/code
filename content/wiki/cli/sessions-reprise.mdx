Une session est une conversation enregistrée et rattachée à un dossier de projet. Claude Code l'écrit sur disque au fil de l'eau : vous pouvez fermer le terminal, faire `/clear` ou subir un crash, puis reprendre exactement où vous en étiez.

## Reprendre une session

| Commande | Effet |
|---|---|
| `claude --continue` (`-c`) | Rouvre la conversation la plus récente du dossier courant |
| `claude --resume` (`-r`) | Ouvre le sélecteur de sessions |
| `claude --resume <nom>` | Reprend directement la session portant ce nom |
| `claude --resume <id>` | Reprend par identifiant, depuis n'importe quel dossier |
| `claude --resume <chemin.jsonl>` | Reprend depuis un fichier de transcription |
| `claude --from-pr 123` | Sélecteur filtré sur les sessions liées à la PR 123 |
| `/resume` | Change de conversation sans quitter Claude Code |

Les sessions lancées avec `claude -p` ou l'Agent SDK n'apparaissent ni dans le sélecteur ni dans `--continue`. Vous pouvez toujours les reprendre en passant leur identifiant à `--resume`.

## Ce qu'une reprise restaure

- **L'historique complet**, y compris les appels d'outils et leurs résultats. Un outil interrompu par un crash n'est pas relancé : Claude est prévenu qu'il doit vérifier s'il a eu lieu.
- **Le modèle** utilisé, sauf si vous imposez `--model` ou `ANTHROPIC_MODEL`.
- **Le mode de permission**, avec `--continue` ou `--resume <id|nom>` depuis le terminal. Exceptions : une session terminée en `bypassPermissions` ou en `plan` redémarre dans le mode par défaut. Depuis le sélecteur ou `/resume`, le mode n'est pas restauré.
- **Les tâches planifiées** non expirées et l'objectif `/goal` actif.

Ne sont **pas** restaurés : les flags `--mcp-config`, `--settings`, `--plugin-dir`, `--add-dir`, ni les dossiers ajoutés avec `/add-dir`. Repassez-les à la reprise si la session en dépend.

Sur une offre Pro ou Max, si la session est inactive depuis plus d'une heure environ et dépasse 100 000 tokens, une boîte de dialogue propose de reprendre depuis un résumé (moins coûteux par la suite) ou la session complète. Le cache de prompt a expiré : la première requête retraitera de toute façon tout l'historique.

## Nommer ses sessions

Un nom rend la session facile à retrouver et à reprendre :

```bash
claude -n refacto-auth            # nom donné au démarrage
claude --resume refacto-auth      # reprise par nom
```

En cours de session, `/rename refacto-auth` fait la même chose et affiche le nom dans la barre de saisie. Sans nom, Claude Code génère un titre à partir de votre premier prompt.

## Le sélecteur de sessions

`/resume` ou `claude --resume` sans argument ouvre un sélecteur. Raccourcis utiles :

| Touche | Action |
|---|---|
| `Space` | Aperçu de la session |
| `Ctrl+R` | Renommer |
| `/` ou une lettre | Rechercher (on peut coller l'URL d'une PR) |
| `Ctrl+B` | Filtrer sur la branche git courante |
| `Ctrl+W` | Afficher tous les worktrees du dépôt |
| `Ctrl+A` | Afficher tous les projets de la machine |

Chaque ligne indique l'ancienneté, la branche git et la taille du fichier.

## Brancher une conversation

Pour tester une autre piste sans perdre la conversation actuelle :

```text
/branch piste-streaming
```

`/branch` copie l'historique dans une nouvelle session et vous y place. L'original reste intact dans le sélecteur. Depuis la ligne de commande :

```bash
claude --continue --fork-session
```

À ne pas confondre avec `/fork`, qui copie la conversation dans une **session d'arrière-plan** (visible dans `claude agents`) pendant que vous continuez ici.

Évitez d'ouvrir la même session dans deux terminaux sans `--fork-session` : les messages des deux s'entremêlent dans une seule transcription.

## Où sont stockées les sessions

```text
~/.claude/projects/<projet>/<session-id>.jsonl
```

`<projet>` est le chemin du dossier de travail où chaque caractère non alphanumérique devient `-` (par exemple `-Users-marie-mon-app`). Conséquences :

- renommer ou déplacer le dossier fait « disparaître » ses sessions du sélecteur courant (`Ctrl+A` les retrouve) ;
- `/cd <chemin>` déplace la session en cours vers un autre dossier en conservant la conversation ;
- les sessions d'un sous-dossier sont rangées à part.

Chaque ligne du fichier est un objet JSON (message, appel d'outil, métadonnées). **Le format est interne et change d'une version à l'autre** : ne construisez pas d'outils qui le parsent directement.

## Exploiter une session depuis un script

Utilisez plutôt les interfaces prévues :

```bash
# Poser une question à une session existante et lire la réponse
claude -p --resume <session-id> --output-format json \
  "Résume ce que nous avons modifié" | jq -r '.result'
```

- `/export [fichier]` produit une transcription lisible en texte brut.
- Les hooks et la barre d'état reçoivent `transcript_path` en entrée : un hook `SessionEnd` peut archiver la transcription.

## Rétention et confidentialité

| Pour | Réglage |
|---|---|
| Changer la durée de conservation (30 jours par défaut) | `cleanupPeriodDays` dans `settings.json` |
| Déplacer le stockage | `CLAUDE_CONFIG_DIR` |
| Ne rien écrire du tout | `CLAUDE_CODE_SKIP_PROMPT_HISTORY` |
| Ne rien écrire pour un run `-p` | `--no-session-persistence` |
| Effacer les données d'un projet | `claude purge` |

Les transcriptions sont en clair : un secret lu par un outil y est écrit. Bloquez la lecture des `.env` avec une règle `deny`.

Synchroniser `~/.claude/projects/` entre machines (Dropbox, iCloud) est déconseillé : deux machines qui écrivent la même session corrompent l'historique. Pour passer d'un appareil à l'autre, préférez Remote Control ou les sessions cloud.

## Bonnes pratiques

- Nommez les sessions longues ou parallèles (`-n`, `/rename`).
- Utilisez `/clear` quand vous changez de sujet : l'ancienne conversation reste accessible via `/resume`.
- Brancher (`/branch`) coûte moins cher que de tout réexpliquer dans une nouvelle session.
- Mettez les décisions durables dans `CLAUDE.md` ou la mémoire automatique : chaque nouvelle session repart d'un contexte vide.
