Tout ce qui entre dans le contexte influence les réponses de Claude, coûte des tokens à chaque message et repousse le moment de la compaction. Savoir faire oublier est donc aussi utile que savoir faire retenir. Cet article distingue deux mémoires : le **contexte de la session** (volatil) et la **mémoire persistante** (`CLAUDE.md` et mémoire automatique, rechargées à chaque session).

## Voir ce qui occupe le contexte

```text
/context
```

`/context` affiche une grille d'occupation par catégorie (prompt système, outils, fichiers de mémoire, skills, messages) et suggère des optimisations : serveurs MCP lourds, `CLAUDE.md` trop long. C'est le point de départ avant de faire le ménage.

## Oublier toute la conversation : /clear

```text
/rename refacto-auth
/clear
```

`/clear` démarre une conversation vide. Il n'efface pas la mémoire persistante : `CLAUDE.md` et la mémoire automatique sont rechargés. L'ancienne conversation reste accessible avec `/resume`. Utilisez-le dès que vous changez de sujet.

## Résumer en gardant l'essentiel : /compact

```text
/compact Garde les décisions d'architecture et la liste des tests en échec ; oublie les essais ratés
```

`/compact` remplace l'historique par un résumé orienté par votre consigne. Pour orienter toutes les compactions (y compris automatiques), ajoutez une section à `CLAUDE.md` :

```markdown
# Compact instructions
Lors d'une compaction, conserve les décisions prises, les commandes de test et les erreurs non résolues.
```

Ce qui survit à une compaction :

| Élément | Après compaction |
|---|---|
| Prompt système, output style | Toujours appliqués |
| `CLAUDE.md` racine, mémoire automatique | Relus depuis le disque |
| Plan du mode plan | Réinjecté |
| Fichiers lus ou modifiés | Les 5 plus récents sont relus (au-delà de 5 000 tokens, seulement leur chemin) |
| Skills invoquées | Réinjectées, tronquées à 5 000 tokens chacune |
| `CLAUDE.md` des sous-dossiers, règles `paths:` | Rechargés quand Claude relit un fichier concerné |
| Consignes données seulement dans la conversation | Résumées, donc parfois perdues |

Pour déclencher la compaction automatique plus tôt : `/autocompact 500k` (seuil en tokens).

## Oublier une partie seulement : /rewind

`/rewind` (ou `Esc` deux fois) liste vos prompts. Choisissez-en un, puis :

- **Summarize from here** : résume tout ce qui suit ce point, en gardant intact le début (vos consignes initiales) ;
- **Summarize up to here** : résume ce qui précède et garde intacts les échanges récents ;
- **Restore conversation** : supprime tout ce qui suit, comme si cela n'avait jamais eu lieu.

C'est la méthode la plus précise pour se débarrasser d'une longue séance de débogage sans perdre le cadrage du début.

## Oublier un fichier précis

Il n'existe pas de commande `/forget fichier`. Tant que le contenu est dans le contexte, il pèse sur les réponses. Deux options :

```text
/compact Oublie le contenu de app/page.tsx ; relis-le seulement si nécessaire
```

ou bien `/rewind` jusqu'au prompt qui précède la lecture du fichier, puis « Restore conversation ».

## Empêcher certaines choses d'entrer

Le plus efficace reste d'éviter qu'un contenu n'entre dans le contexte.

**Règles `deny`** pour les fichiers sensibles ou inutiles :

```json
{
  "permissions": {
    "deny": ["Read(./.env)", "Read(./.env.*)", "Read(./dist/**)", "Read(./coverage/**)"]
  }
}
```

**Déléguer les lectures volumineuses** à un sous-agent : les logs, les gros fichiers et les recherches restent dans son contexte, seul un résumé revient.

**Filtrer avec un hook** : un hook `PreToolUse` peut réécrire une commande de test pour ne garder que les échecs, ou bloquer une lecture (code de sortie `2`, message sur stderr). Voir [PreToolUse et PostToolUse](/wiki/hooks/pre-post-tool-use).

**Alléger les outils** : coupez les serveurs MCP inutiles dans `/mcp`. Pour une skill que vous invoquez toujours à la main, `disable-model-invocation: true` retire sa description du contexte.

## La mémoire persistante

### CLAUDE.md

Vos instructions. Pour faire oublier durablement une règle, retirez-la du fichier : `/memory` liste et ouvre tous les fichiers chargés. Quelques leviers :

- **`claudeMdExcludes`** dans les réglages : ignorer certains `CLAUDE.md` (utile dans un monorepo où le fichier d'une autre équipe ne vous concerne pas) ;
- **règles ciblées** dans `.claude/rules/` avec un frontmatter `paths:` : chargées seulement quand Claude touche aux fichiers concernés ;
- **taille** : visez moins de 200 lignes. `/doctor` propose de supprimer ce que Claude peut déduire du code.

### La mémoire automatique

Claude y enregistre ce qu'il apprend : vos préférences, vos corrections, le contexte du projet. Elle se trouve dans `~/.claude/projects/<projet>/memory/` : un index `MEMORY.md` (200 premières lignes ou 25 Ko chargés à chaque session) et un fichier par sujet, lu à la demande.

Pour faire oublier quelque chose :

- ouvrez `/memory`, puis le dossier de mémoire automatique, et modifiez ou supprimez le fichier concerné ;
- ou demandez simplement à Claude : « Oublie ce que tu as retenu sur l'utilisation de npm, nous sommes passés à pnpm. »

Ces fichiers ne sont **pas** supprimés par le nettoyage automatique des transcriptions : ils restent jusqu'à ce que vous ou Claude les modifiiez. Une préférence obsolète peut donc persister longtemps. Relisez-les de temps en temps.

Pour désactiver la mémoire automatique : l'interrupteur dans `/memory`, `"autoMemoryEnabled": false` dans les réglages d'un projet, ou `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`.

## Récapitulatif

| Je veux oublier | Outil |
|---|---|
| Toute la conversation | `/clear` |
| Les détails, en gardant les conclusions | `/compact <consigne>` |
| Une portion de la conversation | `/rewind` puis Summarize ou Restore conversation |
| Un fichier lu par erreur | `/compact` ciblé ou `/rewind` |
| Un fichier, pour toujours | Règle `deny` |
| Une règle de projet | Modifier `CLAUDE.md` via `/memory` |
| Une préférence apprise | Supprimer le fichier de mémoire automatique |
