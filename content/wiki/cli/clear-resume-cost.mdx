Trois commandes suffisent à garder une session Claude Code rapide et économique : `/clear` pour repartir d'un contexte propre, `/resume` pour revenir à une conversation, `/usage` pour savoir ce que vous consommez. `/cost` existe toujours, mais c'est désormais un alias de `/usage`.

## Pourquoi le contexte coûte cher

Chaque requête renvoie au modèle toute la conversation : fichiers lus, sorties de commandes, échanges. Plus la session est longue, plus chaque message coûte cher et plus les consignes du début risquent de se diluer. Le cache de prompt réduit fortement le coût des parties répétées, mais il expire après une période d'inactivité.

## /clear : repartir d'un contexte vide

```text
/clear
/clear migration-db      # nomme la conversation que vous quittez
```

`/clear` démarre une nouvelle conversation avec un contexte vide. L'ancienne n'est pas supprimée : elle reste dans `/resume`, et le menu `/rewind` propose d'y revenir tant que vous n'avez pas quitté Claude Code. Vos fichiers `CLAUDE.md` et la mémoire automatique sont rechargés.

Utilisez-le dès que vous passez à une tâche sans rapport avec la précédente. Si vous voulez garder le fil mais alléger, préférez `/compact` :

```text
/compact Garde les décisions d'architecture et les tests qui échouent
```

Vous pouvez aussi ajouter une section « Compact instructions » dans `CLAUDE.md` pour orienter tous les résumés.

## /resume : revenir à une conversation

```text
/resume                  # sélecteur interactif
/resume migration-db     # reprise directe par nom
```

Depuis le shell : `claude --resume` (sélecteur), `claude --resume <nom|id>` ou `claude --continue` pour la plus récente. Le réflexe utile : `/rename` avant `/clear`, pour retrouver facilement la conversation plus tard.

Dans le sélecteur : `Space` pour un aperçu, `Ctrl+R` pour renommer, `Ctrl+B` pour filtrer sur la branche git, `Ctrl+A` pour voir tous les projets. Détails dans [Sessions et reprise](/wiki/cli/sessions-reprise).

## /usage : coût, cache et limites

`/usage` (alias `/cost` et `/stats`) regroupe plusieurs informations.

**Le bloc Session** donne le coût estimé de la session au prix public, la durée et le détail par modèle :

```text
Total cost:            $0.55
Total duration (API):  6m 20s
Total duration (wall): 6h 33m 10s
Total code changes:    0 lines added, 0 lines removed
Usage by model:
   claude-sonnet-5-5:  1.2k input, 5.3k output, 940.0k cache read, 50.0k cache write ($0.55)
```

Ce chiffre est utile si vous payez à l'usage (clé API). Avec un abonnement Pro ou Max, il n'a pas de valeur de facturation. Il repart de zéro après `/clear`.

**La ligne `Prompt cache (main)`** indique la part des tokens d'entrée servie par le cache, les échecs de cache (avec une cause probable) et si le cache est encore « chaud ». Un taux élevé signifie des requêtes beaucoup moins chères.

**Pour les abonnés** (Pro, Max, Team, Enterprise) : les barres de limites du forfait, et une répartition de la consommation par skill, sous-agent, plugin, serveur MCP et tâche `/loop`. `d` et `w` basculent entre 24 heures et 7 jours.

Commandes voisines :

- `/context` : grille d'occupation du contexte, avec des suggestions (outils MCP lourds, mémoire trop longue) ;
- `/insights` : rapport HTML sur vos habitudes d'utilisation et vos points de friction ;
- `/usage-credits` : activer ou demander des crédits pour dépasser la limite du forfait.

## Afficher la consommation en permanence

Une [barre d'état personnalisée](/wiki/cli/status-line-custom) peut afficher le coût de la session, le pourcentage de contexte utilisé et vos limites de forfait sans taper de commande.

## Réduire la consommation

| Levier | Comment |
|---|---|
| Vider entre deux tâches | `/rename`, puis `/clear` |
| Choisir le bon modèle | Sonnet pour l'essentiel, Opus pour les décisions complexes, `model: haiku` pour les sous-agents simples |
| Baisser l'effort | `/effort medium` ou `low` sur les tâches simples |
| Alléger `CLAUDE.md` | Moins de 200 lignes ; déplacer les procédures spécialisées dans des skills |
| Limiter MCP | Couper les serveurs inutiles avec `/mcp`, préférer `gh` ou `aws` en CLI |
| Déléguer le verbeux | Tests, logs et recherches dans un sous-agent qui ne renvoie qu'un résumé |
| Être précis | « Ajoute une validation à login() dans auth.ts » plutôt que « améliore le code » |

Sur Opus 5.5, Sonnet 5.5 et les modèles Fable, la réflexion étendue ne peut pas être désactivée : jouez sur le niveau d'effort.

## Une routine simple

1. Démarrez avec un objectif précis et nommez la session (`claude -n ma-tache`).
2. Surveillez le contexte dans la barre d'état ou avec `/context`.
3. `/compact` quand la session s'alourdit mais que le fil compte encore.
4. `/rename` puis `/clear` quand vous changez de sujet.
5. Le lendemain, `claude --resume ma-tache`.
