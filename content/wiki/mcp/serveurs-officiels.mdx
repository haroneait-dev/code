Le dépôt `modelcontextprotocol/servers` est souvent présenté comme « le catalogue officiel ». Ce n'est plus le cas : il ne contient plus qu'une poignée de **serveurs de référence**, maintenus par le comité de pilotage de MCP pour montrer comment utiliser le protocole et les SDK. Beaucoup de serveurs cités dans les tutoriels de 2025 (GitHub, Postgres, Puppeteer, Slack…) ont été archivés. Voici l'état réel en octobre 2026 et quoi installer à la place.

## Avant tout : ce sont des exemples

Le dépôt le dit clairement : ces serveurs sont des **implémentations de référence** à but pédagogique, **pas des solutions prêtes pour la production**. Évaluez vos propres besoins de sécurité avant de les utiliser sur des données sensibles.

Pour trouver un serveur prêt à l'emploi, deux annuaires :

- le **registre officiel MCP** : https://registry.modelcontextprotocol.io/ ;
- l'**Anthropic Directory** (connecteurs vérifiés par Anthropic) : https://claude.ai/directory. Tout serveur distant qui y figure s'ajoute à Claude Code avec `claude mcp add`.

## Les 7 serveurs de référence

| Serveur | Langage | Lancement | À quoi il sert |
|---|---|---|---|
| **Everything** | TypeScript | `npx -y @modelcontextprotocol/server-everything` | serveur de test qui exerce toutes les fonctions du protocole |
| **Fetch** | Python | `uvx mcp-server-fetch` | récupère une page web et la convertit en Markdown |
| **Filesystem** | TypeScript | `npx -y @modelcontextprotocol/server-filesystem <dossier>` | lecture et écriture dans des dossiers autorisés |
| **Git** | Python | `uvx mcp-server-git --repository <dépôt>` | status, diff, log, commit, branches |
| **Memory** | TypeScript | `npx -y @modelcontextprotocol/server-memory` | mémoire persistante sous forme de graphe |
| **Sequential Thinking** | TypeScript | `npx -y @modelcontextprotocol/server-sequential-thinking` | structure une réflexion en étapes révisables |
| **Time** | Python | `uvx mcp-server-time` | heure courante et conversion de fuseaux |

Les serveurs Python se lancent avec `uvx` (fourni par `uv`), les serveurs TypeScript avec `npx` (Node.js). Sous Windows, dans un fichier de configuration JSON, enveloppez `npx` dans `cmd /c`.

## Filesystem

Il donne accès à un ou plusieurs dossiers précis et refuse tout chemin en dehors.

```bash
claude mcp add fs -- npx -y @modelcontextprotocol/server-filesystem ~/Documents/notes
```

Outils principaux : `read_text_file`, `read_media_file`, `read_multiple_files`, `write_file`, `edit_file`, `create_directory`, `list_directory`, `directory_tree`, `move_file`, `search_files`, `get_file_info`, `list_allowed_directories`.

Chaque outil porte des annotations MCP (`readOnlyHint`, `destructiveHint`…) qui signalent au client les opérations à risque, comme `write_file` ou `move_file`.

**Dans Claude Code, vous n'en avez généralement pas besoin** : Claude lit et modifie déjà vos fichiers avec ses outils intégrés (Read, Edit, Write), sous le contrôle de vos permissions. Pour travailler sur un dossier hors du projet, `--add-dir` ou `/add-dir` suffit souvent. Filesystem reste utile dans Claude Desktop ou dans un client qui n'a pas d'accès disque.

## Git

```bash
claude mcp add git -- uvx mcp-server-git --repository /chemin/vers/depot
```

Outils : `git_status`, `git_diff_unstaged`, `git_diff_staged`, `git_diff`, `git_add`, `git_commit`, `git_reset`, `git_log`, `git_create_branch`, `git_checkout`, `git_show`, `git_branch`. Pas de `push` ni de `blame`. Le serveur est annoncé comme encore en développement précoce.

Comme pour Filesystem, Claude Code utilise déjà `git` via Bash. Ce serveur sert surtout aux clients sans terminal.

## Fetch

```bash
claude mcp add fetch -- uvx mcp-server-fetch
```

Un outil `fetch` avec `url`, `max_length` (5 000 caractères par défaut), `start_index` pour lire une longue page par morceaux, et `raw` pour obtenir le HTML brut. Il respecte `robots.txt` pour les requêtes venant du modèle (désactivable avec `--ignore-robots-txt`).

**Attention** : il peut joindre des adresses locales ou internes (`localhost`, réseau d'entreprise). Ne l'installez pas sur une machine qui a accès à des services sensibles. Claude Code dispose déjà de son outil WebFetch.

## Memory, Time, Sequential Thinking, Everything

- **Memory** : un graphe d'entités, de relations et d'observations stocké dans un fichier JSONL. Article dédié : [Le serveur MCP Memory](/wiki/mcp/serveur-memory).
- **Time** : `get_current_time` et `convert_time`, pratique pour planifier entre fuseaux horaires.
- **Sequential Thinking** : un outil `sequential_thinking` que le modèle appelle plusieurs fois pour découper un problème. Avec les modèles récents et leur réflexion intégrée (voir [Adaptive thinking et effort](/wiki/modeles/adaptive-thinking-effort)), son apport est souvent faible.
- **Everything** : à utiliser pour tester un client MCP ou apprendre le protocole avec [MCP Inspector](/wiki/mcp/debugging-inspector), pas pour travailler.

## Les serveurs archivés et leurs remplaçants

Ces serveurs ont quitté le dépôt principal (ils sont dans `modelcontextprotocol/servers-archived`) et ne sont plus maintenus. Plusieurs paquets npm sont marqués comme non supportés.

| Ancien serveur | Remplaçant conseillé | Ajout dans Claude Code |
|---|---|---|
| GitHub (`@modelcontextprotocol/server-github`) | serveur officiel de GitHub | `claude mcp add --transport http github https://api.githubcopilot.com/mcp/ --header "Authorization: Bearer VOTRE_PAT"` |
| PostgreSQL, SQLite | DBHub (`@bytebase/dbhub`), ou le serveur de votre hébergeur (Supabase, Neon…) | `claude mcp add db -- npx -y @bytebase/dbhub --dsn "postgresql://lecture:mdp@hote:5432/base"` |
| Puppeteer | Playwright MCP (Microsoft) | `claude mcp add playwright -- npx -y @playwright/mcp@latest` |
| Brave Search | serveur officiel de Brave (`@brave/brave-search-mcp-server`) | voir le README de Brave (clé API requise) |
| Sentry | serveur distant officiel de Sentry | `claude mcp add --transport http sentry https://mcp.sentry.dev/mcp` |
| Slack | repris par Zencoder, ou le connecteur Slack de claude.ai | selon l'option choisie |
| Google Drive, GitLab, Redis, Google Maps… | serveurs ou connecteurs des éditeurs | voir le registre officiel |

Pour la base de données, utilisez **un utilisateur en lecture seule** dans la chaîne de connexion : c'est la seule garantie fiable qu'une requête générée ne modifiera rien.

Pour GitHub, créez un jeton à grain fin limité aux dépôts utiles. Le serveur de GitHub existe aussi en version locale (image Docker `ghcr.io/github/github-mcp-server`).

## Construire le vôtre

Si aucun serveur ne couvre votre besoin, un serveur simple tient en quelques dizaines de lignes avec le SDK TypeScript ou Python. Claude Code peut même le générer pour vous avec le plugin officiel `mcp-server-dev` (`/plugin install mcp-server-dev@claude-plugins-official`, puis `/mcp-server-dev:build-mcp-server`).
