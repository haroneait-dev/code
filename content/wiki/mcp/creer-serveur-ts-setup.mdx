Un serveur MCP expose à Claude des **tools** (fonctions qu'il peut appeler), des **resources** (données à lire) et des **prompts** (modèles de messages). Ce guide construit un serveur stdio complet avec le SDK TypeScript officiel, dans sa version 2 sortie avec la révision 2026-07-28 du protocole.

## SDK v1 ou v2 : ce qui a changé

Le SDK TypeScript existe en deux générations. Les tutoriels publiés avant l'été 2026 utilisent presque tous la v1, ce qui crée des confusions.

| | v1 (maintenance) | v2 (stable, recommandée) |
|---|---|---|
| Paquet | `@modelcontextprotocol/sdk` | `@modelcontextprotocol/server` et `@modelcontextprotocol/client` |
| Imports | `@modelcontextprotocol/sdk/server/mcp.js` | `@modelcontextprotocol/server` |
| Lancement stdio | `new StdioServerTransport()` + `server.connect()` | `serveStdio(factory)` |
| Schémas | Zod 3 ou 4, objet « brut » `{ a: z.string() }` | Standard Schema : Zod 4, Valibot, ArkType… (`z.object({...})`) |
| Protocole | révisions 2025 (`initialize`) | 2026-07-28 et révisions 2025 (clients anciens servis automatiquement) |

La v1 reçoit encore des correctifs de sécurité pendant au moins six mois après la sortie de la v2. Pour un nouveau projet, partez sur la v2. Pour migrer un projet v1, le codemod officiel fait l'essentiel du travail :

```bash
npx @modelcontextprotocol/codemod@latest v1-to-v2 .
```

## Initialiser le projet

Il vous faut Node.js 20 ou plus. Le SDK est publié uniquement en modules ES, d'où le `type=module`.

```bash
mkdir mcp-devises && cd mcp-devises
npm init -y
npm pkg set type=module
npm install @modelcontextprotocol/server zod
npm install -D typescript tsx @types/node
mkdir src
```

`tsx` exécute le TypeScript directement pendant le développement. Ajoutez ces scripts dans `package.json` :

```json
{
  "type": "module",
  "scripts": {
    "dev": "tsx src/index.ts",
    "build": "tsc",
    "inspect": "npx @modelcontextprotocol/inspector npx tsx src/index.ts"
  }
}
```

## Le squelette : une factory et `serveStdio`

En v2, vous écrivez une **factory** : une fonction qui construit et renvoie un `McpServer`. Le point d'entrée (`serveStdio` ici, `createMcpHandler` en HTTP) l'appelle pour créer l'instance qui sert la connexion.

```ts
// src/index.ts
import { McpServer, ResourceTemplate } from "@modelcontextprotocol/server";
import { serveStdio } from "@modelcontextprotocol/server/stdio";
import * as z from "zod/v4";

function createServer(): McpServer {
  const server = new McpServer({ name: "devises", version: "0.1.0" });

  // tools, resources et prompts ici (voir les sections suivantes)

  return server;
}

serveStdio(createServer);
console.error("Serveur MCP devises prêt sur stdio");
```

Point crucial : en stdio, **stdout est le canal du protocole**. Un seul `console.log` corrompt le flux JSON-RPC. Écrivez vos logs avec `console.error` (stderr).

## Exposer un tool

Un tool est une fonction que le modèle décide d'appeler. `registerTool` prend un nom, une configuration et un handler asynchrone. Le schéma Zod sert trois fois : il produit le JSON Schema envoyé au client, il valide les arguments avant l'appel du handler, et il type ces arguments.

```ts
const TAUX: Record<string, number> = { EUR: 1, USD: 1.08, GBP: 0.85, CHF: 0.94 };

server.registerTool(
  "convertir_devise",
  {
    title: "Conversion de devise",
    description:
      "Convertit un montant entre deux devises (EUR, USD, GBP, CHF). Taux indicatifs.",
    inputSchema: z.object({
      montant: z.number().min(0).describe("Montant à convertir"),
      de: z.string().length(3).describe("Code ISO de la devise source, ex. EUR"),
      vers: z.string().length(3).describe("Code ISO de la devise cible, ex. USD"),
    }),
    outputSchema: z.object({ resultat: z.number(), devise: z.string() }),
    annotations: { readOnlyHint: true, idempotentHint: true },
  },
  async ({ montant, de, vers }) => {
    const a = TAUX[de.toUpperCase()];
    const b = TAUX[vers.toUpperCase()];
    if (a === undefined || b === undefined) {
      return {
        content: [
          { type: "text", text: `Devise inconnue. Devises prises en charge : ${Object.keys(TAUX).join(", ")}` },
        ],
        isError: true,
      };
    }
    const resultat = Math.round((montant / a) * b * 100) / 100;
    return {
      content: [{ type: "text", text: `${montant} ${de} = ${resultat} ${vers}` }],
      structuredContent: { resultat, devise: vers.toUpperCase() },
    };
  }
);
```

Ce qu'il faut retenir :

- **`description`** : c'est ce que Claude lit pour choisir le tool. Soyez précis sur ce qu'il fait et ses limites.
- **`isError: true`** : l'erreur arrive au modèle comme un résultat lisible, avec un indice pour corriger (ici, la liste des devises). Une exception levée devient au contraire une erreur de protocole que le modèle ne voit pas.
- **`outputSchema` + `structuredContent`** : un résultat exploitable par programme, validé par le SDK avant l'envoi. Gardez quand même un bloc `text` lisible.
- **`annotations`** : des indices pour le client (`readOnlyHint`, `destructiveHint`, `idempotentHint`). Ils ne changent pas l'exécution.

## Exposer une resource

Une resource est une donnée en lecture seule, identifiée par une URI. C'est l'application (le client) qui décide de la charger, pas le modèle. Dans Claude Code, l'utilisateur la mentionne avec `@`.

```ts
server.registerResource(
  "taux",
  "devises://taux",
  { title: "Taux de change", description: "Table des taux utilisés", mimeType: "application/json" },
  async (uri) => ({
    contents: [{ uri: uri.href, mimeType: "application/json", text: JSON.stringify(TAUX) }],
  })
);
```

Pour une famille de resources, utilisez un `ResourceTemplate`. La clé `list` est obligatoire : passez `undefined` si les instances ne sont pas énumérables, ou une fonction qui renvoie la liste.

```ts
server.registerResource(
  "devise",
  new ResourceTemplate("devises://{code}", {
    list: async () => ({
      resources: Object.keys(TAUX).map((code) => ({ uri: `devises://${code}`, name: `Devise ${code}` })),
    }),
  }),
  { title: "Fiche devise", mimeType: "text/plain" },
  async (uri, { code }) => ({
    contents: [{ uri: uri.href, text: `1 EUR = ${TAUX[String(code)] ?? "?"} ${code}` }],
  })
);
```

Si une variable d'URI devient un chemin de fichier, résolvez-la avec `realpath` et vérifiez qu'elle reste dans le dossier autorisé : c'est une entrée contrôlée par le client.

## Exposer un prompt

Un prompt est un modèle de messages que **l'utilisateur** déclenche. Claude Code les affiche comme commandes : `/devises:resume_budget (MCP)`, ou `/mcp__devises__resume_budget`.

```ts
server.registerPrompt(
  "resume_budget",
  {
    title: "Résumé de budget",
    description: "Prépare un résumé d'un budget de voyage dans une devise donnée",
    argsSchema: z.object({
      devise: z.string().describe("Devise cible, ex. USD"),
    }),
  },
  ({ devise }) => ({
    messages: [
      {
        role: "user" as const,
        content: {
          type: "text" as const,
          text: `Résume mon budget de voyage en ${devise}. Utilise le tool convertir_devise pour chaque poste.`,
        },
      },
    ],
  })
);
```

## Tester avec l'Inspector

L'Inspector MCP lance votre serveur et ouvre une interface web pour appeler chaque tool, lire les resources et récupérer les prompts.

```bash
npm run inspect
```

Cliquez sur **Connect**, puis ouvrez l'onglet **Tools**. Essayez un appel invalide (`de: "EURO"`) : le SDK le rejette avant votre handler, et le message d'erreur est celui que verrait le modèle.

## Brancher le serveur sur Claude Code

```bash
claude mcp add devises -- npx tsx /chemin/absolu/mcp-devises/src/index.ts
```

Tout ce qui suit `--` est la commande de lancement. Vérifiez la connexion avec `/mcp` dans une session. Ajoutez `--scope project` pour écrire l'entrée dans `.mcp.json` et la partager avec l'équipe via Git.

## Pièges fréquents

- **`console.log` dans un serveur stdio** : le client reçoit une ligne non JSON et coupe la connexion.
- **Imports v1 dans un projet v2** : `@modelcontextprotocol/sdk/server/mcp.js` n'existe pas dans les paquets v2. Choisissez une génération.
- **Zod 3** : le SDK v2 dépend de `zod ^4.2`. Importez `zod/v4` et évitez de mélanger les versions dans un monorepo.
- **Bornes exclusives** : `.positive()` ne se convertit pas dans tous les contextes (notamment l'elicitation). Préférez `.min(0)` ou `.min(1)`.
- **Logs MCP** : la capacité de logging du protocole est dépréciée depuis 2026-07-28. Loggez sur stderr ou avec OpenTelemetry.
