Ajouter un serveur MCP à Claude Code prend une commande. Les vraies questions sont ailleurs : serveur distant ou local, pour vous seul ou pour toute l'équipe, et comment gérer les secrets. Cet article couvre ces choix, puis la gestion et le dépannage.

## Premier test en 30 secondes

Le serveur de la documentation Claude Code ne demande aucun compte. Il est idéal pour vérifier votre installation. Lancez ces commandes dans votre terminal, pas dans une session `claude` :

```bash
claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp
claude mcp list
```

`claude mcp list` doit afficher `✔ Connected`. Ouvrez ensuite `claude` et demandez : « Cherche dans la doc comment fonctionne le mode auto ».

## Les quatre façons d'ajouter un serveur

### 1. Serveur distant HTTP (recommandé)

C'est le transport Streamable HTTP. La plupart des services officiels l'utilisent.

```bash
# Syntaxe
claude mcp add --transport http <nom> <url>

# Exemples
claude mcp add --transport http notion https://mcp.notion.com/mcp
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

# Avec un jeton fixe dans un en-tête
claude mcp add --transport http mon-api https://api.exemple.com/mcp \
  --header "Authorization: Bearer VOTRE_JETON"
```

### 2. Serveur distant SSE (déprécié)

Le transport SSE est déprécié. Depuis la v2.1.265, `--transport http` bascule tout seul sur SSE si le serveur ne connaît que ce transport. Sur une version plus ancienne, utilisez `--transport sse` :

```bash
claude mcp add --transport sse asana https://mcp.asana.com/sse
```

### 3. Serveur local stdio

Claude Code lance le serveur comme sous-processus. Tout ce qui suit `--` est la commande du serveur, transmise telle quelle :

```bash
# Syntaxe
claude mcp add [options] <nom> -- <commande> [arguments...]

# Navigateur piloté par Playwright (Node.js requis)
claude mcp add playwright -- npx -y @playwright/mcp@latest

# Serveur Git de référence (Python, via uvx)
claude mcp add git -- uvx mcp-server-git --repository /chemin/vers/depot

# Avec une variable d'environnement
claude mcp add airtable --env AIRTABLE_API_KEY=VOTRE_CLE -- npx -y airtable-mcp-server
```

Deux pièges fréquents :

- **Oublier `--`** : Claude Code essaie alors de lire les options du serveur (`-y`, `--port`…) comme les siennes.
- **Placer le nom juste après `--env`** : `--env` accepte plusieurs paires `CLE=valeur` et prend le nom pour une paire de plus. Mettez le nom avant `--env`, comme ci-dessus.

Claude Code définit `CLAUDE_PROJECT_DIR` (racine du projet) dans l'environnement du serveur.

### 4. Serveur WebSocket

Pour les serveurs qui poussent des événements. Pas de flag `--transport ws` ni d'OAuth : passez par `add-json` et un en-tête.

```bash
claude mcp add-json events '{"type":"ws","url":"wss://mcp.exemple.com/socket","headers":{"Authorization":"Bearer VOTRE_JETON"}}'
```

## Choisir le scope

| Scope | Actif dans | Partagé avec l'équipe | Stocké dans |
|---|---|---|---|
| `local` (défaut) | le projet courant | non | `~/.claude.json`, sous le chemin du projet |
| `project` | le projet courant | oui, via Git | `.mcp.json` à la racine du projet |
| `user` | tous vos projets | non | `~/.claude.json`, section globale |

```bash
claude mcp add --scope user --transport http github https://api.githubcopilot.com/mcp/ \
  --header "Authorization: Bearer VOTRE_PAT"
claude mcp add --scope project --transport http sentry https://mcp.sentry.dev/mcp
```

Pour changer de scope, supprimez puis rajoutez : `claude mcp remove <nom> --scope local`, puis `claude mcp add --scope user …`.

**Priorité** quand un même serveur est défini plusieurs fois : local, puis project, puis user, puis plugins, puis connecteurs claude.ai. L'entrée gagnante est utilisée en entier, sans fusion des champs.

**Attention** : Claude Code ne lit pas `~/.claude/mcp.json` ni `~/.claude/.mcp.json`. Les seuls fichiers valides sont `~/.claude.json` et `<projet>/.mcp.json`.

## Le fichier `.mcp.json` partagé

```json
{
  "mcpServers": {
    "sentry": {
      "type": "http",
      "url": "https://mcp.sentry.dev/mcp"
    },
    "api-interne": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.exemple.com}/mcp",
      "headers": { "Authorization": "Bearer ${API_KEY}" }
    },
    "playwright": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}
```

À retenir :

- **Toujours un `type`** pour un serveur distant (`http`, `sse` ou `ws`). Une entrée avec `url` mais sans `type` est lue comme stdio et ignorée avec une erreur. `streamable-http` est accepté comme alias de `http`.
- **Variables `${VAR}` et `${VAR:-défaut}`** dans `command`, `args`, `env`, `url` et `headers`. Chacun garde ainsi ses secrets dans son environnement, pas dans Git.
- **Protection des identifiants** : dans `url` et `headers` d'un serveur distant, les variables sensibles de Claude Code (`ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, identifiants cloud, `NPM_TOKEN`…) sont lues comme vides. Un `.mcp.json` piégé ne peut pas les envoyer à un serveur tiers.
- **Approbation** : à la première ouverture du projet, Claude Code vous demande d'approuver chaque serveur de `.mcp.json`. Pour revenir sur vos choix : `claude mcp reset-project-choices`.
- **Délai d'attente** : un outil peut avoir son propre `"timeout"` en millisecondes dans son entrée.

Claude Code lit `.mcp.json` au démarrage : relancez la session après modification.

## Autres façons d'importer

```bash
# Depuis un bloc JSON (l'objet à l'intérieur de "mcpServers", pas l'enveloppe)
claude mcp add-json local-weather '{"type":"stdio","command":"/chemin/weather-cli","args":["--verbose"]}'

# Depuis Claude Desktop (macOS et WSL), avec sélection interactive
claude mcp add-from-claude-desktop
```

Les **connecteurs** ajoutés sur [claude.ai/customize/connectors](https://claude.ai/customize/connectors) apparaissent automatiquement dans Claude Code si vous êtes connecté avec ce compte claude.ai (pas avec une clé API). Les **plugins** peuvent aussi fournir des serveurs : ils démarrent quand le plugin est activé.

## Authentification OAuth

Beaucoup de serveurs distants demandent une connexion. Claude Code affiche un avis au démarrage quand un serveur attend une authentification.

- Dans une session : `/mcp`, sélectionnez le serveur, **Authenticate**. Le navigateur s'ouvre.
- Depuis le shell : `claude mcp login sentry` (ajoutez `--no-browser` en SSH, puis collez l'URL de redirection). `claude mcp logout sentry` efface les jetons.
- Port de callback imposé par le serveur : `--callback-port 8080` lors du `claude mcp add`.

Les jetons sont stockés de façon sécurisée et rafraîchis automatiquement. Certains connecteurs hébergés par Anthropic (Gmail, Google Calendar, Microsoft 365) ne se connectent que depuis claude.ai.

## Gérer vos serveurs

```bash
claude mcp list                  # tous les serveurs et leur état
claude mcp get sentry            # détail d'un serveur, avec la cause d'un échec
claude mcp remove sentry         # suppression (efface aussi les jetons OAuth)
```

Dans une session :

- `/mcp` : état de chaque serveur, nombre d'outils, authentification, activation ou désactivation par projet sans supprimer la configuration ;
- `/mcp reconnect all` : relance tous les serveurs en échec ou en attente d'authentification ;
- les prompts d'un serveur deviennent des commandes `/serveur:prompt` ;
- les resources se citent avec `@`, par exemple `@github:issue://123`.

## Réglages utiles

| Variable | Effet |
|---|---|
| `MCP_TIMEOUT` | délai de démarrage d'un serveur en ms (30 s par défaut) |
| `MCP_TOOL_TIMEOUT` | durée maximale d'un appel d'outil en ms |
| `MAX_MCP_OUTPUT_TOKENS` | taille maximale d'une réponse d'outil (25 000 tokens par défaut, avertissement dès 10 000) |
| `ENABLE_TOOL_SEARCH` | `false` pour charger toutes les définitions d'outils au démarrage |

Un appel d'outil qui dépasse deux minutes passe en tâche de fond, visible dans `/tasks`.

## Dépannage rapide

| Symptôme | Cause probable | Solution |
|---|---|---|
| `No MCP servers configured` | serveur ajouté en `local` depuis un autre dossier | rajoutez-le ici ou en `--scope user` |
| `✘ Failed to connect` (stdio) | commande ou dépendance manquante | lancez la commande du serveur à la main pour voir l'erreur |
| `✘ Failed to connect` (HTTP) | mauvaise URL ou jeton refusé | `claude mcp get <nom>` affiche le code HTTP |
| `! Needs authentication` | OAuth non fait ou expiré | `/mcp` puis Authenticate, ou `claude mcp login` |
| `⏸ Pending approval` | serveur de `.mcp.json` pas encore approuvé | lancez `claude` dans le projet et approuvez |
| Délai dépassé au premier lancement | `npx` télécharge le paquet | `MCP_TIMEOUT=60000 claude` |
| Connecté mais aucun outil | variable d'environnement manquante | ajoutez-la avec `--env` ou dans `env` |

Pour voir les échanges en détail : `claude --debug='mcp'`, ou testez le serveur seul avec [MCP Inspector](/wiki/mcp/debugging-inspector).

## Bonnes pratiques

- Commitez `.mcp.json` pour les serveurs utiles à toute l'équipe, avec des `${VAR}` à la place des secrets.
- Gardez vos jetons personnels en scope `local` ou `user`, jamais en dur dans un fichier versionné.
- Préférez le serveur **officiel** de l'éditeur, distant si possible.
- Limitez les droits de chaque jeton (lecture seule, un seul projet). Voir [Sécurité des serveurs MCP](/wiki/mcp/securite-mcp).
