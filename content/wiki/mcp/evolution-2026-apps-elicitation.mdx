Le Model Context Protocol a plus évolué en 2026 que depuis sa création. Le protocole est devenu sans état, les interactions avec l'utilisateur passent par un nouveau mécanisme, et des **extensions officielles** (MCP Apps, Tasks) ajoutent interfaces graphiques et tâches longues. Cet article fait le point et indique ce que cela change pour vous dans Claude Code.

## Repères chronologiques

| Date | Événement |
|---|---|
| Novembre 2024 | Anthropic publie MCP en open source |
| Mars 2025 | Révision 2025-03-26 : transport Streamable HTTP, l'ancien HTTP+SSE est déprécié |
| Novembre 2025 | Révision 2025-11-25 : élicitation en mode URL, Client ID Metadata Documents pour OAuth |
| 9 décembre 2025 | Anthropic confie MCP à l'**Agentic AI Foundation** (Linux Foundation) |
| 26 janvier 2026 | Première version stable de la spécification **MCP Apps** |
| 28 juillet 2026 | Révision **2026-07-28** : protocole sans état, extensions Tasks et MCP Apps |

## Une gouvernance neutre

L'Agentic AI Foundation (AAIF) est un fonds dirigé hébergé par la Linux Foundation. Elle a été cofondée par Anthropic, Block et OpenAI, avec le soutien de Google, Microsoft, AWS, Cloudflare et Bloomberg. Elle accueille MCP, goose (Block) et AGENTS.md (OpenAI).

Concrètement, la spécification évolue par propositions publiques (les **SEP**), relues par des groupes de travail. Le code est progressivement relicencié de MIT vers Apache 2.0. Pour vous, c'est un signal de stabilité : un serveur MCP écrit aujourd'hui fonctionnera avec Claude, ChatGPT, VS Code, Cursor et les autres clients compatibles.

## La révision 2026-07-28 : un protocole sans état

C'est le changement le plus profond depuis 2024.

- **Plus de poignée de main** `initialize`. Chaque requête porte dans `_meta` la version du protocole et les capacités du client.
- **Nouvelle méthode `server/discover`**, obligatoire côté serveur, qui décrit versions, capacités et identité.
- **Plus de session HTTP** (`Mcp-Session-Id` disparaît). Un serveur distant devient une application HTTP ordinaire : n'importe quelle instance derrière un répartiteur de charge peut traiter n'importe quelle requête, sans session collante.
- **Notifications sur abonnement** : `subscriptions/listen` remplace le flux GET et `resources/subscribe`.
- **Résultats mis en cache** : `ttlMs` et `cacheScope` sur les listes et les lectures de resources.
- **`ping` et `logging/setLevel` supprimés** ; le niveau de log se règle par requête.

Le détail des messages est dans [JSON-RPC 2.0 sous le capot de MCP](/wiki/mcp/json-rpc-mapping) et celui des transports dans [Transports MCP](/wiki/mcp/transports-stdio-sse).

### Ce qui est déprécié

La spécification adopte une politique de cycle de vie : une fonction dépréciée reste utilisable **au moins 12 mois**. Sont dépréciés en 2026-07-28 :

| Fonction | Alternative conseillée |
|---|---|
| **Sampling** (le serveur demande une complétion au modèle du client) | appeler directement l'API d'un fournisseur de modèles |
| **Roots** (le client indique ses dossiers de travail) | passer chemins ou URI en paramètres d'outil ou en configuration |
| **Logging** côté protocole | logs sur stderr (stdio) ou OpenTelemetry |
| Transport **HTTP+SSE** | Streamable HTTP |
| Enregistrement dynamique de client OAuth (DCR) | Client ID Metadata Documents |

Si vous lisez un tutoriel qui présente le sampling comme l'avenir de MCP, il date d'avant cette révision.

## Élicitation : demander quelque chose à l'utilisateur

L'élicitation permet à un serveur de demander une information à l'utilisateur **pendant** un appel d'outil. Deux modes existent :

- **Formulaire** (`form`) : le serveur décrit un petit formulaire avec un JSON Schema simplifié (objet plat, champs texte, nombre, booléen ou liste de choix). Exemple : choisir l'environnement de déploiement, confirmer une suppression.
- **URL** (`url`) : le client propose d'ouvrir une page web. Les données saisies sur cette page ne transitent pas par le client. C'est **obligatoire** pour tout ce qui est sensible : mot de passe, clé d'API, jeton, paiement. Le mode formulaire est interdit pour ces données.

L'utilisateur peut toujours accepter, refuser ou annuler, et le client doit afficher clairement quel serveur demande quoi.

### Le nouveau mécanisme : les allers-retours (MRTR)

Depuis 2026-07-28, le serveur n'envoie plus de requête au client. Il répond à l'appel d'outil par un résultat `input_required` qui contient sa question. Le client interroge l'utilisateur, puis **rejoue l'appel d'origine** avec la réponse :

```json
{"jsonrpc":"2.0","id":7,"result":{
  "resultType":"input_required",
  "inputRequests":{"env":{"method":"elicitation/create","params":{
    "mode":"form",
    "message":"Sur quel environnement déployer ?",
    "requestedSchema":{"type":"object",
      "properties":{"cible":{"type":"string","enum":["staging","production"]}},
      "required":["cible"]}}}},
  "requestState":"eyJ…"}}
```

Le `requestState` est opaque pour le client : le serveur y encode où il en était. Il doit le signer ou le chiffrer, car le client pourrait le modifier.

### Dans Claude Code

- Les demandes d'élicitation s'affichent dans une boîte de dialogue, sans configuration. En mode URL, Claude Code vous demande s'il peut ouvrir le lien dans votre navigateur.
- Sur les connexions en 2026-07-28, Claude Code déclare les deux modes (`form` et `url`).
- Pour répondre automatiquement (en CI par exemple), utilisez le hook `Elicitation`. Voir [Introduction aux hooks](/wiki/hooks/introduction-hooks).

## MCP Apps : des interfaces dans la conversation

**MCP Apps** est une extension officielle (`io.modelcontextprotocol/ui`). Un outil déclare dans son `_meta.ui.resourceUri` une ressource `ui://` qui contient une page HTML. L'hôte affiche cette page dans une **iframe isolée** à côté de la réponse : tableau de bord, formulaire de configuration, visionneuse de PDF, carte interactive.

Fonctionnement :

1. l'hôte peut précharger la ressource `ui://` avant même l'appel d'outil ;
2. il affiche la page dans un bac à sable (pas d'accès au DOM, aux cookies ni au stockage de l'hôte) ;
3. la page dialogue avec l'hôte par `postMessage`, avec des messages JSON-RPC (`ui/initialize`, `tools/call`…). Elle peut appeler les outils du serveur, avec l'accord de l'hôte ;
4. `_meta.ui.csp` liste les origines externes autorisées, `_meta.ui.permissions` les accès supplémentaires (micro, caméra).

Le paquet `@modelcontextprotocol/ext-apps` fournit une classe `App` pratique, mais n'importe quel framework web convient.

**Où ça s'affiche** : Claude (web), Claude Desktop, ChatGPT, VS Code avec GitHub Copilot, Microsoft 365 Copilot, Cursor, Goose, Postman et d'autres. **Claude Code dans le terminal n'affiche pas ces interfaces** : il masque les ressources `ui://` de la liste des resources, mais les outils restent utilisables normalement. Pour tester le rendu d'une App, utilisez l'onglet Apps de [MCP Inspector](/wiki/mcp/debugging-inspector).

## Les autres extensions officielles

Les extensions sont optionnelles et négociées dans le champ `extensions` des capacités. Les principales :

| Extension | Rôle |
|---|---|
| **Tasks** (`io.modelcontextprotocol/tasks`) | Opérations longues : le serveur renvoie un identifiant de tâche, le client interroge avec `tasks/get` et répond avec `tasks/update` |
| **OAuth Client Credentials** | Authentification machine à machine, sans utilisateur devant un navigateur |
| **Enterprise-Managed Authorization** | Accès piloté par le fournisseur d'identité de l'entreprise |
| **Skills over MCP** | Un serveur expose des skills (instructions et fichiers associés) |

Tasks était une fonction expérimentale du cœur en 2025 ; elle a été sortie du cœur et redessinée en extension.

## Ce qui arrive : la feuille de route

La feuille de route publiée par les mainteneurs (mise à jour le 22 août 2026) fixe cinq priorités. Ce sont des intentions, pas des engagements :

- **Messagerie agentique** : faire converger Tasks, abonnements et progression, et ajouter des événements poussés par le serveur (webhooks).
- **Transport unifié** : un seul modèle HTTP, y compris en local (HTTP sur stdio), et un cache avec ETags.
- **Identité des agents** : DPoP, délégation d'identité, échange de jetons pour les agents qui agissent sans utilisateur présent.
- **Primitives améliorées** : refonte de la forme des résultats de `tools/call` (aujourd'hui `content` et `structuredContent` coexistent) et **découverte progressive** des outils.
- **SDK** : génération et validation automatiques à partir de la spécification et d'une suite de conformité.

## Ce que cela change pour vous

- **Vous utilisez Claude Code** : rien à faire. Claude Code (runtime v2) négocie la révision 2026-07-28 avec les serveurs HTTP qui la supportent, et l'étend progressivement aux serveurs stdio et aux connecteurs ; les autres serveurs restent sur l'ancienne poignée de main (variable `MCP_SDK_GENERATION` pour forcer un runtime, `MCP_PROTOCOL_NEGOTIATION` pour la négociation). Préférez les serveurs distants officiels en Streamable HTTP.
- **Vous écrivez un serveur** : partez sur un SDK v2, n'utilisez ni sampling ni roots, passez par l'élicitation en mode URL pour toute donnée sensible, et prévoyez Streamable HTTP pour un déploiement partagé.
- **Vous exploitez des serveurs en production** : le sans-état simplifie la montée en charge, mais les serveurs qui gardaient un état de session doivent le rendre explicite (identifiants passés en arguments).
