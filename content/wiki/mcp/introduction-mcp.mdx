Le **Model Context Protocol** (MCP) est un standard ouvert qui permet à une application d'IA (Claude Code, l'application Claude, un IDE) de se connecter à des outils et à des données externes : fichiers, bases de données, GitHub, Notion, Sentry, etc. La documentation officielle le compare à un **port USB-C** : une prise unique et normalisée, à la place d'une intégration sur mesure pour chaque service.

## Le problème que MCP résout

Sans standard, chaque application d'IA doit coder sa propre intégration pour chaque service. Avec M applications et N services, on obtient M × N connecteurs à maintenir, tous incompatibles entre eux.

MCP ramène l'équation à **M + N** :

- chaque application implémente une fois le côté **client** MCP ;
- chaque service expose une fois un **serveur** MCP ;
- n'importe quel client peut alors parler à n'importe quel serveur.

Résultat concret : le même serveur Sentry ou GitHub fonctionne dans Claude Code, dans Claude Desktop, dans VS Code ou dans Cursor.

## Ce qu'un serveur MCP peut offrir

Un serveur expose trois types de briques, appelées **primitives** :

| Primitive | Rôle | Exemple |
|---|---|---|
| **Tools** | Actions que le modèle peut déclencher | créer une issue, exécuter une requête SQL |
| **Resources** | Données que l'on peut lire et joindre au contexte | un schéma de base, un fichier, un ticket |
| **Prompts** | Modèles de requêtes réutilisables | « revue de PR », « résumé d'incident » |

Côté client, la spécification définit aussi l'**élicitation** : le serveur peut demander une information à l'utilisateur en cours de tâche (un formulaire, une connexion dans le navigateur).

Le détail de chaque primitive est dans [Resources, Tools, Prompts](/wiki/mcp/primitives-resources-tools-prompts).

## Local ou distant

Un serveur MCP peut tourner à deux endroits :

- **en local**, lancé par le client comme sous-processus (transport **stdio**). Exemple : le serveur Filesystem qui lit un dossier de votre machine ;
- **à distance**, hébergé par l'éditeur du service (transport **Streamable HTTP**, souvent avec OAuth). Exemple : `https://mcp.notion.com/mcp` ou `https://mcp.sentry.dev/mcp`.

L'ancien transport HTTP+SSE est déprécié. En 2026, la plupart des grands services proposent un serveur distant officiel.

## Un exemple dans Claude Code

Ajoutez deux serveurs distants :

```bash
claude mcp add --transport http notion https://mcp.notion.com/mcp
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp
```

Lancez `claude`, tapez `/mcp` pour vous connecter (OAuth dans le navigateur), puis demandez :

```text
Trouve les 3 erreurs Sentry les plus fréquentes de cette semaine
et crée une page Notion qui les résume avec un plan de correction.
```

Claude choisit lui-même les outils des deux serveurs (`mcp__sentry__…`, `mcp__notion__…`) et vous demande l'autorisation selon votre mode de permission.

## Où en est le protocole en octobre 2026

- **Origine** : publié par Anthropic en novembre 2024, sous licence open source. La spécification, les SDK et les serveurs de référence sont sur GitHub (`modelcontextprotocol`).
- **Version courante de la spécification** : **2026-07-28**. Elle rend le protocole sans état : plus de poignée de main `initialize`, chaque requête porte sa version et ses capacités, et une méthode `server/discover` décrit le serveur.
- **Fonctions dépréciées** dans cette version : Roots, Sampling et Logging (toujours utilisables pendant au moins 12 mois).
- **Extensions officielles** : Tasks (opérations longues) et MCP Apps (interfaces interactives affichées dans la conversation).
- **Écosystème** : Claude, ChatGPT, VS Code, Cursor et de nombreux autres clients supportent MCP. Le [registre officiel](https://registry.modelcontextprotocol.io/) liste les serveurs publiés.

Claude Code gère les deux générations du protocole : il utilise la révision 2026-07-28 avec les serveurs qui la supportent et l'ancienne poignée de main avec les autres.

## MCP, skill ou plugin ?

- **MCP** donne à Claude un **accès** : un service, une API, une base.
- Une **skill** lui donne une **méthode** : des instructions et des scripts pour une tâche.
- Un **plugin** **regroupe** skills, agents, hooks et serveurs MCP pour les installer en une fois.

Voir [Skill, agent ou MCP ?](/wiki/skills/skill-vs-agent-vs-mcp) pour choisir.
