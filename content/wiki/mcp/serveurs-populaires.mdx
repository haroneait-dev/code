En 2026, la plupart des services pour développeurs publient leur propre serveur MCP, presque toujours **distant** (Streamable HTTP) avec une connexion **OAuth**. Plus besoin de paquet npm ni de jeton collé dans un fichier : une commande, une connexion dans le navigateur, et Claude Code accède au service. Voici les plus utiles et comment les configurer proprement.

## Le schéma commun

```bash
claude mcp add --transport http <nom> <url-du-serveur>
```

Puis, dans une session : `/mcp`, sélectionnez le serveur, **Authenticate**. Ou depuis le shell : `claude mcp login <nom>`.

Ajoutez `--scope user` pour l'avoir dans tous vos projets, ou `--scope project` pour le partager via `.mcp.json`. Voir [Installer un serveur MCP](/wiki/mcp/installer-serveur-mcp).

## Récapitulatif

| Service | Commande Claude Code | Authentification |
|---|---|---|
| Supabase | `claude mcp add --transport http supabase https://mcp.supabase.com/mcp` | OAuth |
| Vercel | `claude mcp add --transport http vercel https://mcp.vercel.com` | OAuth |
| Linear | `claude mcp add --transport http linear https://mcp.linear.app/mcp` | OAuth |
| Sentry | `claude mcp add --transport http sentry https://mcp.sentry.dev/mcp` | OAuth |
| Notion | `claude mcp add --transport http notion https://mcp.notion.com/mcp` | OAuth |
| Stripe | `claude mcp add --transport http stripe https://mcp.stripe.com` | OAuth |
| GitHub | `claude mcp add --transport http github https://api.githubcopilot.com/mcp/ --header "Authorization: Bearer VOTRE_PAT"` | jeton personnel |
| Playwright | `claude mcp add playwright -- npx -y @playwright/mcp@latest` | aucune (local) |

Vérifiez toujours l'URL dans la documentation de l'éditeur : elles changent parfois (passage de `/sse` à `/mcp`, par exemple).

## Supabase

Le serveur officiel donne accès à vos projets : tables, requêtes SQL, migrations, types TypeScript, Edge Functions, logs et conseils de sécurité (advisors).

```bash
claude mcp add --transport http supabase \
  "https://mcp.supabase.com/mcp?project_ref=VOTRE_REF&read_only=true&features=database,docs"
```

Les paramètres d'URL sont vos meilleurs garde-fous :

- `project_ref` limite le serveur à **un seul projet** (sinon il voit toute l'organisation) ;
- `read_only=true` retire les outils qui modifient des données ;
- `features` ne garde que certains groupes d'outils (`database`, `docs`…).

Le tableau de bord Supabase génère cette URL pour vous (onglet MCP de la fenêtre « Connect »).

Exemple de demande :

```text
Liste mes tables, propose une migration qui ajoute archived_at à posts,
montre-la-moi avant de l'appliquer, puis régénère les types TypeScript.
```

Claude enchaîne `list_tables`, `apply_migration` et `generate_typescript_types`. Supabase recommande de **ne pas connecter ce serveur à une base de production** : travaillez sur un projet de développement ou une branche.

## Vercel

Le serveur Vercel permet de chercher dans la documentation Vercel, de lister vos projets et déploiements et de lire les logs de build et d'exécution.

```bash
# Accès à tous vos projets
claude mcp add --transport http vercel https://mcp.vercel.com

# Limité à un projet précis d'une équipe
claude mcp add --transport http vercel-monprojet https://mcp.vercel.com/mon-equipe/mon-projet
```

Demande typique : « Pourquoi mon dernier déploiement a échoué ? Propose un correctif. » Claude lit les logs de build et remonte jusqu'à l'erreur.

## Linear

Le serveur distant de Linear sait chercher, créer et mettre à jour des issues, projets et commentaires.

```bash
claude mcp add --transport http linear https://mcp.linear.app/mcp
```

L'ancien point d'accès `https://mcp.linear.app/sse` utilisait le transport SSE, désormais déprécié. Préférez `/mcp`.

Demande typique : « Crée une issue Linear pour ce bug avec les étapes de reproduction, priorité haute, dans le cycle en cours. »

## Les autres incontournables

- **GitHub** : issues, pull requests, revues, recherche de code, Actions. Utilisez un jeton à grain fin limité aux dépôts utiles. L'ancien paquet `@modelcontextprotocol/server-github` est abandonné.
- **Sentry** : récupérer une erreur, sa stack trace et son contexte, puis demander un correctif.
- **Notion** : chercher, lire et créer des pages dans votre espace.
- **Stripe** : consulter clients, paiements et abonnements. Commencez en mode test.
- **Playwright** : un navigateur que Claude pilote (naviguer, cliquer, lire la page). Idéal pour vérifier une page après une modification. Il remplace l'ancien serveur Puppeteer.

D'autres services proposent un serveur officiel. Cherchez dans l'[Anthropic Directory](https://claude.ai/directory) ou le [registre MCP](https://registry.modelcontextprotocol.io/) avant d'installer un serveur communautaire.

## Combiner plusieurs serveurs

La force de MCP apparaît quand Claude enchaîne plusieurs services dans la même demande :

```text
1. Récupère dans Sentry l'erreur la plus fréquente des dernières 24 h.
2. Trouve la cause dans le code et corrige-la.
3. Ouvre une issue Linear liée, puis une PR GitHub avec le correctif.
4. Vérifie que le déploiement de prévisualisation Vercel passe.
```

## Sécurité et permissions

Chaque serveur agit avec les droits du compte ou du jeton que vous lui donnez. Quatre règles :

1. **Droits minimaux** : un projet, de la lecture seule quand c'est possible, un environnement de développement plutôt que la production.
2. **Pas de secret en dur** : dans un `.mcp.json` partagé, utilisez `${VAR}` et laissez chacun définir ses variables.
3. **Bloquez les outils dangereux** avec les règles de permission. Un outil MCP se nomme `mcp__<serveur>__<outil>` :

```json
{
  "permissions": {
    "deny": ["mcp__supabase__execute_sql"],
    "ask": ["mcp__supabase__apply_migration"]
  }
}
```

4. **Méfiez-vous du contenu externe** : un ticket, une issue ou une page peut contenir des instructions cachées (injection de prompt). Relisez les actions proposées avant d'approuver.
