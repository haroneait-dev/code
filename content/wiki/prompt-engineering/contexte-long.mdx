Les modèles Claude actuels (Fable 5.1, Opus 5.5, Sonnet 5.5, Opus 5, Sonnet 5) acceptent jusqu'à **1 million de tokens** de contexte, soit plusieurs milliers de pages. Mais plus de contexte n'est pas automatiquement mieux : la documentation d'Anthropic rappelle que la précision et le rappel se dégradent quand le nombre de tokens augmente (*context rot*). Cet article montre comment structurer un prompt long pour que Claude exploite réellement ce que vous lui donnez.

## Ce qu'il faut savoir sur la fenêtre

| Point | Détail |
|---|---|
| Taille | 1M de tokens pour les modèles actuels (sauf Haiku 4.5 : 200k) |
| Sortie maximale | 128k tokens par requête sur les modèles à 1M |
| Prix | Tarif standard sur toute la fenêtre, sans supplément « long contexte » ni en-tête bêta |
| Ce qui compte dans la fenêtre | Prompt système, messages, documents, images, définitions d'outils, réflexion et réponse |
| Fichiers | Jusqu'à 600 images ou pages de PDF par requête (100 pour les modèles à 200k) |

Un contexte immense coûte cher et ralentit la première réponse. Envoyez ce qui est **utile**, pas tout ce qui est disponible.

## Règle 1 : les documents en haut, la question à la fin

C'est le conseil le plus rentable de la documentation : placez les documents longs **au début** du prompt, au-dessus de la question, des consignes et des exemples. Selon Anthropic, poser la question à la fin peut améliorer la qualité des réponses **jusqu'à 30 %** dans leurs tests, surtout avec plusieurs documents complexes.

## Règle 2 : une balise par document, avec ses métadonnées

Entourez chaque document de balises `<document>`, avec la source et le contenu dans des sous-balises. Claude sait alors exactement de quel document vient chaque passage.

```xml
<documents>
  <document index="1">
    <source>contrat_2025.pdf</source>
    <document_content>
      {{CONTRAT}}
    </document_content>
  </document>
  <document index="2">
    <source>avenant_2026.pdf</source>
    <document_content>
      {{AVENANT}}
    </document_content>
  </document>
</documents>

Comparez le contrat et l'avenant. Listez chaque clause modifiée avec
l'ancienne et la nouvelle formulation.
```

Voir [Balises XML](/wiki/prompt-engineering/balises-xml) pour les conventions de nommage.

## Règle 3 : faire citer avant de répondre

Pour une tâche sur un document long, demandez à Claude d'**extraire d'abord les passages pertinents**, puis de travailler à partir d'eux. Cela l'aide à se concentrer sur ce qui compte et réduit les inventions.

```text
Trouvez dans les documents les passages qui concernent la résiliation
et placez-les mot pour mot dans des balises <citations>, numérotés.
Si aucun passage ne correspond, écrivez « Aucun passage trouvé ».
Ensuite, en vous appuyant uniquement sur ces citations, répondez dans
<reponse> en renvoyant aux numéros : [1], [2]…
```

Via l'API, la fonction **Citations** fait ce travail de façon native : Claude renvoie des références précises vers les passages des documents fournis (voir [Citations API](/wiki/api/citations-api)). Elle n'est pas compatible avec les sorties structurées.

## Règle 4 : autoriser « je ne sais pas »

Un long dossier ne contient pas forcément la réponse. Dites-le explicitement :

```text
Si les documents ne permettent pas de répondre, écrivez : « Les
documents fournis ne contiennent pas cette information. » N'utilisez
pas vos connaissances générales pour compléter.
```

## Dans claude.ai

Les mêmes principes s'appliquent quand vous joignez des fichiers à une conversation :

1. Joignez les documents, puis écrivez votre question **après**, en une fois.
2. Nommez les fichiers dans votre demande : « Dans le fichier *budget_2026.xlsx*… ».
3. Demandez des citations : « Citez le passage exact qui justifie chaque point. »

Exemple prêt à l'emploi :

```text
Je vous ai joint trois comptes rendus de réunion (janvier, mars, juin).
Je prépare un point d'avancement pour la direction.

1. Pour chaque décision prise, citez la phrase exacte et le compte
   rendu d'où elle vient.
2. Signalez les décisions qui se contredisent d'une réunion à l'autre.
3. Terminez par les actions encore ouvertes, sous forme de tableau
   (action, responsable, date prévue).
```

Pour des documents que vous interrogez souvent, utilisez un **projet** : son contenu est mis en cache et réutilisé, ce qui consomme moins de vos limites d'usage que de le renvoyer à chaque conversation (voir [Bien nourrir un projet](/wiki/claude-ai/projects-knowledge-base)).

## Via l'API : cache, comptage et compaction

**Mettez en cache le contexte stable.** Si vous posez plusieurs questions sur le même corpus, le [prompt caching](/wiki/prompt-engineering/prompt-caching-concepts) facture les lectures suivantes à une fraction du prix (0,1 fois le prix d'entrée en général, 0,05 fois sur Opus 5.5).

```python
import anthropic

client = anthropic.Anthropic()

with open("rapport_annuel.txt", encoding="utf-8") as f:
    rapport = f.read()

response = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=8000,
    system="Vous êtes analyste financier. Répondez uniquement à partir "
           "du document fourni et citez vos sources.",
    messages=[{
        "role": "user",
        "content": [
            {
                "type": "text",
                "text": f"<document>\n<source>rapport_annuel.txt</source>\n"
                        f"<document_content>\n{rapport}\n</document_content>\n"
                        f"</document>",
                "cache_control": {"type": "ephemeral"},
            },
            {"type": "text", "text": "Quels sont les trois principaux risques cités ?"},
        ],
    }],
)

print(response.usage)  # cache_creation_input_tokens, cache_read_input_tokens
```

**Comptez avant d'envoyer.** L'endpoint de comptage de tokens estime la taille d'une requête. Si l'entrée seule dépasse la fenêtre, l'API renvoie une erreur 400 « prompt is too long ».

**Laissez le serveur compacter les longues conversations.** Pour un agent ou une conversation qui grossit, la *compaction* côté serveur (bêta) résume automatiquement les échanges anciens. Le *context editing* permet aussi d'effacer d'anciens résultats d'outils.

## Les erreurs fréquentes

- **Concaténer des dizaines de fichiers sans balises** : Claude ne sait plus où commence chaque document.
- **Poser la question en premier, les documents ensuite** : c'est l'inverse de la recommandation.
- **Tout charger « au cas où »** : le coût et la latence montent, la précision baisse. Une recherche ciblée (RAG) qui ne garde que les passages pertinents donne souvent de meilleurs résultats.
- **Changer le début du prompt à chaque requête** (date, identifiant) : le cache ne sert plus.
