Le *prefilling* consistait à écrire vous-même le début de la réponse de Claude, dans un dernier message `assistant`, pour qu'il continue à partir de là. Un simple `{` garantissait une réponse en JSON, sans préambule. **Cette technique n'est plus prise en charge sur les modèles récents** : la requête renvoie une erreur 400. Cet article explique ce qui a changé et comment obtenir le même résultat aujourd'hui.

## Ce qui a changé

Selon la documentation d'Anthropic, depuis les modèles **Claude 4.6** (et Claude Mythos Preview), un message `assistant` pré-rempli en **dernière position** n'est plus accepté. La raison donnée : l'intelligence et le suivi des consignes ont tellement progressé que la plupart des usages du prefill n'en ont plus besoin.

| Modèle | Prefill en dernier tour |
|---|---|
| Fable 5.1, Mythos 5.1, Fable 5, Mythos 5 | Erreur 400 |
| Opus 5.5, Opus 5, Opus 4.8, Opus 4.7, Opus 4.6 | Erreur 400 |
| Sonnet 5.5, Sonnet 5, Sonnet 4.6 | Erreur 400 |
| Haiku 4.5, Sonnet 4.5, Opus 4.5 et antérieurs | Encore accepté |

Deux précisions :

- Des messages `assistant` **ailleurs** dans la conversation (l'historique, des exemples de dialogue) ne posent aucun problème. Seul le dernier message pré-rempli est refusé.
- Le prefill n'est **pas compatible** avec les sorties structurées, quel que soit le modèle.

## L'ancienne technique, pour mémoire

Sur Haiku 4.5, ce code fonctionne encore :

```python
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-haiku-4-5-20251001",
    max_tokens=500,
    messages=[
        {"role": "user", "content": "Extrayez nom et e-mail : Jean Martin, jean@exemple.fr"},
        {"role": "assistant", "content": "{"},  # prefill
    ],
)

texte = "{" + response.content[0].text  # le prefill n'est pas renvoyé
```

Le même appel avec `claude-sonnet-5-5` ou `claude-opus-5-5` échoue. Si vous maintenez une application qui utilise ce schéma, migrez-la avant de changer de modèle.

## Les remplacements, cas par cas

### Forcer un format (JSON, YAML, classification)

Utilisez les **sorties structurées** (`output_config.format`), conçues pour contraindre la réponse à un schéma JSON. Pour une classification, un outil avec un champ `enum` contenant vos étiquettes, ou une sortie structurée, fait le travail.

```python
response = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=2000,
    messages=[{"role": "user", "content": "Extrayez nom et e-mail : Jean Martin, jean@exemple.fr"}],
    output_config={
        "format": {
            "type": "json_schema",
            "schema": {
                "type": "object",
                "properties": {"nom": {"type": "string"}, "email": {"type": "string"}},
                "required": ["nom", "email"],
                "additionalProperties": False,
            },
        }
    },
)
```

Anthropic note aussi que les modèles récents respectent bien un schéma décrit dans le prompt, surtout avec une relance en cas d'échec. Détails dans [Formater la sortie](/wiki/prompt-engineering/output-format).

### Supprimer les préambules

Le prefill `Voici le résumé demandé :` servait à sauter l'introduction. Remplacement recommandé, dans le prompt système :

```text
Répondez directement, sans préambule. Ne commencez pas par des
formules comme « Voici… » ou « D'après… ».
```

Autres options : demander la réponse dans une balise XML que votre code extrait, utiliser une sortie structurée, ou retirer en post-traitement le préambule qui passerait encore.

### Éviter les refus injustifiés

Le prefill servait parfois à « pousser » le modèle à répondre. Selon Anthropic, les modèles actuels refusent beaucoup plus à bon escient : une demande claire dans le message `user`, avec son contexte légitime, suffit.

### Reprendre une réponse interrompue

Déplacez la continuation dans le message utilisateur, avec la fin du texte déjà obtenu :

```text
Votre réponse précédente a été interrompue. Elle se terminait par :
« …et c'est pourquoi la clause 4 doit être renégociée ». Reprenez
exactement là où vous vous êtes arrêté.
```

Si l'interruption vient d'une erreur et que l'expérience utilisateur le permet, relancer simplement la requête est souvent plus simple.

### Maintenir un rôle ou rappeler du contexte

Pour les très longues conversations, placez les rappels dans le tour **utilisateur** (ou dans un message système en cours de conversation) plutôt que dans un faux début de réponse. Dans un système agentique, exposez le contexte via des outils ou laissez la compaction côté serveur gérer l'historique.

## Et dans claude.ai ?

L'interface n'a jamais proposé de prefill. L'équivalent est une consigne explicite dans votre message :

```text
Commencez directement par le tableau, sans phrase d'introduction.
Colonnes : produit, prix, délai de livraison.
```

ou, pour un texte à réutiliser tel quel :

```text
Donnez uniquement le texte de l'e-mail, sans commentaire avant ni
après, pour que je puisse le copier directement.
```
