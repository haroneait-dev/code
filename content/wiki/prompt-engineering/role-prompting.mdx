Le *role prompting* consiste à dire à Claude quelle posture adopter : « conseiller en droit du travail », « relecteur de code exigeant », « professeur de maths pour des élèves de seconde ». La documentation d'Anthropic le résume ainsi : définir un rôle dans le prompt système concentre le comportement et le ton de Claude sur votre cas d'usage, et **une seule phrase fait déjà une différence**.

## Ce que le rôle change

Le rôle n'ajoute pas de connaissances. Il oriente la façon dont Claude utilise celles qu'il a :

- le **vocabulaire** : technique ou vulgarisé ;
- l'**angle** : un juriste pense conformité, un responsable produit pense usage ;
- le **niveau de détail** : survol pour un dirigeant, analyse fine pour un spécialiste ;
- le **ton** : formel, pédagogique, direct.

## Écrire un bon rôle

Un bon rôle est **précis** et dit **pour qui** Claude travaille. Le public visé compte souvent plus que le titre.

```text
Peu utile : Vous êtes un expert.
Mieux     : Vous êtes un développeur senior.
Efficace  : Vous êtes un développeur backend senior qui relit le code
            d'une équipe de quatre personnes. Vous connaissez bien
            Postgres et Node.js. Vos retours sont lus par des
            développeurs juniors : expliquez chaque problème en une phrase.
```

Ajoutez ensuite ce que le rôle ne dit pas : le contexte, les règles et le format attendu (voir [Anatomie d'un prompt efficace](/wiki/prompt-engineering/anatomie-prompt)). Un rôle seul, sans contexte, reste une demande générique.

## Où placer le rôle

### Dans claude.ai

Il n'y a pas de champ « prompt système » dans une conversation. Trois options :

1. **En tête de votre message**, pour une demande ponctuelle :

```text
Agissez comme un professeur de physique qui s'adresse à un élève de
première. Expliquez-moi pourquoi le ciel est bleu, en moins de
200 mots, avec une analogie de la vie courante.
```

2. **Dans les instructions d'un projet**, pour un rôle que vous réutilisez souvent : chaque conversation du projet en hérite (voir [Créer un projet](/wiki/claude-ai/projects-creation)).

```text
Vous êtes le relecteur éditorial de notre blog culinaire. Les lecteurs
sont des débutants. Pour chaque article que je colle :
- signalez les étapes de recette ambiguës ;
- proposez une version plus claire de chaque phrase signalée ;
- gardez le ton chaleureux de nos articles.
```

3. **Dans vos instructions personnelles** (paramètres du compte) pour une posture valable partout, par exemple « Je suis développeur Python, répondez-moi comme à un collègue ». Voir [Personnaliser Claude](/wiki/claude-bases/personnaliser).

### Via l'API

Placez le rôle dans le paramètre `system`. Les messages `user` restent libres pour les données et la question du moment.

```python
import anthropic

client = anthropic.Anthropic()

message = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=4000,
    system=(
        "Vous êtes un avocat français spécialisé en droit du numérique "
        "(RGPD, contrats SaaS B2B). Vous répondez à des fondateurs de "
        "start-up sans formation juridique. Citez les articles de loi "
        "concernés et signalez ce qui demande l'avis d'un avocat."
    ),
    messages=[{
        "role": "user",
        "content": "Notre outil stocke les e-mails de nos clients sur un "
                   "serveur américain. Que devons-nous vérifier ?",
    }],
)

for block in message.content:
    if block.type == "text":
        print(block.text)
```

Lisez la réponse par type de bloc : sur les modèles récents, elle peut commencer par un bloc `thinking`.

## Exemples prêts à adapter

**Relecture de code**

```text
Vous êtes un ingénieur qui relit les pull requests d'une application
SaaS B2B. Vous privilégiez la lisibilité, la testabilité et la gestion
des erreurs. Signalez en priorité les failles de sécurité (injection
SQL, données sensibles dans les logs) et les accès concurrents mal gérés.
```

**Rédaction commerciale**

```text
Vous êtes un rédacteur qui écrit pour des dirigeants de PME. Phrases
courtes, verbes concrets, aucun jargon d'entreprise, une idée par
paragraphe.
```

**Pédagogie**

```text
Vous êtes un tuteur qui aide un étudiant à comprendre, pas à recopier.
Posez une question à la fois et ne donnez la solution complète que si
l'étudiant la demande explicitement.
```

## Les pièges

- **Un rôle en contradiction avec la tâche** : demander à « un poète » d'écrire une documentation d'API donne un résultat médiocre. Le rôle doit servir la tâche.
- **Un rôle grandiloquent** : « le plus grand expert mondial » n'apporte rien de plus qu'un rôle précis.
- **Un rôle qui remplace le contexte** : « Vous êtes un expert marketing » ne dit ni le produit, ni la cible, ni l'objectif. Ajoutez-les.
- **Un rôle qui contredit les valeurs du modèle** : un rôle ne lève pas les limites de Claude. Ne comptez pas sur une persona pour contourner un refus.
- **Des majuscules partout** (« VOUS DEVEZ TOUJOURS ») : sur les modèles récents, ce ton pousse à l'excès de zèle. Un ton normal suffit.
